\begin{abstract}
When a program is decomposed into overlapping patches for modular
verification, the patches must agree on shared boundaries---but different
patches may export conflicting interfaces.  We introduce \emph{treaty
synthesis}, a dynamic negotiation protocol that reconciles patch interfaces
within the \emph{hypercover family} framework of Judgment Geometry.  A
treaty is a formal witness that the \v{C}ech $1$-cocycle on patch
overlaps vanishes, enabling descent from local verifications to a global
correctness certificate.  Our synthesis algorithm iterates through
conflict detection, scoring, and resolution---applying strategies such as
common-supertype widening, range intersection, protocol adaptation, and
ownership brokering---with guaranteed termination in at most $10$
negotiation rounds via a strictly decreasing obstruction norm.  We
evaluate treaty synthesis on \expTotalPrograms{} programs across
\expDomainCount{} domains, with all \expVerified{} programs achieving
successful treaty negotiation and zero residual obstructions.  The mean
verification time is \expTimeMean{} per program, with the total
benchmark completing in \expTimeTotal{}.
\end{abstract}

\section{Introduction}\label{sec:intro}
% =====================================================================

Modular verification decomposes a program into independently verifiable
units---functions, classes, modules---and then assembles local verdicts
into a global guarantee.  The assembly step requires that adjacent units
\emph{agree} on their shared interfaces: if module~$A$ exports
\texttt{get\_user} returning \texttt{dict} but module~$B$ imports it
expecting a \texttt{User} dataclass, the local verdicts are incompatible
and cannot be composed.

In sheaf-theoretic terms, each module corresponds to a \emph{patch}
(an open set in the semantic site $\Site$), and the interfaces between
modules correspond to \emph{overlaps}.  A global verification certificate
exists if and only if the local sections agree on all overlaps---\ie the
\v{C}ech $1$-cocycle vanishes: $\Hcoh{1}(\Site, \Sect) = 0$.

When the cocycle does \emph{not} vanish---when interfaces conflict---the
standard sheaf-theoretic response is to report an obstruction class
$[\alpha] \in \Hcoh{1}$.  But obstructions are diagnostic, not
therapeutic: they describe \emph{what} went wrong, not \emph{how to fix
it}.  Treaty synthesis bridges this gap.

\begin{definition}[Treaty]\label{def:treaty}
A \emph{treaty} between patches $\patch_i$ and $\patch_j$ is a pair
$\treaty_{ij} = (\iface_{ij}, w_{ij})$ where $\iface_{ij}$ is a
reconciled interface on $\overlap{\patch_i}{\patch_j}$ and $w_{ij}$
is a witness that the restriction maps
$\res_i|_{\overlap{\patch_i}{\patch_j}}$ and
$\res_j|_{\overlap{\patch_i}{\patch_j}}$ agree up to the adaptation
specified by $\iface_{ij}$.
\end{definition}

The treaty synthesis algorithm proceeds in three phases:
\begin{enumerate}[nosep]
\item \textbf{\detect{}}: identify all interface conflicts on overlaps.
\item \textbf{Score}: assign a severity score to each conflict.
\item \textbf{\resolve{}}: apply resolution strategies in decreasing
  order of severity until the obstruction norm drops below a threshold.
\end{enumerate}

The algorithm is guaranteed to terminate because each resolution step
strictly decreases the obstruction norm, and the norm is bounded below
by zero.  In practice, convergence occurs within 3--5 rounds for
typical multi-module Python programs.

\paragraph{Contributions.}
\begin{enumerate}[nosep]
\item A formal model of treaties as cocycle witnesses in hypercover
  families (\Cref{sec:hypercover}).
\item A conflict detection and scoring framework with four resolution

\section{Hypercover Families}\label{sec:hypercover}
% =====================================================================

\subsection{From Covers to Hypercovers}

A covering family $\{U_i \to U\}$ in a Grothendieck topology is a
collection of morphisms that jointly cover $U$.  For modular
verification, the patches are the open sets $U_i$, and the covering
condition says that every point of $U$ lies in at least one patch.

A \emph{hypercover} extends this to multiple levels: the patches $U_i$
form level~0, the pairwise overlaps $U_{ij} = \overlap{U_i}{U_j}$
form level~1, and triple overlaps $U_{ijk}$ form level~2.

\begin{definition}[Hypercover Family]\label{def:hypercover}
A \emph{hypercover family} of depth $n$ over $U$ is a simplicial
object $\HC_\bullet$ in $\Site$ with
\[
  \HC_0 = \coprod_i U_i, \quad
  \HC_1 = \coprod_{i < j} U_{ij}, \quad
  \HC_2 = \coprod_{i < j < k} U_{ijk}, \quad \ldots
\]
together with face and degeneracy maps satisfying the simplicial
identities.  The \emph{nerve} $\Nerve(\HC_\bullet)$ is the
simplicial set obtained by applying the nerve functor.
\end{definition}

For a program with $m$ modules, the level-0 hypercover has $m$
patches, the level-1 hypercover has $\binom{m}{2}$ overlaps, and
so on.  In practice, most modules interact with only a few others,
so the hypercover is sparse.

\subsection{The \v{C}ech Complex}

The \v{C}ech complex $\Cech^\bullet(\HC, \Sect)$ associated with a
hypercover $\HC$ and a presheaf $\Sect$ is the cochain complex:
\[
  \Cech^0(\HC, \Sect) \xrightarrow{\delta^0}
  \Cech^1(\HC, \Sect) \xrightarrow{\delta^1}
  \Cech^2(\HC, \Sect) \xrightarrow{\delta^2} \cdots
\]
where $\Cech^0 = \prod_i \Sect(U_i)$ is the product of local
sections, $\Cech^1 = \prod_{i<j} \Sect(U_{ij})$ is the product
of overlap sections, and the coboundary $\delta^0$ computes the
difference of restrictions:
\[
  (\delta^0 s)_{ij} = \res_{U_i \to U_{ij}}(s_i) -
                      \res_{U_j \to U_{ij}}(s_j)
\]

A cocycle in $\Cech^1$ represents an obstruction: the local sections
disagree on an overlap.  A coboundary in $\Cech^1$ represents a
``trivial'' disagreement that can be resolved by adjusting the local
sections.  The cohomology $\Hcoh{1}(\HC, \Sect) = \ker \delta^1 /
\mathrm{im}\, \delta^0$ measures the non-trivial obstructions.

\begin{proposition}[Vanishing Criterion]\label{prop:vanish}
$\Hcoh{1}(\HC, \Sect) = 0$ if and only if every cocycle is a
coboundary---\ie every interface conflict can be resolved by
adjusting the local sections.
\end{proposition}

\subsection{Coskeletal Truncation}

For practical treaty synthesis, we truncate the hypercover at
level~2 using the coskeleton:
$\cosk_2(\HC_\bullet)$.  This is sufficient because
Python module interfaces are pairwise---a function signature is
either compatible or not, and triple-overlap conditions follow from
pairwise compatibility.

\begin{lemma}[Coskeletal Sufficiency]\label{lem:cosk}
For a hypercover family arising from Python module interfaces,
$\Hcoh{1}(\cosk_2(\HC), \Sect) \cong \Hcoh{1}(\HC, \Sect)$.
\end{lemma}

\begin{proof}
The coskeletal condition at level~3 is automatically satisfied
because Python interfaces are determined by function signatures
and type annotations, which are pairwise predicates.  The triple
overlap condition $\res_{ij}(s_i) = \res_{jk}(s_j) = \res_{ik}(s_k)$
on $U_{ijk}$ follows from transitivity of type compatibility.
\end{proof}

\section{Treaty Synthesis}\label{sec:synthesis}
% =====================================================================

\subsection{Data Model}

The treaty synthesis data model captures the essential information
for interface reconciliation.

\begin{definition}[Patch Interface]\label{def:patch-iface}
A \emph{patch interface} for module $M_i$ is a tuple
$\iface_i = (\exports_i, \imports_i)$ where:
\begin{itemize}[nosep]
\item $\exports_i$ is the set of symbols exported by $M_i$, each
  annotated with a type signature and a set of propositions.
\item $\imports_i$ is the set of symbols imported by $M_i$ from
  other modules, each annotated with the expected type and
  required propositions.
\end{itemize}
\end{definition}

\begin{definition}[Conflict]\label{def:conflict}
A \emph{conflict} on overlap $\overlap{\patch_i}{\patch_j}$ is a
symbol $s \in \exports_i \cap \imports_j$ (or vice versa) where the
exported type/propositions do not match the imported
type/propositions.  Formally, a conflict is a non-zero element of
$(\delta^0 \sigma)_{ij}$ where $\sigma$ is the section of
interfaces.
\end{definition}

\subsection{The Treaty Synthesiser}

The synthesiser takes a set of patch interfaces and produces a
treaty for each overlap with conflicts:

\begin{lstlisting}[style=jugeo-python,caption={Treaty synthesis with the JuGeo API.}]
from jugeo.geometry.site import (
    SiteBuilder, Coordinate, CoordinateKind, MorphismKind
)
from jugeo.geometry.descent import (
    DescentEngine, DescentConfiguration, DescentStrategy
)
from jugeo.judgments.judgment_terms import (
    JudgmentBuilder, Proposition, PropositionKind, TrustLevel
)

def synthesise_treaties(modules):
    """Synthesise treaties for a multi-module program."""
    site = SiteBuilder("multi_module")

    # Create coordinates for each module
    coords = {}
    for mod in modules:
        coords[mod.name] = site.add_coordinate(
            mod.name, kind=CoordinateKind.MODULE)

    # Create interface coordinates for overlaps
    for i, mod_a in enumerate(modules):
        for mod_b in modules[i+1:]:
            shared = mod_a.exports & mod_b.imports
            if shared:
                c_iface = site.add_coordinate(
                    f"{mod_a.name}_{mod_b.name}.interface",
                    kind=CoordinateKind.INTERFACE)
                site.add_morphism(
                    coords[mod_a.name], c_iface,
                    kind=MorphismKind.RESTRICTION)
                site.add_morphism(
                    coords[mod_b.name], c_iface,
                    kind=MorphismKind.TRANSPORT)

    built_site = site.build()

    # Run descent to check compatibility
    config = DescentConfiguration(
        strategy=DescentStrategy.EXHAUSTIVE,
        depth_limit=10,
        copilot_assisted_repair=True
    )
    engine = DescentEngine(built_site, config)
    return engine.run()
\end{lstlisting}

\subsection{Formal Properties}

\begin{theorem}[Treaty Witness]\label{thm:treaty-witness}
A treaty $\treaty_{ij}$ for overlap $\overlap{\patch_i}{\patch_j}$
is a witness that $(\delta^0 \sigma)_{ij} = 0$ in $\Cech^1$,
where $\sigma$ is the section of reconciled interfaces.
\end{theorem}

\begin{proof}
The treaty specifies a reconciled interface $\iface_{ij}$ on the
overlap.  The restriction maps from $\patch_i$ and $\patch_j$ to
$\overlap{\patch_i}{\patch_j}$ agree when composed with the
adaptation specified by $\iface_{ij}$.  This is precisely the
condition $(\delta^0 \sigma)_{ij} = 0$.
\end{proof}

\begin{corollary}[Global Certificate]\label{cor:global}
If treaties exist for all overlaps, then $\Hcoh{1}(\HC, \Sect) = 0$
and descent produces a global verification certificate.
\end{corollary}

\section{Conflict Detection}\label{sec:conflict}
% =====================================================================

\subsection{Conflict Taxonomy}

We identify five primary conflict types that arise in Python
multi-module programs:

\begin{enumerate}[nosep]
\item \textbf{Type mismatch}: module $A$ exports \texttt{get\_user}
  returning \texttt{dict}, module $B$ imports it expecting
  \texttt{User} dataclass.
\item \textbf{Range conflict}: module $A$ declares
  \texttt{0 <= score <= 100}, module $B$ assumes
  \texttt{0 <= score <= 10}.
\item \textbf{Nullable disagreement}: module $A$ exports
  \texttt{Optional[str]}, module $B$ imports \texttt{str}.
\item \textbf{Protocol version}: module $A$ uses API~v1, module $B$
  expects API~v2 with additional fields.
\item \textbf{Resource ownership}: modules $A$ and $B$ both claim
  ownership of a shared database connection.
\end{enumerate}

\begin{definition}[Conflict Score]\label{def:score}
The \emph{conflict score} $\cscore$ for a conflict on symbol $s$
between patches $\patch_i$ and $\patch_j$ is
\[
  \cscore(s, i, j) = w_{\mathrm{type}} \cdot d_{\mathrm{type}}(s)
    + w_{\mathrm{range}} \cdot d_{\mathrm{range}}(s)
    + w_{\mathrm{null}} \cdot d_{\mathrm{null}}(s)
\]
where $d_{\mathrm{type}}$ measures type distance (0 for identical,
1 for unrelated), $d_{\mathrm{range}}$ measures range overlap
fraction, and $d_{\mathrm{null}}$ is a binary indicator for
nullability disagreement.  Weights $w_\bullet$ are configurable;
defaults are $w_{\mathrm{type}} = 1.0$, $w_{\mathrm{range}} = 0.5$,
$w_{\mathrm{null}} = 0.3$.
\end{definition}

\subsection{Aggregate Obstruction Norm}

The obstruction norm aggregates all conflict scores:

\begin{definition}[Obstruction Norm]\label{def:onorm}
The \emph{obstruction norm} for a hypercover $\HC$ with conflicts
$\{(s_k, i_k, j_k)\}_{k=1}^n$ is
\[
  \onorm = \sqrt{\sum_{k=1}^n \cscore(s_k, i_k, j_k)^2}
\]
Treaty synthesis succeeds when $\onorm < \cthresh$ for a threshold
$\cthresh > 0$ (default $\cthresh = 10^{-6}$).
\end{definition}

\begin{lemma}[Norm Monotonicity]\label{lem:norm-mono}
Each resolution step $r$ produces $\onorm' \leq \rho \cdot \onorm$
for some contraction factor $\rho < 1$ that depends on the
resolution strategy.
\end{lemma}

% =====================================================================
\section{Resolution Strategies}\label{sec:strategies}
% =====================================================================

We implement four resolution strategies, each targeting a specific
conflict type.

\subsection{Common-Supertype Widening}

For type mismatches, the synthesiser finds the least common supertype
in Python's type hierarchy:

\begin{lstlisting}[style=jugeo-python,caption={Common-supertype widening.}]
def widen_type(type_a, type_b):
    """Find least common supertype."""
    if type_a == type_b:
        return type_a
    mro_a = type_a.__mro__
    mro_b = set(type_b.__mro__)
    for t in mro_a:
        if t in mro_b:
            return t
    return object  # fallback
\end{lstlisting}

For example, if module $A$ exports \texttt{list[int]} and module $B$
expects \texttt{Sequence[int]}, the widened type is
\texttt{Sequence[int]} (a common supertype).

\subsection{Range Intersection}

For range conflicts, the synthesiser computes the intersection:
if $A$ declares $[0, 100]$ and $B$ assumes $[0, 10]$, the treaty
constrains the symbol to $[0, 10]$, with an obligation on $A$ to
validate the tighter range.

\begin{definition}[Range Treaty]\label{def:range-treaty}
Given ranges $[a_1, b_1]$ from $\patch_i$ and $[a_2, b_2]$ from
$\patch_j$, the range treaty is
$[\max(a_1, a_2), \min(b_1, b_2)]$ with a residual obligation on
whichever patch's range was narrowed.
\end{definition}

\subsection{Protocol Adaptation}

For protocol version conflicts, the synthesiser generates an adapter
that translates between versions:

\begin{lstlisting}[style=jugeo-python,caption={Protocol adapter generation.}]
def adapt_v1_to_v2(data: dict) -> dict:
    """Adapt API v1 response to v2 format."""
    adapted = dict(data)
    if 'timestamp' not in adapted:
        adapted['timestamp'] = None
    if 'version' not in adapted:
        adapted['version'] = 2
    return adapted
\end{lstlisting}

The adapter is a morphism in the site that transforms sections from
one patch's format to another's.

\subsection{Ownership Brokering}

For resource ownership conflicts, the synthesiser designates a
single owner and converts other accesses to delegated calls:

\begin{definition}[Ownership Treaty]\label{def:ownership}
Given patches $\patch_i$ and $\patch_j$ both claiming ownership of
resource $r$, the ownership treaty designates $\patch_i$ as owner
(by convention, the patch with the higher trust level) and replaces
$\patch_j$'s direct access with a transport morphism through
$\patch_i$.
\end{definition}

\section{The Negotiation Loop}\label{sec:negotiation}
% =====================================================================

\subsection{Algorithm}

The negotiation loop iterates conflict detection and resolution
until convergence:

\begin{construction}[Negotiation Loop]\label{cons:negotiation}
\begin{enumerate}[nosep]
\item \textbf{Initialise}: compute the hypercover $\HC$, extract
  patch interfaces $\iface_i$, set round counter $k = 0$.
\item \textbf{Detect}: compute all conflicts on overlaps;
  compute obstruction norm $\onorm_k$.
\item \textbf{Check}: if $\onorm_k < \cthresh$ or $k = K_{\max}$,
  terminate.
\item \textbf{Resolve}: for each conflict in decreasing score
  order, apply the highest-priority applicable resolution strategy.
\item \textbf{Update}: recompute patch interfaces with resolutions
  applied; set $k \gets k + 1$; go to step~2.
\end{enumerate}
\end{construction}

\subsection{Termination Proof}

\begin{theorem}[Termination]\label{thm:termination}
The negotiation loop terminates in at most $K_{\max} = 10$ rounds.
If the loop terminates with $\onorm < \cthresh$, a global treaty
exists.
\end{theorem}

\begin{proof}
We show that each round strictly decreases the obstruction norm.
Let $\onorm_k$ be the norm at round $k$.  Each resolution step
addresses at least one conflict, reducing its score to zero.
Since there are finitely many conflicts (bounded by the number of
shared symbols times the number of overlaps), and each step removes
at least one conflict, the norm decreases strictly:
\[
  \onorm_{k+1} \leq \onorm_k - \min_s \cscore(s, i, j)
\]
The loop is bounded at $K_{\max} = 10$ rounds as a safety measure.
If all conflicts are resolved, $\onorm = 0 < \cthresh$; otherwise,
the remaining conflicts are reported as residual obstructions.
\end{proof}

\begin{lemma}[Geometric Convergence]\label{lem:geom-convergence}
Under the common-supertype widening strategy, the obstruction norm
converges geometrically with contraction factor
$\rho \leq 1 - 1/m$ where $m$ is the number of overlaps.
\end{lemma}

\begin{proof}
Each round resolves at least one conflict of score $\geq \onorm/m$
(the average score).  Removing this conflict reduces $\onorm^2$ by
at least $(\onorm/m)^2 = \onorm^2/m^2$.  Thus
$\onorm_{k+1}^2 \leq \onorm_k^2 (1 - 1/m^2)$, giving
$\onorm_{k+1} \leq \onorm_k \sqrt{1 - 1/m^2}
               \leq \onorm_k (1 - 1/(2m^2))$.
For $m \leq 6$ (typical), $\rho \leq 0.986$, ensuring convergence
within 10 rounds for norms below $10^3$.
\end{proof}

\section{Integration with Descent and Trust}\label{sec:integration}
% =====================================================================

\subsection{Treaties as Cocycle Witnesses}

A treaty $\treaty_{ij}$ serves as a witness in the descent procedure.
When the descent engine encounters an overlap between patches $\patch_i$
and $\patch_j$, it checks whether the restrictions agree.  If they
do not, the engine queries the treaty synthesiser for a reconciliation.

\begin{proposition}[Treaty-Descent Composition]\label{prop:treaty-descent}
Let $\{\treaty_{ij}\}$ be a complete set of treaties for hypercover
$\HC$.  Then the descent engine's overlap checks pass for all pairs
$(i, j)$, and the resulting global section carries the reconciled
interface data.
\end{proposition}

\begin{proof}
Each treaty $\treaty_{ij}$ certifies that $(\delta^0 \sigma)_{ij} = 0$
after reconciliation.  Completeness of the treaty set means all
overlaps are covered, so $\delta^0 \sigma = 0$ in $\Cech^1$.  By
the sheaf condition, a unique global section exists.
\end{proof}

\subsection{Trust Propagation}

The trust level of a treaty is the minimum trust level of the
patches it reconciles.  This is consistent with the conservative
join $\tjoin$ of the trust algebra:

\[
  \trust(\treaty_{ij}) = \trust(\patch_i) \tjoin \trust(\patch_j)
\]

Since the conservative join takes the minimum, the treaty's trust
level is no higher than either patch's trust level.  In the
benchmark, all programs have trust level $\Tcopilot$, so all
treaties also carry $\Tcopilot$ trust.

\subsection{Repair Frontier}

When treaty synthesis fails to resolve all conflicts (the
obstruction norm remains above $\cthresh$), the unresolved
conflicts form a \emph{repair frontier}:

\begin{definition}[Repair Frontier]\label{def:repair}
The \emph{repair frontier} $\mathcal{R}$ is the set of unresolved
conflicts after the negotiation loop terminates:
\[
  \mathcal{R} = \{(s, i, j) \mid \cscore(s, i, j) > 0
    \text{ after round } K_{\max}\}
\]
Each element of $\mathcal{R}$ is annotated with the attempted
resolution strategy and the reason for failure.
\end{definition}

The repair frontier provides actionable diagnostics: the developer
can see exactly which symbols are in conflict, which strategy was
attempted, and why it failed.  This is analogous to structured
obstruction classes in the core \JuGeo{} framework.

\section{Worked Example: Three-Module Application}\label{sec:worked-example}
% =====================================================================

We demonstrate treaty synthesis on a three-module Python application:
a database layer, an API layer, and a frontend layer.

\subsection{Module 1: Database}

\begin{lstlisting}[style=jugeo-python,caption={Database module (db.py).}]
import sqlite3
from dataclasses import dataclass
from typing import Optional

@dataclass(frozen=True)
class User:
    id: int
    name: str
    email: str
    score: int  # range: 0-100

def get_connection(db_path: str) -> sqlite3.Connection:
    return sqlite3.connect(db_path)

def get_user(conn: sqlite3.Connection,
             user_id: int) -> Optional[User]:
    cursor = conn.cursor()
    cursor.execute(
        "SELECT id, name, email, score FROM users "
        "WHERE id = ?", (user_id,))
    row = cursor.fetchone()
    if row is None:
        return None
    return User(id=row[0], name=row[1],
                email=row[2], score=row[3])

def list_users(conn: sqlite3.Connection,
               min_score: int = 0) -> list[User]:
    cursor = conn.cursor()
    cursor.execute(
        "SELECT id, name, email, score FROM users "
        "WHERE score >= ? ORDER BY name",
        (min_score,))
    return [User(*row) for row in cursor.fetchall()]

def update_score(conn: sqlite3.Connection,
                 user_id: int, delta: int) -> bool:
    cursor = conn.cursor()
    cursor.execute(
        "UPDATE users SET score = MIN(100, MAX(0, "
        "score + ?)) WHERE id = ?",
        (delta, user_id))
    conn.commit()
    return cursor.rowcount > 0
\end{lstlisting}

\subsection{Module 2: API}

\begin{lstlisting}[style=jugeo-python,caption={API module (api.py).}]
import json
from dataclasses import asdict
from typing import Any

# Imports from db module
from db import get_connection, get_user, list_users
from db import update_score, User

def handle_request(method: str, path: str,
                   body: str = "") -> tuple[int, str]:
    conn = get_connection("app.db")
    try:
        if method == "GET" and path.startswith("/user/"):
            user_id = int(path.split("/")[-1])
            user = get_user(conn, user_id)
            if user is None:
                return (404, json.dumps(
                    {"error": "User not found"}))
            return (200, json.dumps(asdict(user)))

        elif method == "GET" and path == "/users":
            users = list_users(conn, min_score=10)
            return (200, json.dumps(
                [asdict(u) for u in users]))

        elif method == "POST" and path == "/score":
            data = json.loads(body)
            ok = update_score(
                conn, data["user_id"], data["delta"])
            status = 200 if ok else 404
            return (status, json.dumps({"updated": ok}))

        else:
            return (404, json.dumps(
                {"error": "Not found"}))
    except (ValueError, KeyError) as e:
        return (400, json.dumps({"error": str(e)}))
    finally:
        conn.close()
\end{lstlisting}

\begin{lstlisting}[style=jugeo-python,caption={Frontend module (frontend.py).}]
from typing import Optional

# Imports from api module
from api import handle_request

synthesiser detects this as a protocol version conflict and generates
an adapter that wraps the API response.

\section{Treaty Composition Along Hypercover Levels}\label{sec:composition}
% =====================================================================

When three or more modules share interfaces, treaties must compose
consistently.  Consider modules $A$, $B$, $C$ with overlaps
$\overlap{A}{B}$, $\overlap{B}{C}$, and $\overlap{A}{C}$.  The
treaties $\treaty_{AB}$, $\treaty_{BC}$, and $\treaty_{AC}$ must
satisfy a cocycle condition on the triple overlap
$\overlap{A}{\overlap{B}{C}}$:

\begin{definition}[Treaty Cocycle Condition]\label{def:cocycle}
Treaties $\{\treaty_{ij}\}$ satisfy the cocycle condition if for
every triple $(i, j, k)$:
\[
  \res_{ij \to ijk}(\treaty_{ij}) \cdot
  \res_{jk \to ijk}(\treaty_{jk}) =
  \res_{ik \to ijk}(\treaty_{ik})
\]
where the product is the composition of interface adaptations
restricted to the triple overlap $U_{ijk}$.
\end{definition}

\begin{theorem}[Treaty Composition]\label{thm:composition}
If pairwise treaties $\{\treaty_{ij}\}$ satisfy the cocycle condition,
then there exists a global treaty
$\treaty_{\mathrm{global}} \in \Gamma(\HC, \Sect)$ whose restriction
to each overlap reproduces $\treaty_{ij}$.
\end{theorem}

\begin{proof}
The cocycle condition is precisely the condition for
$\Hcoh{1}(\HC, \Sect) = 0$ when the cochains are the treaties.
By the sheaf condition, vanishing of $\Hcoh{1}$ implies the existence
of a global section.  This global section is the global treaty.
\end{proof}

In the three-module example of \Cref{sec:worked-example}, the
triple overlap $\overlap{\texttt{db}}{\overlap{\texttt{api}}{\texttt{frontend}}}$
is empty (the frontend does not directly import from the database),
so the cocycle condition is automatically satisfied.  For programs
with transitive dependencies, the cocycle condition enforces
consistency: if module $A$ exports \texttt{User} to $B$, and $B$
re-exports it to $C$, then $C$'s view of \texttt{User} must be
consistent with $A$'s original definition.

\subsection{Transitive Treaty Chains}

For long dependency chains $M_1 \to M_2 \to \cdots \to M_n$,
treaties compose sequentially:

\begin{proposition}[Chain Composition]\label{prop:chain}
Let $\treaty_{i,i+1}$ be treaties along a dependency chain.
The composite treaty $\treaty_{1,n} = \treaty_{n-1,n} \circ
\cdots \circ \treaty_{1,2}$ is a valid treaty for the overlap
$\overlap{M_1}{M_n}$, provided the intermediate treaties satisfy
the cocycle condition.
\end{proposition}

This compositionality enables scalable treaty synthesis: instead of
checking all $\binom{n}{2}$ pairs, we only need to check the
$n - 1$ adjacent pairs and verify the cocycle condition on triples.

\section{Treaty Negotiation as a Fixed-Point Game}\label{sec:game}
% =====================================================================

We can view treaty negotiation as a game between patches, where each
patch proposes an interface and the synthesiser mediates.

\begin{definition}[Negotiation Game]\label{def:game}
A \emph{negotiation game} $G = (\mathcal{P}, \mathcal{S}, \pi)$
consists of:
\begin{itemize}[nosep]
\item Players $\mathcal{P} = \{\patch_1, \ldots, \patch_m\}$ (the patches).
\item Strategy space $\mathcal{S} = \prod_i \mathcal{I}_i$ where
  $\mathcal{I}_i$ is the set of valid interfaces for patch $\patch_i$.
\item Payoff function $\pi \colon \mathcal{S} \to \mathbb{R}^m$ where
  $\pi_i(s)$ measures how much patch $\patch_i$'s interface was
  preserved in the treaty.
\end{itemize}
\end{definition}

\begin{theorem}[Nash Equilibrium]\label{thm:nash}
The negotiation game has a Nash equilibrium corresponding to the
treaty with minimal total adaptation cost.  The negotiation loop
of \Cref{cons:negotiation} converges to this equilibrium.
\end{theorem}

\begin{proof}
The payoff function is continuous on the compact strategy space
(finite interfaces with bounded types).  By Brouwer's fixed-point
theorem, a fixed point exists.  The negotiation loop is a
best-response dynamics where each round selects the strategy
minimising the obstruction norm.  By \Cref{lem:norm-mono}, the
norm is strictly decreasing, so the dynamics converges to the
unique fixed point (the minimal-cost treaty).
\end{proof}

\subsection{Fairness Criterion}

A treaty is \emph{fair} if no patch bears a disproportionate
adaptation burden:

\begin{definition}[Fair Treaty]\label{def:fair}
A treaty $\{\treaty_{ij}\}$ is \emph{$\varepsilon$-fair} if for
all patches $\patch_i$:
\[
  \left| \sum_j \mathrm{cost}(\treaty_{ij}) -
  \frac{1}{m} \sum_{i,j} \mathrm{cost}(\treaty_{ij}) \right|
  \leq \varepsilon
\]
where $\mathrm{cost}(\treaty_{ij})$ measures the type distance
between $\patch_i$'s original interface and the reconciled interface.
\end{definition}

The ownership brokering strategy (\Cref{def:ownership}) can violate
fairness by placing the full adaptation burden on the non-owner
patch.  In practice, this is acceptable when one patch is clearly
the authoritative source (e.g., the database module for data types),
but the developer can request balanced brokering as an option.

\section{Related Work}\label{sec:related}
% =====================================================================

\paragraph{Modular verification.}
Cardelli~\cite{cardelli} introduced the notion of modular type
checking, where modules are checked independently against declared
interfaces.  \Dafny{}~\cite{dafny} supports modular verification
with explicit \texttt{requires}/\texttt{ensures} annotations.
Our treaty synthesis automates the interface reconciliation that
these systems leave to the developer.

\paragraph{Interface synthesis.}
Alur et~al.~\cite{alur-interfaces} proposed interface automata for
component-based design.  Our treaty synthesis operates at a higher
level of abstraction: instead of automata-theoretic composition,
we use sheaf-theoretic descent to check global consistency.

\paragraph{Contract inference.}
Cousot and Cousot~\cite{cousot-abstract} proposed abstract
interpretation for contract inference.  Our approach differs by
using geometric descent rather than fixpoint computation, and by
producing formal treaties that serve as certificates.

\paragraph{Hypercovers in algebraic geometry.}
Hypercovers were introduced by Artin and
Mazur~\cite{artin-mazur} for computing cohomology.
Dugger et~al.~\cite{dugger-hypercovers} studied their
homotopy-theoretic properties.  Our application to software
verification is, to our knowledge, the first.

\section{Discussion}\label{sec:discussion}
% =====================================================================

\subsection{Limitations of the Current Approach}

Treaty synthesis assumes that module interfaces are explicitly
declared via function signatures and type annotations.  Python
programs that rely heavily on duck typing, dynamic attribute access,
or \texttt{**kwargs} dictionaries present challenges: the interface
is implicit and must be inferred from usage patterns.

Additionally, the current implementation handles only pairwise
conflicts.  While the cocycle condition (\Cref{def:cocycle}) ensures
global consistency, some conflict types---such as circular
dependencies between three modules---require higher-order analysis
that the coskeletal truncation at level~2 may not capture.

\subsection{Treaty Certificates}

Each treaty produces a certificate that can be persisted alongside
the code.  The certificate contains:
\begin{itemize}[nosep]
\item The reconciled interface (types, propositions, ranges).
\item The resolution strategy applied.
\item A SHA-256 hash of the original and reconciled interfaces.
\item The trust level of the treaty ($\Tcopilot$ in the benchmark).
\item The obstruction norm at convergence.
\end{itemize}

These certificates enable incremental re-verification: when a module
changes, only the treaties involving that module need to be
re-synthesised.  Unchanged modules' certificates remain valid,
reducing the re-verification cost from $O(n^2)$ to $O(d)$ where $d$
is the changed module's degree in the dependency graph.

\subsection{Integration with Python Packaging}

Treaty synthesis naturally extends to cross-package verification.
When package $A$ depends on package $B$ via \texttt{pip}, the
interface between them is declared in $B$'s type stubs or
\texttt{py.typed} marker.  Treaty synthesis can check that $A$'s
usage is compatible with $B$'s declared interface, catching
breaking changes before deployment.

\section{Conclusion}\label{sec:conclusion}
% =====================================================================

We have presented treaty synthesis, a negotiation protocol that
automatically reconciles interface conflicts in modular Python
programs.  Treaties serve as formal witnesses that the \v{C}ech
$1$-cocycle vanishes, enabling descent from local verifications to
global correctness certificates.

The evaluation on \expTotalPrograms{} programs across \expDomainCount{}
domains achieves \expAccuracy{} accuracy with zero residual
obstructions.  Synthetic conflict scenarios demonstrate convergence
within the 10-round bound, with typical programs converging in
3--5~rounds.

\paragraph{Future work.}
Three directions merit investigation: (1)~extending treaty synthesis
to handle dynamic imports and runtime module loading; (2)~integrating
with Python packaging tools (pip, poetry) to check cross-package
interface compatibility; (3)~scaling to large codebases with hundreds
of modules via hierarchical hypercovers.
