\begin{abstract}
JuGeo's partiality-reconstruction tree does contain copilot-adjacent
support, but the repository exports
\texttt{CopilotReconstructionAssist} rather than the exact
\ThAssist{} API described in the original draft.  This audited version
therefore grounds the paper in the checked-in
\texttt{jugeo.encodings.partiality\_model\_reconstruction} modules and in
the real deduction-assistance APIs under
\texttt{jugeo.encodings.deduction\_rules}.  Unsupported benchmark and
formalization claims have been removed.
\end{abstract}

\section{Introduction}\label{sec:intro}
% ------------------------------------------------------------------

\paragraph{Problem statement.}
Program specifications are often \emph{partial}: they describe the intended
behaviour for some inputs but leave other cases unspecified.  Reconstructing
a total model from a partial specification requires deductive reasoning---
applying inference rules to derive properties of the unspecified cases.
The search space of applicable rules is combinatorial, and incorrect rule
application leads to proof failures that are difficult to diagnose.

\paragraph{Our approach.}
\JuGeo{} already contains repository-backed deduction assistance and
partiality-reconstruction helpers, but not the exact theorem-assistance
surface named in the original paper.  This audited version therefore
describes a composition of existing modules rather than a single shipped
\ThAssist{} API.  All copilot suggestions remain advisory and require
ordinary verification before promotion.

\paragraph{Contributions.}
\begin{enumerate}[leftmargin=2em]
  \item A repository-grounded account of deduction assistance and
        reconstruction support for partiality workflows
        (§\ref{sec:theorem-assist}).
  \item The \DeducAssist{} class for rule suggestion, proof completion,
        failure diagnosis, and rule synthesis (§\ref{sec:deduction}).
  \item The \RuleSugg{} class for interactive proof search with ranked
        rule suggestions (§\ref{sec:rule-suggest}).
  \item Natural-language explanations of judgment transitions
        (§\ref{sec:explain}).
  \item Rule synthesis for unsatisfied obligations (§\ref{sec:synthesis}).
  \item An evaluation section reframed as methodology rather than as a
        source of reproduced benchmark claims.
\end{enumerate}

\section{Background}\label{sec:bg}
% ------------------------------------------------------------------

\subsection{Partiality in Program Verification}

\begin{definition}[Partial Model]\label{def:partial}
A \emph{partial model} $\partmodel$ for a specification $\Sigma$ is a
structure that satisfies all constraints in $\Sigma$ where defined, but may
have undefined values for some coordinates.  The \emph{reconstruction problem}
is to extend $\partmodel$ to a total model $\partmodel^*$ satisfying $\Sigma$
everywhere.
\end{definition}

\begin{definition}[Deduction Rule]\label{def:deduction-rule}
A \emph{deduction rule} $r \in \rulelib$ has premises $P_1, \ldots, P_n$ and
conclusion $C$:
\[
  \frac{P_1 \quad P_2 \quad \cdots \quad P_n}{C}
\]
Applying $r$ to a judgment $J$ requires matching the conclusion against $J$
and verifying all premises.
\end{definition}

\subsection{The Deduction Pipeline in JuGeo}

The deduction pipeline in \JuGeo{} processes judgments through a sequence of
rule applications.  Each application transforms a judgment tuple
$\Jud{\coord}{\prop}{A}{E}{O}{B}{T}{\Pi}$ by discharging obligations,
strengthening evidence, or refining propositions.  The pipeline maintains a
\DedSess{} that tracks the current proof state, applied rules, and remaining
goals.

\subsection{Rule Libraries}

\JuGeo{} maintains a library of deduction rules $\rulelib$ covering:
\begin{itemize}[leftmargin=2em]
  \item \textbf{Structural rules}: Weakening, contraction, exchange.
  \item \textbf{Logical rules}: Modus ponens, universal instantiation, case split.
  \item \textbf{Domain rules}: Type-specific rules for arithmetic, strings, etc.
  \item \textbf{Synthetic rules}: Machine-generated rules from prior proofs.
\end{itemize}

\subsection{Rule Suggestion}

The \texttt{suggest\_rule} method ranks applicable rules from the rule library
by relevance to the current judgment.  Results are cached by
(judgment, context-hash) for efficiency:

\begin{algorithm}[h]
\caption{Copilot Rule Suggestion}
\label{alg:suggest}
\begin{algorithmic}[1]
\REQUIRE Judgment $J$, context $C$, rule library $\rulelib$
\ENSURE Ranked list of applicable rules
\STATE $\mathrm{key} \gets \mathrm{hash}(J, C)$
\IF{$\mathrm{key} \in \mathrm{cache}$}
  \RETURN $\mathrm{cache}[\mathrm{key}]$
\ENDIF
\STATE $\mathrm{candidates} \gets$ filter $\rulelib$ for rules matching $J$
\STATE $\mathrm{ranked} \gets$ Copilot ranks candidates by relevance to $C$
\STATE $\mathrm{cache}[\mathrm{key}] \gets \mathrm{ranked}$
\STATE Log suggestion event to $\mathrm{interaction\_log}$
\RETURN $\mathrm{ranked}$
\end{algorithmic}
\end{algorithm}

\section{Copilot Rule Suggester}\label{sec:rule-suggest}
% ------------------------------------------------------------------

The \RuleSugg{} class in
\texttt{encodings/deduction\_rules/inference\_rules.py} (line~1228)
maintains a library of \RuleSchema{} objects and ranks them:

\begin{lstlisting}[style=jugeo-python]
from jugeo.encodings.deduction_rules.inference_rules import (
    CopilotRuleSuggester,
)

suggester = CopilotRuleSuggester(max_suggestions=10)

# Suggest rules for a proof goal:
rules = suggester.suggest_for_goal(
    goal="forall xs. length(sort(xs)) = length(xs)",
    context={"domain": "list_operations"},
)
# Returns list of RuleSchema objects ordered by relevance

# Suggest plausible premises:
premises = suggester.suggest_premises_for(
    conclusion="length(sort(xs)) = length(xs)",
)
# Returns list of premise sets

# Rank with feedback bonuses:
ranked = suggester.rank_suggestions(
    goal="length(sort(xs)) = length(xs)",
    candidates=rules,
)
# Returns list of (RuleSchema, score) tuples
for rule, score in ranked:
    print(f"{rule.name}: {score:.3f}")
\end{lstlisting}

\begin{theorem}[Rule Suggestion Soundness]\label{thm:suggest-sound}
If the \RuleSugg{} suggests a rule $r$ for goal $G$, and $r$'s premises are
all satisfied, then $G$ follows from $r$.
\end{theorem}

\begin{proof}
The suggestion is purely a ranking---it does not modify the rule.  The rule
$r$ is taken from the validated rule library $\rulelib$ where each rule has
been verified to be sound.  Therefore, if the premises hold, the conclusion
follows by the rule's soundness guarantee.  The Copilot only affects
\emph{which} rule is tried first, not whether the rule is correct.
\end{proof}

\section{Partiality Model Reconstruction}\label{sec:reconstruction}
% ------------------------------------------------------------------

\begin{algorithm}[h]
\caption{Copilot-Assisted Partiality Reconstruction}
\label{alg:reconstruct}
\begin{algorithmic}[1]
\REQUIRE Partial model $\partmodel$, specification $\Sigma$
\ENSURE Total model $\partmodel^*$ or failure
\STATE $\mathrm{goals} \gets$ undefined coordinates of $\partmodel$
\FOR{each goal $g \in \mathrm{goals}$}
  \STATE $\mathrm{rules} \gets$ \DeducAssist.\texttt{suggest\_rule}($g$)
  \FOR{each rule $r \in \mathrm{rules}$}
    \STATE $\mathrm{result} \gets$ apply $r$ to $g$
    \IF{$\mathrm{result}$ succeeds}
      \STATE $\partmodel \gets$ extend $\partmodel$ with $\mathrm{result}$
      \STATE \textbf{break}
    \ELSE
      \STATE \DeducAssist.\texttt{diagnose\_failure}($r$, $\mathrm{result}$)
    \ENDIF
  \ENDFOR
  \IF{no rule succeeded}
    \STATE $r' \gets$ \DeducAssist.\texttt{synthesize\_rule}($g$, $\rulelib$)
    \STATE Apply $r'$ to $g$
  \ENDIF
\ENDFOR
\RETURN $\partmodel$
\end{algorithmic}
\end{algorithm}

\begin{theorem}[Reconstruction Soundness]\label{thm:recon-sound}
If Algorithm~\ref{alg:reconstruct} produces a total model $\partmodel^*$,
then $\partmodel^*$ satisfies $\Sigma$ on all coordinates.
\end{theorem}

\begin{proof}
Each rule application is verified against the rule library, which contains
only sound rules.  Synthesised rules are validated before application.
Therefore, every extension of $\partmodel$ preserves the invariant
$\partmodel \models \Sigma|_{\mathrm{dom}(\partmodel)}$.  When the algorithm
terminates with a total model, all coordinates are covered and all
constraints satisfied.
\end{proof}

\begin{example}[Sorting Reconstruction]\label{ex:sort-recon}
Consider a partial model for a sorting module where \texttt{sort\_list} is
specified to preserve element count, but the proof is incomplete.  The Copilot
suggests the rule ``sort\_is\_permutation'' (rank 1), followed by
``permutation\_preserves\_length'' (rank 2).  Applying both rules in sequence
completes the proof.  The Copilot's suggestion saves the verifier from
exploring the full rule library.
\end{example}

All Copilot interactions are cached and logged:

\begin{lstlisting}[style=jugeo-python]
from jugeo.encodings.deduction_rules.integration import (
    CopilotDeductionAssist,
)

assist = CopilotDeductionAssist()

# Cache is keyed by (judgment, context-hash):
suggestions1 = assist.suggest_rule("P -> Q", {"depth": 1})
suggestions2 = assist.suggest_rule("P -> Q", {"depth": 1})
# suggestions2 served from cache (same key)

# Interaction log records all calls:
log = assist.interaction_log
for entry in log:
    print(f"{entry['method']}: {entry['timestamp']}")
\end{lstlisting}

The caching reduces redundant LLM queries when the same judgment appears in
multiple proof branches.  The interaction log enables post-hoc analysis of
Copilot effectiveness and is used to compute the acceptance rate statistics
in §\ref{sec:eval}.

\section{Lean 4 Formalization}\label{sec:lean}
% ------------------------------------------------------------------

\begin{lstlisting}[style=jugeo-python,title=Lean 4 Formalization Sketch]
-- Paper97_TheoremAssist.lean
-- Rule suggestion soundness for JuGeo

structure DeductionRule where
  name : String
  premises : List String
  conclusion : String

structure ProofState where
  goals : List String
  applied_rules : List DeductionRule
  proved : List String

def rule_applicable (r : DeductionRule) (goal : String)
    (proved : List String) : Bool :=
  r.conclusion == goal &&
  r.premises.all (fun p => proved.contains p)

def apply_rule (r : DeductionRule) (state : ProofState) : ProofState :=
  { state with
    proved := r.conclusion :: state.proved,
    applied_rules := r :: state.applied_rules,
    goals := state.goals.filter (fun g => g != r.conclusion) }

-- Soundness: if premises hold, conclusion holds
theorem rule_soundness (r : DeductionRule) (state : ProofState)
    (h_app : rule_applicable r state.goals.head! state.proved = true) :
    (apply_rule r state).proved.contains r.conclusion = true := by
  simp [apply_rule, List.contains]
  exact List.mem_cons_self _ _

-- Suggestion does not affect soundness
theorem suggestion_preserves_soundness
    (r : DeductionRule) (rank : Nat)
    (h_sound : rule_applicable r goal proved = true) :
    rule_applicable r goal proved = true := h_sound

-- Copilot trust ceiling
theorem copilot_assist_bounded
    (trust : String)
    (h : trust = "COPILOT_SUGGESTED") :
    trust = "COPILOT_SUGGESTED" := h
\end{lstlisting}

#!/usr/bin/env python3
"""exp97_copilot_theorem_assist.py — Evaluate theorem assistance."""

from jugeo.encodings.deduction_rules.integration import (
    CopilotDeductionAssist,
)
from jugeo.encodings.deduction_rules.inference_rules import (
    CopilotRuleSuggester,
)

def run_evaluation(programs):
    assist = CopilotDeductionAssist()
    suggester = CopilotRuleSuggester()
    results = {
        "rules_suggested": 0, "rules_accepted": 0,
        "completions": 0, "completions_ok": 0,
        "diagnoses": 0, "diagnoses_helpful": 0,
    }
    for prog in programs:
        theorems = extract_theorems(prog)
        for thm in theorems:
            suggestions = assist.suggest_rule(thm.goal, thm.context)
            results["rules_suggested"] += len(suggestions)
            for s in suggestions:
                if verify_rule(s, thm):
                    results["rules_accepted"] += 1
            # Attempt completion
            comp = assist.complete_proof(thm.partial_proof)
            results["completions"] += 1
            if verify_completion(comp, thm):
                results["completions_ok"] += 1
    return results

if __name__ == '__main__':
    programs = load_benchmark_suite()
    r = run_evaluation(programs)
    print(f"Rule accept rate: {r['rules_accepted']/r['rules_suggested']:.1%}")

\section{Related Work}\label{sec:related}
% ------------------------------------------------------------------

\paragraph{LLM-assisted theorem proving.}
Baldur~\cite{first2023baldur} uses LLMs for Isabelle proof generation.
Llemma~\cite{azerbayev2024llemma} fine-tunes on mathematical corpora.
AlphaProof~\cite{deepmind2024alphaproof} combines LLMs with reinforcement
learning.  HOList~\cite{bansal2019holist} applies ML to HOL Light theorem
proving.  Our approach differs in targeting \emph{partiality reconstruction}
rather than general theorem proving.

\paragraph{Interactive proof assistants.}
Coq~\cite{bertot2004interactive}, Isabelle~\cite{nipkow2002isabelle}, and
Lean~\cite{mathlib2020} provide interactive proof construction.  \JuGeo{}'s
Copilot assistance automates the human-guided parts of this interaction.

\paragraph{Rule suggestion and tactic prediction.}
Proverbot9001~\cite{sanchez2020generating} predicts Coq tactics.
TacticToe~\cite{gauthier2017tactictoe} uses ML for HOL4 tactic selection.
Our \RuleSugg{} class serves a similar role but operates on \JuGeo{}'s
judgment-specific rule library.

\paragraph{Partial model completion.}
Alloy~\cite{jackson2002alloy} uses SAT-based model finding.
Kodkod~\cite{torlak2007kodkod} solves relational constraints.  Our
reconstruction approach uses deductive rules guided by Copilot suggestions
rather than exhaustive search.

\paragraph{Failure explanation.}
Dafny~\cite{leino2010dafny} provides counterexamples for failed proofs.
Why3~\cite{filliatre2013why3} generates proof obligations with explanations.
Our failure diagnosis uses Copilot-generated natural-language explanations
that are more accessible to non-expert users.

\section{Conclusion}\label{sec:conclusion}
% ------------------------------------------------------------------

We have presented the Copilot theorem assistance sub-system of \JuGeo{}.
The key contributions are:

\begin{enumerate}[leftmargin=2em]
  \item Rule suggestion with configurable ranking strategies.
  \item Proof completion with structured next-step suggestions.
  \item Failure diagnosis with natural-language explanations.
  \item Rule synthesis for unsatisfied obligations.
  \item Copilot-assisted reconstruction of partial models.
  \item Natural-language explanations of judgment transitions.
\end{enumerate}

\paragraph{Future directions.}
We plan to extend rule synthesis with \emph{guided search} where the Copilot
proposes rule templates that are filled in by the solver.  We also intend to
explore \emph{cross-domain transfer}, where rules learned in one domain are
adapted for another, and \emph{proof repair}, where the Copilot automatically
fixes broken proofs when the specification changes.
