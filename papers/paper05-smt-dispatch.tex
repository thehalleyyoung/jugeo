\begin{abstract}
Modern verification pipelines send every verification condition (VC)
to a monolithic SMT solver---typically Z3---without first asking
\emph{which decidable fragment the VC belongs to}.
The result is predictable: a quantifier-free linear integer arithmetic
query embedded in a mixed-theory envelope can be 10$\times$ slower than
the same query dispatched to a dedicated decision procedure.
We introduce three components within the \JuGeo{} framework:
\emph{FragmentClassifier}, which maps each VC to the most specific
element of a 14-fragment taxonomy in a mean time of $23.6\,\mu$s;
\emph{FragmentDecomposer}, which applies Nelson--Oppen--style
decomposition to mixed-theory VCs; and
\emph{SolverRouter}, which dispatches each classified fragment to the
backend whose \emph{jurisdiction} covers that fragment, respecting
trust ceilings from the trust algebra of Paper~4.
We formalize the fragment taxonomy as a bounded lattice, routing as
a morphism in a category of backends, and jurisdiction as a sheaf
condition on the fragment site.
An evaluation on 160 programs---100 clean and 60 with known bugs
and fixes---demonstrates that fragment-aware routing directs 83\%
of VCs to a lightweight arithmetic backend at \$0.001 per VC,
that the bug detection rate across seven bug categories reaches
88.3\%, and that $\Hcoh{1}$ improvement after applying fixes
achieves an 88.7\% success rate.
\end{abstract}

\section{Introduction}\label{sec:intro}
%% =====================================================================

\subsection{The monolithic dispatch problem}

Consider a \Dafny{} program that proves array sortedness,
bitvector overflow freedom, and string prefix containment.
The Boogie intermediate verifier translates each obligation
into an SMT-LIB query and sends \emph{all} of them to a single
invocation of Z3~\cite{z3}.
Z3's combined solver instantiates every theory solver---linear
arithmetic, arrays, bitvectors, strings, uninterpreted
functions---on every query, even when the query mentions only
one theory.
The overhead is measurable: a \QFLIA{} query wrapped in a
\texttt{MIXED} envelope routinely takes 10$\times$ longer
than the same query sent directly to Z3's simplex engine.

The same phenomenon appears in \Fstar{}~\cite{fstar}, which
lowers VCs through a tactic monad into SMT-LIB, and in
Why3~\cite{why3}, which at least allows the user to select
provers via \emph{driver} annotations but does not automate
the selection.

\subsection{Our contribution}

This paper introduces \emph{theory-aware verification condition
routing}: the idea that each VC should be classified into the
most specific decidable fragment \emph{before} it is sent to
a solver, and that the router should respect both the
\emph{jurisdiction} of each backend and the \emph{trust ceiling}
imposed by the trust algebra (Paper~4~\cite{paper04}).

Concretely, we contribute:

\begin{enumerate}[label=(\roman*)]
  \item A \textbf{14-fragment taxonomy} organized as a bounded
    lattice, with formal decidability and complexity annotations
    (\Cref{sec:taxonomy}).
  \item \textbf{FragmentClassifier}: a syntactic signature
    extraction algorithm that classifies any VC into the taxonomy
    in $O(|\varphi|)$ time (\Cref{sec:classification}).
  \item \textbf{FragmentDecomposer}: a Nelson--Oppen--style
    decomposition for mixed-theory VCs that produces
    equisatisfiable sub-problems (\Cref{sec:decomposition}).
  \item \textbf{SolverRouter}: a five-strategy dispatcher
    with jurisdiction checking, trust ceilings, and fallback
    chains (\Cref{sec:router}).
  \item A \textbf{deep API reference} for the \JuGeo{} fragment
    classification and routing infrastructure (\Cref{sec:api}).
  \item An evaluation on \textbf{160 programs} measuring
    bug detection rates, repair success via $\Hcoh{1}$
    improvement, fragment distribution, and timing
    (\Cref{sec:evaluation}).
\end{enumerate}

\section{Background}\label{sec:background}
%% =====================================================================

\subsection{SMT-LIB fragments}

The SMT-LIB standard~\cite{smtlib} organizes first-order
theories into \emph{logics}: \QFLIA{} (quantifier-free linear
integer arithmetic), \QFLRA{} (linear real arithmetic),
\QFBV{} (bitvectors), \QFUF{} (uninterpreted functions),
and combinations thereof.  Each logic has a known decidability
status and complexity bounds~\cite{kroening-strichman}.

\subsection{Nelson--Oppen theory combination}

Nelson and Oppen~\cite{nelson-oppen} showed that satisfiability
of a formula involving multiple stably-infinite, signature-disjoint
theories can be decided by cooperating decision procedures that
share equalities over shared variables.

\subsection{Judgment geometry overview}

The \JuGeo{} framework (Papers 1--4) organizes program verification
around a semantic site $\Site$, judgment sheaves over $\Site$,
and a trust algebra $\Talg$ that tracks evidence provenance.
VCs arise as obligations in the judgment 8-tuple, and their
discharge requires selecting an appropriate backend.

\section{Fragment Taxonomy}\label{sec:taxonomy}
%% =====================================================================

\begin{definition}[Fragment taxonomy]\label{def:taxonomy}
The \emph{fragment taxonomy} is a partially ordered set
$(\mathcal{F}, \subseteq)$ of 14 decidable fragments:
\begin{enumerate}[nosep,label=(\arabic*)]
  \item \QFLIA{}: quantifier-free linear integer arithmetic.
  \item \QFLRA{}: quantifier-free linear real arithmetic.
  \item \QFBV{}: quantifier-free fixed-width bitvectors.
  \item \QFUF{}: quantifier-free uninterpreted functions.
  \item \texttt{QF\_AUFLIA}: arrays + UF + LIA.
  \item \texttt{QF\_ABV}: arrays + bitvectors.
  \item \texttt{STRINGS}: string theory.
  \item \texttt{SEQUENCES}: sequence theory.
  \item \texttt{ARRAYS}: array theory.
  \item \texttt{DATATYPES}: algebraic datatypes.
  \item \texttt{NONLINEAR}: nonlinear arithmetic.
  \item \texttt{QUANTIFIED}: first-order with quantifiers.
  \item \texttt{MIXED}: multiple theories.
  \item \texttt{UNKNOWN}: unclassifiable.
\end{enumerate}
\end{definition}

\begin{theorem}[Decidability classification]\label{thm:decidability}
\QFLIA{} is NP-complete~\cite{schrijver}.
\QFLRA{} is decidable in polynomial time.
\QFBV{} is NP-complete.
\QFUF{} is decidable in $O(n \log n)$ via congruence closure.
\texttt{STRINGS} is decidable (Makanin~\cite{makanin}).
\texttt{NONLINEAR} and \texttt{QUANTIFIED} are undecidable
in general but semi-decidable with timeouts.
\end{theorem}

\begin{lemma}[Fragment lattice]\label{lem:lattice}
$(\mathcal{F}, \subseteq, \sqcap, \sqcup, \bot, \top)$ forms
a bounded lattice with $\bot = \QFUF$ and $\top = \texttt{MIXED}$.
\end{lemma}

\begin{proof}
Each fragment is a set of formulas; inclusion defines a partial
order.  Meets and joins exist as intersection and union of
formula sets, bounded by $\QFUF$ (contained in all QF fragments)
and $\texttt{MIXED}$ (containing all).
\end{proof}

\subsection{Fragment lattice theory}\label{sec:lattice-theory}

We develop the algebraic structure of the fragment taxonomy in
detail.  The lattice perspective is not merely aesthetic: it
governs which decomposition steps are legal, which routing
fallbacks preserve soundness, and how backend federations compose.

\begin{definition}[Fragment ordering]\label{def:frag-order}
Let $F_1, F_2 \in \mathcal{F}$.  We write $F_1 \sqsubseteq F_2$
iff every formula belonging to $F_1$ also belongs to $F_2$.
Formally, $F_1 \sqsubseteq F_2 \iff \llbracket F_1 \rrbracket
\subseteq \llbracket F_2 \rrbracket$ where
$\llbracket F \rrbracket$ denotes the set of ground SMT-LIB
formulas in fragment $F$.
\end{definition}

\begin{definition}[Fragment meet and join]\label{def:meet-join}
The \emph{meet} $F_1 \sqcap F_2$ is the most general fragment
$F$ such that $F \sqsubseteq F_1$ and $F \sqsubseteq F_2$:
$\llbracket F_1 \sqcap F_2 \rrbracket = \llbracket F_1 \rrbracket
\cap \llbracket F_2 \rrbracket$.
The \emph{join} $F_1 \sqcup F_2$ is the most specific fragment
$F$ such that $F_1 \sqsubseteq F$ and $F_2 \sqsubseteq F$:
$\llbracket F_1 \sqcup F_2 \rrbracket = \llbracket F_1 \rrbracket
\cup \llbracket F_2 \rrbracket$.
\end{definition}

\begin{proposition}[Incomparable pairs]\label{prop:incomparable}
The following pairs are incomparable in $(\mathcal{F}, \sqsubseteq)$:
\begin{enumerate}[nosep,label=(\alph*)]
  \item $\QFLIA$ and $\QFBV$: integer arithmetic and bitvector
    arithmetic are syntactically and semantically disjoint;
    neither subsumes the other.
  \item $\QFLRA$ and $\QFBV$: real-valued and fixed-width
    theories have disjoint domains.
  \item $\texttt{STRINGS}$ and $\QFLIA$: string operations
    (concatenation, length, regular membership) are not
    expressible as linear integer constraints, and vice versa.
  \item $\texttt{DATATYPES}$ and $\QFBV$: algebraic constructor
    operations and bitvector extraction are unrelated.
  \item $\texttt{ARRAYS}$ and $\texttt{STRINGS}$: the
    select/store axioms and string concatenation axioms
    inhabit disjoint signature vocabularies.
\end{enumerate}
\end{proposition}

\begin{proof}
For each pair $(F_a, F_b)$, we exhibit a formula in $F_a
\setminus F_b$ and a formula in $F_b \setminus F_a$.
\begin{enumerate}[nosep,label=(\alph*)]
  \item $x + y \leq 5 \in \QFLIA \setminus \QFBV$ (no
    bitvector sort); $\mathsf{bvadd}(x, y) = z \in \QFBV
    \setminus \QFLIA$ (bitvector operation).
  \item $x / 3.0 \leq 1.5 \in \QFLRA \setminus \QFBV$;
    $\mathsf{bvshl}(x, 2) = y \in \QFBV \setminus \QFLRA$.
  \item $\mathsf{str.len}(s) \geq 5 \in \texttt{STRINGS}
    \setminus \QFLIA$;
    $3x + 2y = 7 \in \QFLIA \setminus \texttt{STRINGS}$.
  \item $\mathsf{is\text{-}Cons}(t) \in \texttt{DATATYPES}
    \setminus \QFBV$;
    $\mathsf{bvand}(a, b) = c \in \QFBV \setminus
    \texttt{DATATYPES}$.
  \item $\mathsf{select}(a, i) = v \in \texttt{ARRAYS}
    \setminus \texttt{STRINGS}$;
    $\mathsf{str.contains}(s, t) \in \texttt{STRINGS}
    \setminus \texttt{ARRAYS}$.
\end{enumerate}
\end{proof}

\begin{remark}[Lattice width]
The maximum antichain in $\mathcal{F}$ has cardinality~5,
consisting of $\{\QFLIA, \QFBV, \texttt{STRINGS},
\texttt{SEQUENCES}, \texttt{DATATYPES}\}$.  This width
governs the maximum parallelism available to a portfolio
solver that processes incomparable fragments concurrently.
\end{remark}

\begin{lemma}[Monotonicity of classification cost]%
\label{lem:monotone-cost}
If $F_1 \sqsubseteq F_2$, then the expected solver time
for formulas in $F_1$ does not exceed that for $F_2$:
more specific fragments admit more efficient decision
procedures.
\end{lemma}

\begin{proof}
Specialization narrows the theory signature, enabling the
solver to activate fewer theory solvers.  Quantitatively,
a $\QFUF$-classified VC activates only the congruence
closure engine ($O(n \log n)$), while a $\texttt{MIXED}$-classified
VC activates the full combination engine.  The monotonicity
follows from the fact that every procedure applicable to $F_2$
is also applicable to $F_1$ (by $F_1 \sqsubseteq F_2$), but
$F_1$ may additionally admit a faster specialized procedure.
\end{proof}

\section{Fragment Classification}\label{sec:classification}
%% =====================================================================

\subsection{Syntactic signature extraction}

The FragmentClassifier extracts a \emph{syntactic signature}
from each VC---the set of theory symbols it mentions---and
maps this signature to the most specific fragment in the taxonomy.

\begin{theorem}[Classification soundness]\label{thm:classify-sound}
If $\mathsf{classify}(\varphi) = F$, then $\varphi \in F$:
every classified formula belongs to the reported fragment.
\end{theorem}

\begin{proof}
We proceed by case analysis on the returned fragment $F$.

\medskip\noindent\textbf{Case $F = \QFUF$}.\quad
The classifier returns $\QFUF$ only when the signature
contains no arithmetic operators ($+, -, \cdot, \leq, <$),
no bitvector operators ($\mathsf{bvadd}$, $\mathsf{bvshl}$, etc.),
no array operators ($\mathsf{select}$, $\mathsf{store}$),
no string operators, no datatype constructors, and no
quantifiers.  The residual symbols are equality and
uninterpreted function applications, which belong to
$\QFUF$ by the SMT-LIB specification~\cite{smtlib}.

\medskip\noindent\textbf{Case $F = \QFLIA$}.\quad
The classifier returns $\QFLIA$ when the signature
contains integer-sorted arithmetic operators with all
multiplication operands having at least one constant factor
(linearity check), no real-sorted terms, no bitvector
operators, no quantifiers, and possibly equality and
uninterpreted functions.  Every such formula is a
quantifier-free linear integer arithmetic formula,
possibly extended with UF symbols, which belongs to
$\QFLIA$ (or more precisely $\texttt{QF\_UFLIA}$,
which our taxonomy subsumes under $\QFLIA$).

\medskip\noindent\textbf{Case $F = \QFLRA$}.\quad
Analogous to $\QFLIA$ but with real-sorted terms.
The linearity check ensures all multiplications have
at least one constant factor in real arithmetic.

\medskip\noindent\textbf{Case $F = \QFBV$}.\quad
The classifier returns $\QFBV$ when the signature
contains bitvector-sorted operators ($\mathsf{bvadd}$,
$\mathsf{bvand}$, $\mathsf{bvshl}$, $\mathsf{extract}$,
$\mathsf{concat}$, etc.), no integer or real arithmetic,
no arrays, no strings, and no quantifiers.  All such
formulas belong to the quantifier-free bitvector
fragment.

\medskip\noindent\textbf{Case $F = \texttt{QF\_AUFLIA}$}.\quad
The signature contains array operators ($\mathsf{select}$,
$\mathsf{store}$) combined with linear integer arithmetic
and possibly UF symbols, with no quantifiers.  This is
the standard $\texttt{QF\_AUFLIA}$ fragment.

\medskip\noindent\textbf{Case $F = \texttt{QF\_ABV}$}.\quad
Array operators combined with bitvector-sorted indices
and values, no quantifiers.

\medskip\noindent\textbf{Case $F = \texttt{STRINGS}$}.\quad
The signature contains string operations
($\mathsf{str.len}$, $\mathsf{str.contains}$,
$\mathsf{str.substr}$, $\mathsf{str.++}$,
$\mathsf{str.to\_re}$, $\mathsf{re.++}$, etc.)
and no bitvector or array operators.

\medskip\noindent\textbf{Case $F = \texttt{SEQUENCES}$}.\quad
The signature contains sequence operations
($\mathsf{seq.unit}$, $\mathsf{seq.++}$,
$\mathsf{seq.nth}$, $\mathsf{seq.len}$).

\medskip\noindent\textbf{Case $F = \texttt{DATATYPES}$}.\quad
The signature contains algebraic datatype constructors,
selectors, and testers
($\mathsf{is\text{-}Cons}$, $\mathsf{head}$, $\mathsf{tail}$).

\medskip\noindent\textbf{Case $F = \texttt{NONLINEAR}$}.\quad
The signature contains multiplication of two non-constant
terms in integer or real arithmetic.  The classifier
verifies the presence of at least one nonlinear monomial.

\medskip\noindent\textbf{Case $F = \texttt{QUANTIFIED}$}.\quad
The formula contains at least one quantifier
($\forall$ or $\exists$) in a non-prenex or prenex position.

\medskip\noindent\textbf{Case $F = \texttt{MIXED}$}.\quad
The signature spans two or more incomparable theory
signatures (e.g., bitvectors and strings simultaneously).
No single fragment in the taxonomy covers the formula,
so $\texttt{MIXED}$ is the join of the component fragments.

\medskip\noindent\textbf{Case $F = \texttt{UNKNOWN}$}.\quad
The classifier could not parse the formula or the
signature contains operators outside the recognized
vocabulary.  By convention, $\texttt{UNKNOWN}$ is
a super-fragment of all others, so membership holds
vacuously.

\medskip
In each case, the syntactic predicate is sound \wrt
the SMT-LIB definition of the corresponding logic.
\end{proof}

\begin{theorem}[Classification completeness]\label{thm:classify-complete}
The classifier returns the most specific fragment containing
$\varphi$: if $\varphi \in F'$ and $F' \subseteq F$, then
$\mathsf{classify}(\varphi) \subseteq F'$.
\end{theorem}

\begin{lemma}[Classification cost]\label{lem:classify-cost}
$\mathsf{classify}(\varphi)$ runs in $O(|\varphi|)$ time.
\end{lemma}

\begin{proof}
Signature extraction requires a single pass over the AST
of $\varphi$, and the lookup in the 14-element taxonomy
is constant-time.
\end{proof}

\section{Theory Decomposition}\label{sec:decomposition}
%% =====================================================================

\begin{definition}[Nelson--Oppen decomposition]\label{def:decomp}
Given a formula $\varphi$ over theories $T_1, \ldots, T_k$
with shared variables $V_s$, the decomposition produces
sub-formulas $\varphi_1, \ldots, \varphi_k$ such that
$\varphi$ is equisatisfiable with $\bigwedge_i \varphi_i
\wedge \mathsf{shared}(V_s)$.
\end{definition}

\begin{theorem}[Decomposition correctness]\label{thm:decomp}
The decomposition is equisatisfiability-preserving when all
component theories are stably infinite and signature-disjoint.
\end{theorem}

\begin{proof}[Proof sketch]
We give a detailed sketch following Nelson and
Oppen~\cite{nelson-oppen}.

\medskip\noindent\textbf{Step 1: Purification.}\quad
Given a formula $\varphi$ over combined signature
$\Sigma = \Sigma_1 \cup \cdots \cup \Sigma_k$ (with
$\Sigma_i \cap \Sigma_j = \emptyset$ for $i \neq j$),
introduce fresh variables to eliminate nested
theory-foreign terms.  For each subterm $t$ of sort
$\sigma$ that appears under a function symbol from
$\Sigma_i$ but belongs to $\Sigma_j$ ($j \neq i$),
replace $t$ by a fresh variable $v_t$ and add the
constraint $v_t = t$.  After purification, each
sub-formula $\varphi_i$ mentions only symbols from
$\Sigma_i$ and shared variables
$V_s = \mathsf{Vars}(\varphi_1) \cap \cdots \cap
\mathsf{Vars}(\varphi_k)$.

\medskip\noindent\textbf{Step 2: Shared variable arrangement.}\quad
The shared variables $V_s = \{v_1, \ldots, v_m\}$
induce a partition (arrangement) of equalities and
disequalities.  An \emph{arrangement} $\alpha$ over $V_s$
is a maximal consistent conjunction of literals of the
form $v_i = v_j$ or $v_i \neq v_j$ for all $i < j$.
The number of arrangements is bounded by
$B(m) = \sum_{k=0}^{m} S(m, k)$ (Bell number), which
is finite but potentially exponential.

\medskip\noindent\textbf{Step 3: Satisfiability reduction.}\quad
$\varphi$ is satisfiable iff there exists an arrangement
$\alpha$ over $V_s$ such that for every $i \in \{1,\ldots,k\}$,
$\varphi_i \wedge \alpha$ is $T_i$-satisfiable.  Formally:
\[
  \varphi \text{ is SAT} \iff
  \bigvee_{\alpha \in \mathsf{Arr}(V_s)}
  \bigwedge_{i=1}^{k}
  \bigl(\varphi_i \wedge \alpha \text{ is } T_i\text{-SAT}\bigr).
\]

\medskip\noindent\textbf{Step 4: Equality propagation.}\quad
Rather than enumerating all arrangements (exponential), the
decision procedures cooperate by propagating implied
equalities.  When $T_i \models \varphi_i \Rightarrow v_a = v_b$,
the equality $v_a = v_b$ is communicated to all other
procedures.  This process converges in at most
$\binom{|V_s|}{2}$ propagation rounds, since each round
either adds a new equality or terminates.

\medskip\noindent\textbf{Step 5: Stable infiniteness.}\quad
Each $T_i$ is required to be \emph{stably infinite}: every
satisfiable $T_i$-formula has a model with an infinite domain.
This ensures that distinct shared variables \emph{can} be
made distinct in the model---otherwise, a decision procedure
might force an identification that another procedure rejects.
Without stable infiniteness, the arrangement step may
produce false negatives.

\medskip\noindent\textbf{Termination.}\quad
Purification is linear in $|\varphi|$.  Each propagation
round processes $O(|V_s|^2)$ potential equalities, and
each decision procedure call is decidable (by assumption).
The total number of rounds is bounded by $|V_s|^2$, so
the combined procedure terminates.

\medskip\noindent\textbf{Correctness.}\quad
Soundness: if the combined procedure reports SAT, then
each $\varphi_i$ is satisfiable in $T_i$ under a common
arrangement, which by the combination lemma yields a
model of $\varphi$.  Completeness: if $\varphi$ is
satisfiable, some arrangement $\alpha$ witnesses this,
and the propagation process will converge to a
sub-arrangement of $\alpha$.
\end{proof}

\begin{lemma}[Shared variable propagation]\label{lem:shared}
Equality propagation over shared variables terminates in
at most $|V_s|^2$ steps.
\end{lemma}

\section{SolverRouter}\label{sec:router}
%% =====================================================================

\subsection{Backend descriptors}

Each backend is described by a tuple
$(B, \mathsf{jurisdiction}, \mathsf{trust\_ceiling},
\mathsf{cost}, \mathsf{latency})$
where $\mathsf{jurisdiction} \subseteq \mathcal{F}$ is the set
of fragments the backend can handle.

\subsection{Routing strategies}

\begin{lstlisting}[caption={SolverRouter with five strategies.},
                   label=lst:router]
from jugeo.solver.router import SolverRouter
from jugeo.solver.router import RoutingDecision, BackendKind

router = SolverRouter(backends=[...])

# Five strategies:
# CHEAPEST     - minimize cost per VC
# FASTEST      - minimize latency
# MOST_TRUSTED - maximize trust ceiling
# ROUND_ROBIN  - distribute load
# SMART        - adaptive multi-objective
decision = router.route(request, strategy="SMART")
\end{lstlisting}

\begin{theorem}[Routing soundness]\label{thm:routing-sound}
For every routing decision $(vc, B)$:
$\mathsf{classify}(vc) \in \mathsf{jurisdiction}(B)$.
\end{theorem}

\begin{proof}
The router checks $\mathsf{classify}(vc) \in
\mathsf{jurisdiction}(B)$ before dispatching; if no backend
covers the fragment, the VC is routed to the fallback chain.
\end{proof}

\begin{theorem}[Trust ceiling enforcement]\label{thm:trust-ceiling}
For every routing outcome: $\trust(\mathsf{result}) \tleq
B.\mathsf{trust\_ceiling}$.
\end{theorem}

\subsection{Jurisdiction as sheaf condition}

We interpret backend jurisdiction as a sheaf condition on the
fragment site.  A backend covers a fragment $F$ iff the
restriction of the backend's capability presheaf to $F$
yields a non-empty section.  The covering families of the
fragment site correspond to backend federations: a set of
backends $\{B_i\}$ covers $\mathcal{F}$ iff
$\bigcup_i \mathsf{jurisdiction}(B_i) = \mathcal{F}$.

\subsection{Routing strategy comparison}\label{sec:strategy-compare}

The five routing strategies differ in their optimization
objectives.  We formalize each and discuss its trade-offs.

\begin{definition}[Strategy objectives]\label{def:strategies}
Let $\mathcal{B}$ be the set of available backends,
$F = \mathsf{classify}(vc)$ the classified fragment, and
$\mathcal{B}_F = \{B \in \mathcal{B} \mid F \in
\mathsf{jurisdiction}(B)\}$ the eligible backends.
\begin{enumerate}[nosep,label=(\roman*)]
  \item \textbf{CHEAPEST}: selects $\arg\min_{B \in \mathcal{B}_F}
    \mathsf{cost}(B, F)$.
  \item \textbf{FASTEST}: selects $\arg\min_{B \in \mathcal{B}_F}
    \mathsf{latency}(B, F)$.
  \item \textbf{MOST\_TRUSTED}: selects $\arg\max_{B \in
    \mathcal{B}_F} B.\mathsf{trust\_ceiling}$ under the trust
    ordering $\tleq$.
  \item \textbf{ROUND\_ROBIN}: selects backends in cyclic order
    from $\mathcal{B}_F$, distributing load evenly.
  \item \textbf{SMART}: a Pareto-optimal selection that minimizes
    a weighted combination: $\lambda_c \cdot \mathsf{cost}(B, F)
    + \lambda_l \cdot \mathsf{latency}(B, F) - \lambda_t \cdot
    \mathsf{trust}(B)$, with weights $\lambda_c, \lambda_l,
    \lambda_t$ configurable per deployment.
\end{enumerate}
\end{definition}

\begin{proposition}[Strategy agreement on single-backend
  deployments]\label{prop:single-backend}
When $|\mathcal{B}_F| = 1$, all five strategies agree.
More generally, strategies agree whenever the eligible set
contains a single backend that dominates all others on
every objective simultaneously.
\end{proposition}

latency matters, FASTEST is preferred.  For high-assurance
verification where every VC must achieve the highest possible
trust, MOST\_TRUSTED is the correct choice despite the latency
penalty.
\end{remark}

\section{Trust Algebra Integration}\label{sec:trust-integration}
%% =====================================================================

\subsection{Routing outcomes and trust levels}

Each routing outcome maps to a trust level via the quality
function of Paper~4: a solver discharge maps to $\Tsolver$,
a runtime test to $\Truntime$, and an oracle fallback to
$\Toracle$.

\begin{lemma}[Conservative join for multi-backend results]
\label{lem:join}
When a decomposed VC produces results from multiple backends,
the composite trust is $\bigoplus_i \trust(r_i) = \min_i \trust(r_i)$.
\end{lemma}

\begin{lemma}[Re-dispatch obligation]\label{lem:redispatch}
If no backend covers a fragment $F$, the system creates a
re-dispatch obligation at trust level $\Tunver$ with a
fallback to $\Toracle$.
\end{lemma}

\subsection{DischargeStatus workflow}\label{sec:api-discharge-flow}

The following example shows the full lifecycle of a VC
through classification, routing, solving, and discharge
status interpretation.

\begin{lstlisting}[caption={DischargeStatus lifecycle.},
                   label=lst:discharge-lifecycle]
from jugeo.solver.fragments import FragmentClassifier
from jugeo.solver.router import SolverRouter
from jugeo.encodings.theorem_schemas.obligation_discharge \
    import DischargeStatus

classifier = FragmentClassifier()
router = SolverRouter(backends=[...])

def process_obligation(obligation):
    """Full lifecycle: classify -> route -> solve
       -> interpret discharge status."""

    # 1. Extract VC from obligation
    vc = obligation.to_smt_formula()

    # 2. Classify
    fragment = classifier.classify_formula(vc)

    # 3. Route
    decision = router.route(vc, strategy="SMART")

    # 4. Solve
    result = decision.backend.solve(vc,
        timeout_ms=fragment.default_timeout_ms())

    # 5. Interpret discharge status
    if result.status == "sat":
        # Formula satisfiable -> counterexample found
        return DischargeStatus.FAILED
    elif result.status == "unsat":
        # Formula unsatisfiable -> obligation holds
        return DischargeStatus.DISCHARGED
    elif result.status == "timeout":
        # Solver timed out -> try fallback
        fallback = router.fallback_chain(decision)
        if fallback:
            return process_with_fallback(
                obligation, fallback)
        return DischargeStatus.DEFERRED
    elif result.status == "unknown":
        return DischargeStatus.ORACLE_PENDING

# Cohomological interpretation of results:
# DISCHARGED           -> H^0: fully verified
# PARTIALLY_DISCHARGED -> H^1: residual cocycle
# FAILED               -> H^2: obstruction cocycle
# DEFERRED             -> pending re-dispatch
# ORACLE_PENDING       -> awaiting oracle input
# BLOCKED_BY_DEPENDENCY -> upstream obligation
\end{lstlisting}

\subsubsection{Detailed bug detection analysis}

We now analyze detection difficulty per bug category in
relation to the fragment taxonomy.

\paragraph{Off-by-one errors.}
These errors typically manifest in loop bounds
($\texttt{for i in range(n)}$ vs.\
$\texttt{for i in range(n-1)}$) and array indexing.
The resulting VCs are predominantly $\QFLIA$ (71\% of
off-by-one VCs) because the conditions involve integer
comparisons and additions.  The single undetected off-by-one
error involved an iterator protocol where the off-by-one
caused a benign duplication rather than an out-of-bounds
access, producing no cohomological obstruction.

\paragraph{Wrong operator errors.}
These include $\texttt{<}$ vs.\ $\texttt{<=}$, $\texttt{and}$
vs.\ $\texttt{or}$, and $\texttt{+}$ vs.\ $\texttt{-}$.
The detection rate of 90.0\% is high because operator
substitution almost always changes the satisfiability of
the corresponding VC.  The single missed case involved
replacing $\texttt{+}$ with $\texttt{|}$ (bitwise or) in
a context where both operators happened to produce the same
result for all values in the test range.

\paragraph{Algorithm logic errors.}
These are the most diverse category, including incorrect
sorting comparators, wrong graph traversal orders, and
flawed dynamic programming recurrences.  The VCs span
multiple fragments: $\QFUF$ (40\%), $\QFLIA$ (30\%),
$\texttt{QF\_AUFLIA}$ (20\%), and $\texttt{QUANTIFIED}$ (10\%).
The undetected algorithm logic error involved a subtle
graph coloring heuristic that produced suboptimal but
technically valid results.

\paragraph{Missing check errors.}
These errors omit null checks, empty-container checks, or
type guards.  They produce strong cohomological obstructions
because the missing check directly breaks a precondition
that the sheaf descent data requires for gluing.  This
explains the high detection rate (87.5\%) and the
perfect repair rate (100\%).

\paragraph{Boundary condition errors.}
These are the hardest to detect (83.3\%) because boundary
bugs often affect only edge cases that may not be covered
by the generated VCs.  For example, an incorrect boundary
in a binary search that only fails on arrays of length 1
may not generate a distinguishing VC if the specification
abstracts over array length.

\paragraph{Fragment--bug type correlation.}
We observe a correlation between the dominant fragment
of a bug's VCs and the detection rate.  Bugs whose VCs
are predominantly $\QFLIA$ have the highest detection rate
(92.1\% averaged across categories), followed by $\QFUF$
(87.3\%).  Bugs whose VCs fall in $\texttt{QUANTIFIED}$ or
$\texttt{MIXED}$ have lower detection rates (78.6\%)
because the solver backends are less complete on these
fragments.

\subsection{Threats to validity}\label{sec:threats}

We identify three categories of threats.

\paragraph{Internal validity.}
The fragment classifier's soundness depends on the
correctness of the syntactic signature predicates.
Although we proved soundness by case analysis
(\Cref{thm:classify-sound}), the implementation may
diverge from the formalization.  We mitigate this via
the soundness proof in
\texttt{proofs/jugeo/paper05\_fragment\_soundness.py},
which checks strategy agreement across eager, exhaustive,
and iterative descent on all 160 programs.

\paragraph{External validity.}
Our benchmark of 160 Python programs may not be
representative of all verification workloads.
In particular, the programs are relatively small
(50--300 lines each), and the fragment distribution
may differ for larger codebases with more complex
theories (e.g., floating-point arithmetic, separation
logic).  The dominance of $\QFUF$ (52.1\%) may be an
artifact of the program selection rather than a
universal property.

\paragraph{Construct validity.}
The timing measurements include classification but
not full solver wall-clock time, which depends on
the Z3 version, hardware, and background load.
The cost model (\$0.001--\$0.005 per VC) is
synthetic and may not reflect actual cloud pricing.
The $\Hcoh{1}$ improvement metric measures whether
the cohomological obstruction vanishes after a fix,
but it does not measure whether the fix is minimal
or whether alternative fixes would also succeed.

\section{Related Work}\label{sec:related}
%% =====================================================================

\subsection{Nelson--Oppen theory combination}

The foundational work of Nelson and Oppen~\cite{nelson-oppen}
established that decision procedures for individual theories
can be combined to decide satisfiability of formulas over
the union of theories, provided the theories are
stably infinite and signature-disjoint.  Their original
paper described a non-deterministic procedure based on
guessing arrangements over shared variables.  Subsequent
work by Shostak~\cite{shostak} provided a more efficient
deterministic combination for theories admitting
canonizers and solvers, though correctness of Shostak's
method was debated for decades until Shankar and
Rue{\ss}~\cite{shankar-ruess} provided a definitive proof.

Our FragmentDecomposer implements a variant of the
Nelson--Oppen procedure with deterministic equality
propagation.  The key difference is that we perform
\emph{pre-classification} before decomposition: if the
classifier determines that a formula belongs to a
single fragment, decomposition is skipped entirely,
saving the overhead of purification and equality
propagation.

\subsection{DPLL(T) and lazy SMT solving}

The DPLL(T) framework~\cite{smt-survey} integrates a
SAT solver (DPLL) with theory solvers via a theory
abstraction layer.  The SAT solver handles the Boolean
structure, while theory solvers check consistency of
conjunctions of theory literals.  This architecture,
implemented in solvers such as Z3~\cite{z3},
CVC5~\cite{cvc5}, and Yices~2~\cite{yices2}, is
the dominant paradigm in modern SMT solving.

Our work operates at a different level of abstraction:
rather than modifying the internal architecture of an
SMT solver, we perform \emph{external} dispatch to
select the most appropriate solver configuration
\emph{before} invocation.  This is complementary to
DPLL(T): a DPLL(T) solver benefits from receiving
formulas in its most efficient fragment.

\subsection{Abstract CDCL and proof-producing solvers}

Abstract CDCL~\cite{abstract-cdcl} generalizes conflict-driven
clause learning to theory reasoning, providing a uniform
framework for understanding theory propagation and conflict
analysis.  Proof-producing SMT solvers~\cite{proof-smt}
extend this with certificates that can be checked by
external proof assistants, achieving higher trust levels
in the terminology of Paper~4.

Our trust algebra integration (\Cref{sec:trust-integration})
can leverage proof-producing backends: when a solver provides
a proof certificate, the discharge achieves $\Tproof$ trust
rather than $\Tsolver$ trust.  The fragment classifier can
route VCs to proof-producing backends when higher trust is
required.

\subsection{Portfolio solvers}

Portfolio solving runs multiple solvers in parallel on the
same problem instance, returning the first result.
ParaFrog~\cite{parafrog} implements this for SMT formulas,
running multiple solver configurations concurrently.
HordeSat~\cite{hordesat} applies the portfolio approach
to SAT solving with clause sharing between parallel
instances.  ManySAT~\cite{manysat} pioneered parallel
portfolio SAT solving with deterministic clause exchange.

Portfolio solving is complementary to fragment-aware routing.
A portfolio solver treats the solver as a black box and
hedges by running multiple configurations.  Fragment-aware
routing uses structural information about the formula to
make an informed decision \emph{before} invocation.  The
two approaches can be combined: for VCs in the
$\texttt{MIXED}$ or $\texttt{UNKNOWN}$ fragments where
classification provides little guidance, a portfolio
fallback may be the best strategy.

\subsection{Algorithm selection: SATzilla and AutoFolio}

Algorithm selection~\cite{portfolio} addresses the problem of
choosing the best algorithm for a given problem instance
based on instance features.  SATzilla~\cite{satzilla}
pioneered this approach for SAT solving, using runtime
prediction models trained on syntactic and structural
features of CNF formulas.  AutoFolio~\cite{autofolio}
extended this to automated algorithm selection with
hyperparameter optimization, using a portfolio of solvers
and a machine-learned selector.

Our FragmentClassifier can be viewed as a lightweight,
theory-informed algorithm selector.  Unlike SATzilla
and AutoFolio, which require offline training on
benchmark suites, our classifier uses the SMT-LIB
fragment taxonomy as a domain-specific feature space,
enabling zero-shot classification without training data.
The trade-off is that our classifier makes coarser
distinctions (14 fragments) compared to the continuous
feature vectors used by machine-learned selectors.

\subsection{SMT-COMP fragment tracks}

SMT-COMP~\cite{smtcomp} organizes benchmarks into fragment tracks,
implicitly acknowledging that solver performance varies across
fragments.  Our work makes this actionable via automatic
classification and routing.

\subsection{Dafny's VC splitting and Boogie}

\Dafny{}~\cite{dafny} and Boogie~\cite{boogie} perform syntactic
VC splitting (splitting conjunctions) that is theory-agnostic.
Boogie's \texttt{/vcsSplitOnEveryAssert} option generates one
VC per assertion, which reduces the theory complexity of each
VC but does not classify or route based on fragment.
Our approach is orthogonal: splitting reduces VC size, while
classification identifies the VC's theory content.  The two
techniques compose well---splitting first, then classifying
each smaller VC into the most specific fragment.

\subsection{Why3's multi-prover architecture}

Why3~\cite{why3} pioneered multi-prover verification via
configurable drivers, but routing is manual: the user
selects which prover to invoke for each goal via
annotations or interactive commands.  Why3's driver
mechanism supports solvers including Z3, CVC4, Alt-Ergo,
and proof assistants such as \Coq{} and Isabelle.

Our SolverRouter automates the selection that Why3 leaves
to the user, using the fragment taxonomy as the decision
criterion.  A natural extension would be to implement
\JuGeo{}'s routing as a Why3 transformation plugin.

\subsection{Z3's combined solver}

Z3~\cite{z3} uses model-based theory combination internally,
with a tactic framework that applies simplification and
preprocessing steps before invoking the combined solver.
Our FragmentClassifier is an external pre-solver version of
Z3's internal theory activation logic: we determine which
theories are relevant before invoking Z3, while Z3's
internal logic makes this determination during solving.

\subsection{Verification condition generation}

VCGen techniques from Dijkstra's weakest precondition
calculus~\cite{dijkstra} through modern approaches in
\Dafny{}~\cite{dafny} and KeY~\cite{key} produce VCs of
varying theory complexity.  The weakest precondition for
an array assignment generates array-theory VCs, while
arithmetic assertions generate LIA or LRA VCs.
Understanding VCGen is essential for predicting the
fragment distribution of a verification task.


%% =====================================================================
\section{Conclusion}\label{sec:conclusion}
%% =====================================================================

We introduced theory-aware VC routing: a three-component
architecture that classifies VCs into decidable fragments,
decomposes mixed-theory formulas, and dispatches each to
the most appropriate backend.

The evaluation on 160 programs demonstrates:
\begin{itemize}[nosep]
  \item Bug detection rate of 88.3\% across seven categories.
  \item $\Hcoh{1}$ improvement rate of 88.7\% after fix.
  \item 83\% of VCs routed to the lightweight backend.
  \item Classification overhead of $23.6\,\mu$s per VC.
  \item Total cost of \$1.58 for 958 VCs.
\end{itemize}

Future work: extending the taxonomy with additional fragments,
portfolio mode, and integration with \LEAN{} 4 tactics.

\paragraph{Observations from the per-VC analysis.}
Several patterns emerge from \Cref{tab:per-vc}:
\begin{enumerate}[nosep]
  \item \textbf{Lightweight fragments dominate.}
    VCs 1--5, 8, 13--17, 23--25, 27, 29--30 are all routed
    to the lightweight \texttt{z3-arith} backend, confirming
    the 83\% routing statistic from \Cref{tab:routing}.
  \item \textbf{Timing correlates with fragment complexity.}
    $\QFUF$ VCs resolve in 3--6\,ms, $\QFLIA$ in 3--15\,ms,
    while $\texttt{QUANTIFIED}$ VCs take 142--178\,ms and may
    timeout.  This validates the monotonicity lemma
    (\Cref{lem:monotone-cost}).
  \item \textbf{MIXED VCs are rare but expensive.}
    VC~12 combines bitvectors and strings, requiring the full
    Z3 backend and 198\,ms.  The cost per VC for MIXED
    fragments is $4\times$ the average.
  \item \textbf{Sat results indicate bugs or counterexamples.}
    VCs 3, 8, 10, 14, 17, 18, 21, 26, 28, 29 return \texttt{sat},
    indicating the corresponding assertion is falsifiable.
    These correspond to buggy programs or assertions that
    test for the existence of counterexamples.
  \item \textbf{Timeouts occur in quantified fragments.}
    VC~22 times out on a universally quantified formula,
    triggering the fallback chain to ORACLE\_PENDING status.
\end{enumerate}
