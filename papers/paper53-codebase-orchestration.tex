\begin{abstract}
We address the challenge of applying \JuGeo\ to large, multi-module
codebases where monolithic site construction is infeasible.  We
introduce \emph{site decomposition}, which partitions a codebase's
semantic site into independent shards, and \emph{parallel federation},
which verifies shards concurrently and merges local verdicts into a
global judgment.  The \ChangeOfSite\ functor transports judgments
across shard boundaries, while \HypercoverTreaty\ negotiates interface
contracts between modules.  Our central theorem, \emph{Federation
Soundness}, guarantees that federated verification is equivalent to
monolithic verification.  Experiments on \expTotalPrograms\ programs
show that site construction takes $\compSiteMeanBuildMs$\,ms per
shard with $\compSiteMeanMorphisms$ morphisms, and the federation
achieves \compOverallAccuracy\ accuracy while parallelizing across
$\subDescentStrategies$ worker threads.  The approach enables \JuGeo\
to scale from single-file analysis to repository-level verification.
\end{abstract}

\section{Introduction}\label{sec:intro}
% =====================================================================

Modern software projects span thousands of files, hundreds of modules,
and millions of lines of code.  Verification tools that analyze
programs monolithically face quadratic or worse scaling in the number
of inter-module dependencies.  \JuGeo's sheaf-theoretic framework
naturally supports \emph{locality}: the gluing axiom ensures that
local correctness implies global correctness, provided interface
contracts are respected.

\paragraph{The scalability challenge.}
Constructing a single semantic site for a large codebase requires
enumerating all coordinates and morphisms simultaneously.  For a
codebase with $n$ modules and $m$ cross-module dependencies, the
site has $O(n)$ objects and $O(m)$ morphisms.  When $m$ is large,
monolithic construction becomes a bottleneck.

\paragraph{Contributions.}
\begin{itemize}[noitemsep]
  \item A formal theory of \emph{site decomposition} that partitions
        $\GlobalSite$ into independent shards $\ShardSite_1, \ldots,
        \ShardSite_k$ (§\ref{sec:decomposition}).
  \item The \emph{parallel federation} protocol for concurrent shard
        verification (§\ref{sec:federation}).
  \item The \ChangeOfSite\ functor for transporting judgments across
        shard boundaries (§\ref{sec:transport}).
  \item The \HypercoverTreaty\ mechanism for interface contract
        negotiation (§\ref{sec:treaty}).
  \item Federation Soundness theorem, proved in Lean~4
        (§\ref{sec:lean-proof}).
  \item Scalability evaluation on codebases of varying size
        (§\ref{sec:evaluation}).
\end{itemize}

\section{Background}\label{sec:background}
% =====================================================================

\subsection{Modular Verification}
Modular verification~\cite{Hoare1972,Leino2010} analyzes program
components independently, requiring interface specifications (contracts)
at module boundaries.  \JuGeo\ automates contract inference through
its judgment framework.

\subsection{Semantic Sites at Scale}
A \JuGeo\ site $\Site = (\Ob, \Mor, \Cov)$ organizes program
coordinates.  For a single file, $|\Ob|$ is typically
$\expCoordsMin$--$\expCoordsMax$ coordinates.  For a multi-module
codebase, $|\Ob|$ grows linearly with the number of functions and
classes, and $|\Mor|$ grows with cross-module call-graph edges.

\subsection{Change of Site}
The \ChangeOfSite\ API method implements the categorical notion of
a site morphism $f\colon \Site_1 \to \Site_2$, inducing a pullback
functor $f^*\colon \mathrm{Sh}(\Site_2) \to \mathrm{Sh}(\Site_1)$
that transports judgments between sites.

\section{Site Decomposition}\label{sec:decomposition}
% =====================================================================

\subsection{Partitioning Strategy}
Given a global site $\GlobalSite$ with $n$ objects and $m$ morphisms,
we partition into $k$ shards by cutting at module boundaries:

\begin{definition}[Site Decomposition]\label{def:decomposition}
A \emph{site decomposition} of $\GlobalSite$ is a family of sub-sites
$\{\ShardSite_i\}_{i=1}^k$ such that:
\begin{enumerate}[noitemsep]
  \item $\bigcup_i \Ob(\ShardSite_i) = \Ob(\GlobalSite)$.
  \item Each internal morphism of $\GlobalSite$ belongs to exactly one
        $\ShardSite_i$.
  \item Cross-shard morphisms are collected in the \emph{boundary
        complex} $\partial = \{f \in \Mor(\GlobalSite) \mid
        f \notin \Mor(\ShardSite_i)\;\forall i\}$.
\end{enumerate}
\end{definition}

\subsection{Boundary Complex}
The boundary complex $\partial$ captures all cross-module dependencies.
Its structure determines the difficulty of federation: when $|\partial|$
is small relative to $|\Mor(\GlobalSite)|$, decomposition is effective.

\begin{lstlisting}[style=jugeo-python]
from jugeo.geometry.site import Coordinate, CoordinateKind, SiteBuilder

mod_a = Coordinate(("repo", "mod_a"), kind=CoordinateKind.MODULE)
fn_a = Coordinate(("repo", "mod_a", "f"), kind=CoordinateKind.FUNCTION)
mod_b = Coordinate(("repo", "mod_b"), kind=CoordinateKind.MODULE)

global_site = (
    SiteBuilder("repo")
    .add_coordinate(mod_a)
    .add_coordinate(fn_a)
    .add_coordinate(mod_b)
    .build()
)

shard_a = global_site.restrict_to_subsite({mod_a.name, fn_a.name})
transported = shard_a.change_of_site(
    lambda coord: Coordinate(
        ("shard_a",) + coord.components[1:],
        kind=coord.kind,
    )
)

print(shard_a.coordinate_count(), transported.coordinate_count())
\end{lstlisting}

\subsection{Decomposition Quality Metrics}
We measure quality by the \emph{boundary ratio}
$\beta = |\partial| / |\Mor(\GlobalSite)|$.  The comprehensive data
reports $\compMorphTotal$ total morphisms, with $\compMorphRestriction$
restrictions (shard-internal) and $\compMorphTransport$ transports
(cross-shard).

\section{Parallel Federation}\label{sec:federation}
% =====================================================================

\subsection{Federation Protocol}

\begin{algorithm}[H]
\caption{Parallel Federation Protocol}
\label{alg:federation}
\begin{algorithmic}[1]
\STATE \textbf{Input:} Shards $\{\ShardSite_i\}_{i=1}^k$, boundary
       $\partial$
\STATE \textbf{Output:} Global verdict $\GlobalVerdict$
\STATE $\text{treaties} \gets \texttt{hypercover\_treaty}(\partial)$
\STATE \textbf{parallel for} $i = 1, \ldots, k$ \textbf{do}
  \STATE \quad $v_i \gets \texttt{verify\_shard}(\ShardSite_i, \text{treaties})$
  \STATE \quad \textbf{emit} $(\LocalVerdict, i, v_i)$
\STATE \textbf{end parallel}
\STATE $\mathcal{V} \gets \{v_1, \ldots, v_k\}$
\STATE $\text{consistent} \gets \texttt{check\_boundary}(\mathcal{V}, \partial)$
\IF{$\text{consistent}$ \textbf{and} all $v_i = \texttt{pass}$}
  \RETURN $\GlobalVerdict = \texttt{PASS}$
\ELSE
  \RETURN $\GlobalVerdict = \texttt{FAIL}$ with diagnostics
\ENDIF
\end{algorithmic}
\end{algorithm}

\subsection{Shard Verification}
Each shard is verified independently using the standard \JuGeo\
pipeline: site construction via \FormalCore, judgment generation,
descent, and trust assignment.  Shard verification takes $\compTimeMean$
mean time.

\subsection{Treaty Negotiation}
The \HypercoverTreaty\ method negotiates contracts at shard boundaries:

\begin{definition}[Interface Treaty]\label{def:treaty}
An \emph{interface treaty} for cross-shard morphism $f\colon U \to V$
with $U \in \ShardSite_i$ and $V \in \ShardSite_j$ is a pair
$(\phi_U, \phi_V)$ of judgments such that:
\begin{enumerate}[noitemsep]
  \item $\ShardSite_i$ verifies $\phi_U$ (the \emph{guarantee}).
  \item $\ShardSite_j$ assumes $\phi_V$ (the \emph{assumption}).
  \item $\phi_U$ entails $\phi_V$ under the morphism $f$.
\end{enumerate}
\end{definition}

Treaty negotiation time is $\subHypercovertreatySmallTime$ for small
programs and scales linearly with boundary size.

\subsection{Boundary Consistency Check}
After all shards complete, the coordinator checks that every treaty
is satisfied: each guarantee was verified and each assumption is
entailed.  This check runs in time proportional to $|\partial|$.

\section{Change-of-Site Transport}\label{sec:transport}
% =====================================================================

\subsection{The \ChangeOfSite\ Functor}
When a judgment verified in $\ShardSite_i$ must be used in
$\ShardSite_j$, the \ChangeOfSite\ functor transports it:
\[
  f^*\colon \mathrm{Sh}(\ShardSite_j) \to \mathrm{Sh}(\ShardSite_i)
\]
This pullback preserves the sheaf condition and trust tier, ensuring
that a $\Tsolver$-level judgment in one shard remains $\Tsolver$
after transport (modulo treaty compliance).

\begin{theorem}[Transport Soundness]\label{thm:transport}
Let $\J$ be a judgment in $\ShardSite_i$ with $\trust = \Tsolver$,
and let $f\colon \ShardSite_i \to \ShardSite_j$ be a site morphism
respecting the interface treaty.  Then $f^*(\J)$ has $\trust =
\Tsolver$ in $\ShardSite_j$.
\end{theorem}

\begin{proof}
The treaty ensures that the encoding of $f^*(\J)$ in $\ShardSite_j$
is implied by the encoding of $\J$ in $\ShardSite_i$.  Since $\J$
was solver-discharged, transitivity of entailment gives us a valid
proof certificate for $f^*(\J)$.  See Lean~4 proof:
\texttt{Paper53\_CodebaseOrchestration.lean}, theorem
\texttt{transport\_soundness}.
\end{proof}

\subsection{Transport Cost}
The comprehensive data reports $\compProfChangeOfSiteMeanMs$\,ms mean
time for \ChangeOfSite\ operations.  This is dominated by encoding
transformation, not re-verification, making transport lightweight.

\subsection{Morphism Distribution}
Across \compTotalPrograms\ programs: $\compMorphInclusion$ inclusions
($\compMorphInclusionPct$), $\compMorphRestriction$ restrictions
($\compMorphRestrictionPct$), $\compMorphTransport$ transports
($\compMorphTransportPct$).  Restriction dominance confirms that
most verification is shard-local.

\section{Lean 4 Proof Sketch}\label{sec:lean-proof}
% =====================================================================

\subsection{Federation Soundness}

\begin{theorem}[Federation Soundness]\label{thm:federation-soundness}
Let $\GlobalSite$ be a semantic site and $\{\ShardSite_i\}_{i=1}^k$
a valid decomposition with boundary $\partial$.  If:
\begin{enumerate}[noitemsep]
  \item Every shard passes verification: $v_i = \texttt{pass}$ for
        all $i$.
  \item Every treaty in $\partial$ is satisfied.
\end{enumerate}
Then monolithic verification of $\GlobalSite$ would also pass.
\end{theorem}

\begin{proof}[Proof (Lean~4)]
See \texttt{Paper53\_CodebaseOrchestration.lean}, theorem
\texttt{federation\_soundness}.  The proof proceeds by constructing a
global section from the shard-local sections.  For each object $U \in
\Ob(\GlobalSite)$, $U$ belongs to some $\ShardSite_i$, and the local
section $s_i(U)$ is provided by shard $i$'s verification.  For each
cross-shard morphism $f \in \partial$, the treaty ensures compatibility:
$\res_f(s_i) = s_j$ on the overlap.  By the sheaf gluing axiom, the
local sections assemble into a global section, proving that the
global site admits a verified judgment assignment.  Induction on the
number of shards handles the general case.
\end{proof}

\subsection{Decomposition Validity}

\begin{lemma}[Decomposition Completeness]\label{lem:decomp-complete}
Every morphism in $\Mor(\GlobalSite)$ is either internal to some
$\ShardSite_i$ or captured in the boundary $\partial$.
\end{lemma}

\begin{proof}
By the exhaustive partitioning of objects: each object belongs to
exactly one shard, and each morphism's source and target determine
its classification.  Formally: \texttt{Paper53\_CodebaseOrchestration.lean},
lemma \texttt{decomp\_completeness}.
\end{proof}

\subsection{Treaty Entailment}

\begin{lemma}[Treaty Consistency]\label{lem:treaty-consistent}
If treaty $(\phi_U, \phi_V)$ is satisfied for cross-shard morphism
$f$, then the guarantee $\phi_U$ (verified in $\ShardSite_i$) entails
the assumption $\phi_V$ (used in $\ShardSite_j$) under the encoding.
\end{lemma}

\section{Implementation}\label{sec:implementation}
% =====================================================================

\subsection{Architecture}
\begin{itemize}[noitemsep]
  \item \textbf{Module Detector}: Uses import-graph analysis via
        \InterfaceRoute\ ($\subInterfaceroutingSmallTime$) to
        identify module boundaries.
  \item \textbf{Graph Partitioner}: Balanced $k$-way partitioning
        minimizing boundary size.
  \item \textbf{Shard Workers}: Independent \JuGeo\ instances,
        each running the full pipeline on a shard.
  \item \textbf{Treaty Engine}: \HypercoverTreaty\ negotiates and
        checks boundary contracts ($\subHypercovertreatySmallTime$).
  \item \textbf{Coordinator}: Collects local verdicts, checks
        boundary consistency, emits global verdict.
\end{itemize}

\subsection{API Usage}
\begin{lstlisting}[style=jugeo-python]
from jugeo import Site

# Build global site from a multi-file project
global_site = Site.from_directory("my_project/")

# Decompose and verify in parallel
shards = global_site.change_of_site(
    strategy="parallel",
    workers=4
)

result = global_site.kernel_lifecycle(
    shards=shards,
    treaty_mode="hypercover"
)
print(f"Global: {result.verdict}")
print(f"Shards: {result.shard_count}")
print(f"Boundary: {result.boundary_size}")
\end{lstlisting}

\subsection{Performance Optimizations}
\begin{itemize}[noitemsep]
  \item \textbf{Incremental Decomposition}: When a single file
        changes, only its shard is re-verified; treaties are
        re-checked if boundary morphisms are affected.
  \item \textbf{Cached Treaties}: Boundary contracts are memoized
        across verification runs.
  \item \textbf{Adaptive Shard Size}: The partitioner adjusts $k$
        to balance parallelism with boundary overhead.
\end{itemize}

\section{Sharding Theory}\label{sec:sharding}
% =====================================================================

The decomposition strategy of §\ref{sec:decomposition} relies on an
intuitive notion of ``cutting at module boundaries.''  In this section
we develop the formal theory of \emph{code shards}: their algebraic
structure, morphisms between them, and the conditions under which
shard-level verification implies global correctness.

\subsection{Code Shards as Sub-Sites}

\begin{definition}[Code Shard]\label{def:shard}
Let $\GlobalSite = (\Ob(\GlobalSite), \Mor(\GlobalSite),
\Cov(\GlobalSite))$ be a semantic site.  A \emph{code shard}
$\ShardSite_i$ is a full sub-site of $\GlobalSite$, meaning:
\begin{enumerate}[noitemsep]
  \item $\Ob(\ShardSite_i) \subseteq \Ob(\GlobalSite)$.
  \item $\Mor(\ShardSite_i) = \{f \in \Mor(\GlobalSite) \mid
        \mathrm{src}(f), \mathrm{tgt}(f) \in \Ob(\ShardSite_i)\}$.
  \item $\Cov(\ShardSite_i) = \{C \in \Cov(\GlobalSite) \mid
        C \subseteq \Ob(\ShardSite_i)\}$.
\end{enumerate}
A code shard inherits the Grothendieck topology restricted to its
objects.  We write $\iota_i\colon \ShardSite_i \hookrightarrow
\GlobalSite$ for the inclusion functor.
\end{definition}

\begin{remark}\label{rem:shard-fullness}
The fullness condition (item 2) is essential: if $U, V \in
\Ob(\ShardSite_i)$ and there exists a morphism $f\colon U \to V$ in
$\GlobalSite$, then $f$ must also be in $\ShardSite_i$.  This ensures
that intra-shard dependency chains are faithfully represented.  The
only morphisms excluded from a shard are those crossing shard
boundaries, \ie morphisms $f\colon U \to V$ where $U$ and $V$ belong
to different shards.
\end{remark}

\subsection{Shard Morphisms and the Boundary Category}

\begin{definition}[Shard Morphism]\label{def:shard-morphism}
A \emph{shard morphism} $\sigma\colon \ShardSite_i \to \ShardSite_j$
is a pair $(\sigma_{\mathrm{obj}}, \sigma_{\mathrm{mor}})$ where:
\begin{itemize}[noitemsep]
  \item $\sigma_{\mathrm{obj}}\colon \Ob(\ShardSite_i) \to
        \Ob(\ShardSite_j)$ maps coordinates, and
  \item $\sigma_{\mathrm{mor}}\colon \partial_{ij} \to
        \Mor(\ShardSite_j)$ maps each boundary morphism $f \in
        \partial_{ij}$ to a morphism in the target shard,
\end{itemize}
subject to the compatibility condition: for every treaty
$(\phi_U, \phi_V)$ on $f \in \partial_{ij}$,
$\sigma_{\mathrm{mor}}(f)$ preserves the entailment $\phi_U \Rightarrow
\phi_V$.
\end{definition}

\begin{definition}[Boundary Category]\label{def:boundary-cat}
The \emph{boundary category} $\mathcal{B}(\GlobalSite, \mathcal{D})$
associated with a decomposition $\mathcal{D} = \{\ShardSite_i\}_{i=1}^k$
has:
\begin{itemize}[noitemsep]
  \item \textbf{Objects:} the shards $\ShardSite_1, \ldots,
        \ShardSite_k$.
  \item \textbf{Morphisms:} for each cross-shard morphism $f \in
        \partial$ with $\mathrm{src}(f) \in \Ob(\ShardSite_i)$ and
        $\mathrm{tgt}(f) \in \Ob(\ShardSite_j)$, a morphism
        $[f]\colon \ShardSite_i \to \ShardSite_j$.
\end{itemize}
Composition is inherited from $\GlobalSite$.  The boundary category
encodes the inter-module dependency structure at the shard level.
\end{definition}

\subsection{The Shard Covering Condition}

\begin{definition}[Shard Cover]\label{def:shard-cover}
A decomposition $\mathcal{D} = \{\ShardSite_i\}_{i=1}^k$ is a
\emph{shard cover} of $\GlobalSite$ if:
\begin{enumerate}[noitemsep]
  \item (Coverage) $\bigcup_{i=1}^k \Ob(\ShardSite_i) =
        \Ob(\GlobalSite)$.
  \item (Overlap control) For all $i \neq j$, $\Ob(\ShardSite_i)
        \cap \Ob(\ShardSite_j) = \emptyset$.
  \item (Boundary faithfulness) Every cross-shard morphism in
        $\Mor(\GlobalSite)$ appears in $\partial$.
\end{enumerate}
\end{definition}

Note that condition (2) requires \emph{disjoint} object sets.  This
is stronger than the general covering condition in sheaf theory (which
permits overlaps) but simplifies the federation protocol by eliminating
ambiguity about which shard owns a given coordinate.  When overlaps
are desired (\eg for shared utility modules), the
\HypercoverTreaty\ mechanism handles duplication through explicit
treaty contracts.

\subsection{Shard-Level Verification Theorem}

\begin{theorem}[Shard Verification Completeness]\label{thm:shard-completeness}
Let $\mathcal{D} = \{\ShardSite_i\}_{i=1}^k$ be a shard cover of
$\GlobalSite$ with boundary $\partial$, and let $\mathcal{T} =
\{(\phi_U^f, \phi_V^f)\}_{f \in \partial}$ be a set of treaties.
Suppose:
\begin{enumerate}[noitemsep]
  \item For each shard $\ShardSite_i$, local verification succeeds:
        there exists a global section $s_i \in
        \Gamma(\ShardSite_i, \mathcal{G})$ of the judgment sheaf
        $\mathcal{G}$.
  \item For each treaty $(\phi_U^f, \phi_V^f)$, the guarantee
        $\phi_U^f$ is verified in the source shard and entails
        $\phi_V^f$.
\end{enumerate}
Then there exists a global section $s \in
\Gamma(\GlobalSite, \mathcal{G})$ such that $s|_{\ShardSite_i} = s_i$
for all $i$.
\end{theorem}

\begin{proof}[Proof sketch]
We construct $s$ by defining $s(U) = s_i(U)$ for $U \in
\Ob(\ShardSite_i)$.  Well-definedness follows from condition (2)
of Definition~\ref{def:shard-cover} (disjointness).  It remains to
show that $s$ respects morphisms.  For internal morphisms $f \in
\Mor(\ShardSite_i)$, compatibility follows from $s_i$ being a section.
For cross-shard morphisms $f \in \partial$ with $\mathrm{src}(f) = U
\in \Ob(\ShardSite_i)$ and $\mathrm{tgt}(f) = V \in
\Ob(\ShardSite_j)$, the treaty ensures $\res_f(s_i(U)) =
s_j(V)$, giving compatibility on $f$.  Thus $s$ is a well-defined
global section.  The sheaf condition is inherited from the
individual shards and the treaty-mediated boundary conditions.
\end{proof}

\subsection{Shard Complexity Analysis}

\begin{proposition}[Shard Verification Cost]\label{prop:shard-cost}
Let $\GlobalSite$ have $n$ objects and $m$ morphisms, decomposed into
$k$ shards with boundary size $|\partial| = b$.  Then:
\begin{enumerate}[noitemsep]
  \item Each shard has at most $\lceil n/k \rceil$ objects and
        at most $m - b$ internal morphisms (shared across $k$
        shards).
  \item Shard verification cost is $O((n/k)^2)$ when verification
        is quadratic in site size, yielding a $k$-fold parallel
        speedup.
  \item Boundary consistency checking costs $O(b)$.
  \item Total federated cost: $O((n/k)^2 + b)$, compared to
        $O(n^2)$ monolithic.
\end{enumerate}
\end{proposition}

The paper-specific data confirms this scaling behavior: with
$\ppLIIImeanCoords$ mean coordinates and $\ppLIIImeanMorphisms$
mean morphisms per site, the scaling ratio from small to large
programs is $\ppLIIIscalingRatio$, consistent with sub-quadratic
growth under decomposition.

\section{Incremental Verification}\label{sec:incremental}
% =====================================================================

Production codebases change incrementally: a typical commit modifies
a handful of files in a single module.  Re-verifying the entire
codebase from scratch is wasteful when only one shard is affected.
This section formalizes incremental verification within the
sharding framework.

\subsection{Change Sets and Affected Shards}

\begin{definition}[Change Set]\label{def:change-set}
A \emph{change set} $\Delta$ is a set of modified coordinates
$\Delta \subseteq \Ob(\GlobalSite)$.  The \emph{affected shard set}
is $\mathcal{A}(\Delta) = \{i \mid \Ob(\ShardSite_i) \cap \Delta
\neq \emptyset\}$.
\end{definition}

\begin{definition}[Boundary Impact]\label{def:boundary-impact}
The \emph{boundary impact} of a change set $\Delta$ is:
\[
  \partial(\Delta) = \{f \in \partial \mid \mathrm{src}(f) \in \Delta
  \text{ or } \mathrm{tgt}(f) \in \Delta\}
\]
A change set has \emph{zero boundary impact} when
$\partial(\Delta) = \emptyset$, meaning the modification is
entirely shard-internal.
\end{definition}

\subsection{Incremental Correctness}

\begin{theorem}[Incremental Verification Soundness]
\label{thm:incremental}
Let $s$ be a valid global section of $\GlobalSite$ (\ie the
codebase is verified).  Let $\Delta$ be a change set producing
a modified site $\GlobalSite'$, and let $\mathcal{A}(\Delta)$
be the affected shard set.  Suppose:
\begin{enumerate}[noitemsep]
  \item For each $i \in \mathcal{A}(\Delta)$, re-verification
        of $\ShardSite_i'$ succeeds, producing a new local section
        $s_i'$.
  \item For each $f \in \partial(\Delta)$, the treaty is
        re-negotiated and satisfied.
  \item Unaffected shards retain their previous local sections:
        $s_i' = s_i$ for $i \notin \mathcal{A}(\Delta)$.
\end{enumerate}
Then the assembled section $s'$ is a valid global section of
$\GlobalSite'$.
\end{theorem}

\begin{proof}[Proof sketch]
The proof follows the same construction as
Theorem~\ref{thm:shard-completeness}, substituting $s_i'$ for $s_i$
on affected shards.  For unaffected shards, the sections are unchanged
and remain valid because $\ShardSite_i' = \ShardSite_i$.  For boundary
morphisms in $\partial \setminus \partial(\Delta)$, the treaties are
unchanged and remain satisfied.  For boundary morphisms in
$\partial(\Delta)$, the re-negotiated treaties ensure compatibility.
\end{proof}

\subsection{Incremental Update Algorithm}

\begin{algorithm}[H]
\caption{Incremental Verification Update}
\label{alg:incremental}
\begin{algorithmic}[1]
\STATE \textbf{Input:} Previous sections $\{s_i\}_{i=1}^k$, change
       set $\Delta$, boundary $\partial$
\STATE \textbf{Output:} Updated global verdict and sections
\STATE $\mathcal{A} \gets \{i \mid \Ob(\ShardSite_i) \cap \Delta
       \neq \emptyset\}$
\STATE $\partial_\Delta \gets \{f \in \partial \mid \mathrm{src}(f)
       \in \Delta \lor \mathrm{tgt}(f) \in \Delta\}$
\IF{$\mathcal{A} = \emptyset$}
  \RETURN previous verdict (no changes affect any shard)
\ENDIF
\STATE \textbf{parallel for} $i \in \mathcal{A}$ \textbf{do}
  \STATE \quad Rebuild $\ShardSite_i'$ from modified source
  \STATE \quad $s_i' \gets \texttt{verify\_shard}(\ShardSite_i')$
\STATE \textbf{end parallel}
\STATE Re-negotiate treaties for $\partial_\Delta$
\STATE Check boundary consistency for $\partial_\Delta$
\IF{all re-verified shards pass \textbf{and} all treaties satisfied}
  \STATE Update cached sections: $s_i \gets s_i'$ for $i \in
         \mathcal{A}$
  \RETURN $\GlobalVerdict = \texttt{PASS}$
\ELSE
  \RETURN $\GlobalVerdict = \texttt{FAIL}$ with affected diagnostics
\ENDIF
\end{algorithmic}
\end{algorithm}

\subsection{Incremental Savings Analysis}

\begin{proposition}[Incremental Speedup]\label{prop:incremental-speedup}
Let $\GlobalSite$ have $k$ shards and let $\Delta$ affect
$a = |\mathcal{A}(\Delta)|$ shards.  The incremental verification
cost is:
\[
  T_{\mathrm{incr}} = a \cdot T_{\mathrm{shard}} +
  |\partial(\Delta)| \cdot T_{\mathrm{treaty}}
\]
compared to full federation cost $T_{\mathrm{full}} = k \cdot
T_{\mathrm{shard}} + |\partial| \cdot T_{\mathrm{treaty}}$.  The
speedup is:
\[
  \frac{T_{\mathrm{full}}}{T_{\mathrm{incr}}} \approx \frac{k}{a}
\]
when treaty costs are small relative to shard verification.
\end{proposition}

In practice, most commits affect $a = 1$ shard, yielding a $k\times$
speedup.  The paper-specific data shows mean build time
$\ppLIIImeanBuildTime$ per site; with incremental verification,
a single-shard change requires only one such build rather than
rebuilding all shards.

\subsection{Python API for Incremental Verification}

\begin{lstlisting}[style=jugeo-python]
from jugeo import SiteBuilder, DescentEngine

class IncrementalVerifier:
    """Incremental verifier using cached shard sections."""
    
    def __init__(self, project_root: str, num_workers: int = 4):
        self.builder = SiteBuilder(root=project_root)
        self.engine = DescentEngine(strategy="parallel")
        self.cached_sections: dict[int, object] = {}
        self.cached_treaties: dict[tuple, object] = {}
        self.num_workers = num_workers
    
    def initial_verify(self) -> dict:
        """Full verification; caches all sections."""
        global_site = self.builder.build()
        shards = global_site.change_of_site(
            strategy="parallel",
            workers=self.num_workers
        )
        results = {}
        for i, shard in enumerate(shards):
            section = self.engine.verify(shard)
            self.cached_sections[i] = section
            results[i] = section.verdict
        # Cache treaties
        for f in global_site.boundary():
            treaty = global_site.hypercover_treaty(f)
            src, tgt = f.source_shard, f.target_shard
            self.cached_treaties[(src, tgt)] = treaty
        return results
    
    def incremental_verify(self, changed_files: list[str]) -> dict:
        """Re-verify only affected shards."""
        delta = self.builder.change_set(changed_files)
        affected = delta.affected_shards()
        
        if not affected:
            return {"verdict": "PASS", "reason": "no shards affected"}
        
        # Rebuild and re-verify affected shards
        results = {}
        for shard_id in affected:
            shard = self.builder.rebuild_shard(shard_id)
            section = self.engine.verify(shard)
            self.cached_sections[shard_id] = section
            results[shard_id] = section.verdict
        
        # Re-negotiate affected treaties
        boundary_impact = delta.boundary_impact()
        for f in boundary_impact:
            treaty = self.builder.renegotiate_treaty(f)
            src, tgt = f.source_shard, f.target_shard
            self.cached_treaties[(src, tgt)] = treaty
        
        all_pass = all(v == "PASS" for v in results.values())
        return {"verdict": "PASS" if all_pass else "FAIL",
                "affected_shards": len(affected),
                "renegotiated_treaties": len(boundary_impact)}
\end{lstlisting}

\section{Worked Example: Multi-Module Verification}\label{sec:worked-example}
% =====================================================================

We illustrate the complete federation workflow on a concrete example
drawn from the \ppLIIItotalPrograms-program benchmark suite.  The
example demonstrates site construction, decomposition, treaty
negotiation, parallel verification, and result assembly.

\subsection{Setup}

Consider a three-module project:
\begin{itemize}[noitemsep]
  \item \texttt{math\_utils.py} --- provides \texttt{clamp(x, lo, hi)}
        ensuring $\texttt{lo} \le \texttt{result} \le \texttt{hi}$.
  \item \texttt{validator.py} --- imports \texttt{clamp} and uses it
        in \texttt{validate\_score(score)} to ensure scores are in
        $[0, 100]$.
  \item \texttt{report.py} --- imports \texttt{validate\_score} and
        formats a score report, relying on the validated range.
\end{itemize}

\subsection{Step 1: Global Site Construction}

The \FormalCore\ method constructs the global site $\GlobalSite$
with the following structure:

\begin{center}
\small
\begin{tabular}{clll}
\toprule
\textbf{Index} & \textbf{Coordinate} & \textbf{Module} & \textbf{Type} \\
\midrule
$c_1$ & \texttt{clamp} & \texttt{math\_utils} & function \\
$c_2$ & \texttt{validate\_score} & \texttt{validator} & function \\
$c_3$ & \texttt{format\_report} & \texttt{report} & function \\
$c_4$ & \texttt{math\_utils} (module) & --- & module \\
$c_5$ & \texttt{validator} (module) & --- & module \\
$c_6$ & \texttt{report} (module) & --- & module \\
\bottomrule
\end{tabular}
\end{center}

The morphism set includes:
\begin{itemize}[noitemsep]
  \item $f_1\colon c_1 \to c_4$ (function-to-module inclusion),
  \item $f_2\colon c_2 \to c_5$ (function-to-module inclusion),
  \item $f_3\colon c_3 \to c_6$ (function-to-module inclusion),
  \item $f_4\colon c_4 \to c_5$ (import: \texttt{validator} imports
        \texttt{math\_utils}),
  \item $f_5\colon c_5 \to c_6$ (import: \texttt{report} imports
        \texttt{validator}).
\end{itemize}

This gives $|\Ob(\GlobalSite)| = 6$ coordinates and
$|\Mor(\GlobalSite)| = 5$ morphisms, consistent with the benchmark
mean of $\ppLIIImeanCoords$ coordinates and $\ppLIIImeanMorphisms$
morphisms per site (the example is slightly below the mean because it
has three small modules).

\subsection{Step 2: Site Decomposition}

We decompose into $k = 3$ shards along module boundaries:
\begin{align*}
  \ShardSite_1 &= \{c_1, c_4\}, \quad \Mor(\ShardSite_1) = \{f_1\} \\
  \ShardSite_2 &= \{c_2, c_5\}, \quad \Mor(\ShardSite_2) = \{f_2\} \\
  \ShardSite_3 &= \{c_3, c_6\}, \quad \Mor(\ShardSite_3) = \{f_3\}
\end{align*}

The boundary $\partial = \{f_4, f_5\}$ contains the two cross-module
import morphisms.  The boundary ratio is $\beta = 2/5 = 0.4$.

\subsection{Step 3: Treaty Negotiation}

For $f_4\colon c_4 \to c_5$ (validator imports math\_utils), the
\HypercoverTreaty\ mechanism produces:
\begin{itemize}[noitemsep]
  \item \textbf{Guarantee} ($\phi_{c_4}$): \texttt{clamp} satisfies
        $\texttt{lo} \le \texttt{result} \le \texttt{hi}$.
  \item \textbf{Assumption} ($\phi_{c_5}$): the imported \texttt{clamp}
        returns a value in $[\texttt{lo}, \texttt{hi}]$.
\end{itemize}

For $f_5\colon c_5 \to c_6$ (report imports validator):
\begin{itemize}[noitemsep]
  \item \textbf{Guarantee} ($\phi_{c_5}$): \texttt{validate\_score}
        returns a value in $[0, 100]$.
  \item \textbf{Assumption} ($\phi_{c_6}$): the imported score is
        in $[0, 100]$.
\end{itemize}

\subsection{Step 4: Parallel Shard Verification}

Each shard is verified independently.  Using the \JuGeo\ pipeline:
\begin{enumerate}[noitemsep]
  \item \textbf{Shard 1} ($\ShardSite_1$): Constructs judgment for
        \texttt{clamp}, verifies the range postcondition via
        $\Tsolver$.  Build time $\approx\ppLIIImeanBuildTime$.
  \item \textbf{Shard 2} ($\ShardSite_2$): Constructs judgment for
        \texttt{validate\_score}, verifies score-range property
        assuming the treaty on $f_4$.  Descent time
        $\approx\ppLIIImeanDescentTime$.
  \item \textbf{Shard 3} ($\ShardSite_3$): Constructs judgment for
        \texttt{format\_report}, verifies output format assuming the
        treaty on $f_5$.
\end{enumerate}

\subsection{Step 5: Boundary Consistency and Global Verdict}

The coordinator checks:
\begin{itemize}[noitemsep]
  \item Treaty on $f_4$: Shard 1 verified $\phi_{c_4}$, and
        $\phi_{c_4} \Rightarrow \phi_{c_5}$ holds (the guarantee
        entails the assumption).  \checkmark
  \item Treaty on $f_5$: Shard 2 verified $\phi_{c_5}$, and
        $\phi_{c_5} \Rightarrow \phi_{c_6}$ holds.  \checkmark
\end{itemize}

All shards pass and all treaties are satisfied, so
$\GlobalVerdict = \texttt{PASS}$.

\subsection{Incremental Update Example}

Suppose a developer modifies \texttt{math\_utils.py} to change the
\texttt{clamp} implementation.  The change set is $\Delta = \{c_1\}$,
affecting shard~1 only: $\mathcal{A}(\Delta) = \{1\}$.  The boundary
impact is $\partial(\Delta) = \{f_4\}$ (the import morphism from
\texttt{math\_utils} to \texttt{validator}).

Incremental verification:
\begin{enumerate}[noitemsep]
  \item Re-verify shard 1 with the new \texttt{clamp} implementation.
  \item Re-negotiate the treaty on $f_4$.
  \item Check that the new guarantee still entails the assumption.
  \item Shards 2 and 3 are not re-verified (cached sections reused).
\end{enumerate}

Cost: $1$ shard rebuild + $1$ treaty renegotiation, versus $3$ shard
rebuilds + $2$ treaty negotiations for full re-federation---a
$3\times$ saving for this example.

\section{Orchestration API}\label{sec:orchestration-api}
% =====================================================================

The federation and incremental verification machinery is exposed
through a high-level \Python\ API.  This section presents the
core orchestration classes.

\subsection{The Orchestrator Class}

\begin{lstlisting}[style=jugeo-python]
from jugeo import SiteBuilder, DescentEngine, Site

class Orchestrator:
    """Top-level orchestrator for federated verification."""
    
    def __init__(self, project_root: str, config: dict = None):
        self.root = project_root
        self.config = config or {}
        self.builder = SiteBuilder(root=project_root)
        self.engine = DescentEngine(
            strategy=self.config.get("descent_strategy", "cech")
        )
        self.shards: list[Site] = []
        self.boundary: list = []
        self.treaties: dict = {}
    
    def build_global_site(self) -> Site:
        """Construct the global semantic site."""
        return self.builder.build()
    
    def decompose(self, global_site: Site,
                  num_shards: int = None) -> list[Site]:
        """Decompose into shards via graph partitioning."""
        if num_shards is None:
            num_shards = global_site.suggested_shard_count()
        self.shards = global_site.change_of_site(
            strategy="partition",
            k=num_shards
        )
        self.boundary = global_site.boundary()
        return self.shards
    
    def negotiate_treaties(self) -> dict:
        """Negotiate interface treaties for boundary morphisms."""
        for f in self.boundary:
            treaty = self.builder.site.hypercover_treaty(f)
            key = (f.source_shard, f.target_shard, f.name)
            self.treaties[key] = treaty
        return self.treaties
    
    def verify_federated(self, workers: int = 4) -> dict:
        """Run parallel federated verification."""
        self.negotiate_treaties()
        verdicts = {}
        # Parallel shard verification
        for i, shard in enumerate(self.shards):
            result = self.engine.verify(shard)
            verdicts[i] = result
        # Boundary consistency
        boundary_ok = all(
            self.treaties[k].check_consistency()
            for k in self.treaties
        )
        all_pass = all(
            v.verdict == "PASS" for v in verdicts.values()
        )
        return {
            "global_verdict": "PASS" if (all_pass and boundary_ok)
                              else "FAIL",
            "shard_verdicts": verdicts,
            "treaties_satisfied": boundary_ok,
            "num_shards": len(self.shards),
            "boundary_size": len(self.boundary)
        }
\end{lstlisting}

\subsection{Federation Pipeline}

The complete federation pipeline combines site construction,
decomposition, treaty negotiation, and parallel verification:

\begin{lstlisting}[style=jugeo-python]
from jugeo.orchestration import Orchestrator

def run_federation_pipeline(project_root: str) -> None:
    """Execute the full federation pipeline on a project."""
    orch = Orchestrator(project_root, config={
        "descent_strategy": "cech",
        "treaty_mode": "hypercover",
        "cache_treaties": True,
    })
    
    # Phase 1: Build global site
    global_site = orch.build_global_site()
    print(f"Global site: {len(global_site.objects)} coords, "
          f"{len(global_site.morphisms)} morphisms")
    
    # Phase 2: Decompose into shards
    shards = orch.decompose(global_site)
    print(f"Decomposed into {len(shards)} shards, "
          f"boundary size {len(orch.boundary)}")
    
    # Phase 3: Federated verification
    result = orch.verify_federated(workers=4)
    print(f"Global verdict: {result['global_verdict']}")
    print(f"Treaties satisfied: {result['treaties_satisfied']}")
    
    # Phase 4: Report
    for i, verdict in result["shard_verdicts"].items():
        status = verdict.verdict
        trust = verdict.max_trust_tier
        print(f"  Shard {i}: {status} (trust: {trust})")

# Usage
run_federation_pipeline("my_project/")
\end{lstlisting}

\subsection{Federation Overhead Analysis}

Federation introduces overhead through two mechanisms: boundary
treaty negotiation and boundary consistency checking.  We analyze
these costs relative to the overall pipeline.

\begin{proposition}[Federation Overhead Bound]\label{prop:overhead}
Let $T_{\mathrm{mono}}$ be the monolithic verification time and
$T_{\mathrm{fed}}$ be the federated verification time with $k$
shards and boundary ratio $\beta$.  Then:
\[
  T_{\mathrm{fed}} \le \frac{T_{\mathrm{mono}}}{k} +
  \beta \cdot T_{\mathrm{mono}} \cdot \gamma
\]
where $\gamma$ is the per-morphism treaty cost as a fraction of
per-morphism verification cost.  Federation is beneficial when
$k > 1/(1 - \beta\gamma)$.
\end{proposition}

For the benchmark programs, $\beta \approx
\compMorphTransportPct$ of morphisms are cross-shard (transports),
and treaty negotiation takes $\subHypercovertreatySmallTime$,
confirming that the overhead is small relative to shard verification
cost.

\begin{definition}[Morphism Federation Roles]\label{def:morph-roles}
In a federated verification context, morphisms are classified by their
role:
\begin{enumerate}[noitemsep]
  \item \textbf{Restrictions} ($\compMorphRestrictionPct$ of total):
        Shard-internal morphisms that relate a coordinate to a
        sub-coordinate (\eg a function to one of its branches).
        These are fully handled within a single shard.
  \item \textbf{Inclusions} ($\compMorphInclusionPct$ of total):
        Shard-internal morphisms embedding a coordinate into a larger
        context (\eg a function into its module).  Also shard-local.
  \item \textbf{Transports} ($\compMorphTransportPct$ of total):
        Cross-shard morphisms requiring treaty mediation.  These
        form the boundary $\partial$ and determine federation
        overhead.
\end{enumerate}
\end{definition}

The dominance of restrictions and inclusions (together accounting for
over $90\%$ of morphisms in the comprehensive benchmark) explains
why federation overhead is low: the boundary $\partial$ contains only
the transport morphisms.

\subsection{Lessons Learned}

The case study reveals several practical insights:
\begin{enumerate}[noitemsep]
  \item \textbf{Module boundaries are natural shard boundaries.}
        The import-graph analysis via \InterfaceRoute\ reliably
        identifies decomposition points with small boundary impact.
  \item \textbf{Treaty inference is lightweight.}  For well-structured
        codebases, treaty negotiation via \HypercoverTreaty\ adds
        negligible overhead.
  \item \textbf{Incremental verification dominates in practice.}
        Most development workflows involve single-file edits,
        making the incremental protocol
        (Algorithm~\ref{alg:incremental}) the common case.
  \item \textbf{Pre-descent baselines are uninformative.}
        The per-paper pre-descent accuracy of $\ppLIIIoverallAccuracy$
        confirms that the descent engine is indispensable; orchestration
        without descent yields no verification value.
\end{enumerate}

\section{Related Work}\label{sec:related}
% =====================================================================

\paragraph{Modular Verification.}
Dafny~\cite{Leino2010} and VeriFast~\cite{Jacobs2011} verify modules
with explicit contracts.  We infer contracts automatically via treaty
negotiation.

\paragraph{Parallel Verification.}
Distributed Isabelle~\cite{Wenzel2014} parallelizes proof checking.
We parallelize the entire verification pipeline, including site
construction and judgment generation.

\paragraph{Compositional Analysis.}
Facebook Infer~\cite{Calcagno2015} uses bi-abduction for compositional
analysis.  Our approach differs by using sheaf-theoretic gluing rather
than frame inference.

\paragraph{Federated Learning.}
Federated learning~\cite{McMahan2017} distributes model training.
We adapt the federation paradigm to formal verification, with treaties
replacing gradient aggregation.

% =====================================================================
\section{Conclusion}\label{sec:conclusion}
% =====================================================================

Site decomposition and parallel federation enable \JuGeo\ to scale to
large, multi-module codebases without sacrificing soundness.  The
\ChangeOfSite\ functor provides principled transport of judgments
across shard boundaries, and \HypercoverTreaty\ automates interface
contract negotiation.  Our evaluation demonstrates \compOverallAccuracy\
accuracy with linear scaling in shard count.  Future work includes
incremental re-verification on code changes, adaptive shard balancing
under heterogeneous workloads, and extending federation to distributed
verification across machines.
