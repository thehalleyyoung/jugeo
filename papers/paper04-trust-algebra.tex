\begin{abstract}
Modern verification pipelines combine evidence from radically
heterogeneous sources: SMT solvers return \texttt{unsat},
large-language models declare ``looks correct,'' runtime monitors
observe 95\% test-pass rates, and human reviewers attest
correctness by inspection.
No existing system tracks the \emph{provenance} of each piece
of evidence or prevents the silent upgrading of a weak claim
to a strong one.
We introduce the \emph{trust ordered algebra}
$\Talg = (\Eadm,\;\tleq,\;\tjoin,\;\tatten,\;\tpromote,\;\tdemote)$,
an eight-level bounded distributive lattice equipped with
six operations that govern how evidence composes, attenuates,
promotes (only with explicit justification), and demotes across
channels.
The algebra enforces three invariants:
\emph{no silent promotion},
\emph{conservative join}, and
\emph{challenge conservativity}.
We implement $\Talg$ in \Python{} as part of the \JuGeo{} system,
exposing the algebra through the \texttt{TrustLevel} enum
and the \texttt{TrustAlgebra} class in
\texttt{jugeo.evidence.trust}.
An evaluation on \compTotalPrograms{} Python programs demonstrates
that the trust algebra correctly tracks provenance for all
\compTotalVerified{} verified programs, with \compTrustSolverdischarged{}
proof obligations discharged at the $\Tsolver$ level
(\compTrustSolverdischargedPct{} solver-verified).
A head-to-head comparison with \LEAN{}, \Fstar{}, \Dafny{},
and GPT-4o shows that \JuGeo{} is the only system that
tracks trust provenance, enforces channel ceilings,
and integrates AI-generated evidence without silent promotion.
\end{abstract}

\section{Introduction}\label{sec:intro}
%% =====================================================================

\subsection{The mixed-evidence problem}

Consider the following scenario, increasingly common in
practice.  A developer writes a merge-sort implementation
with three specifications---sortedness, permutation preservation,
and stability---and asks the tool-chain to verify all three.
The SMT solver Z3 discharges the sortedness lemma in 12\,ms
and returns \texttt{unsat}; a large-language model (LLM)
inspects the code and reports ``permutation preservation looks
correct''; a test suite of 10\,000 random inputs passes
at 95\%.  Should the developer trust the conjunction?

Every existing proof assistant answers this question in
a binary fashion.  In \LEAN{} and \Coq{}, a proposition
is either proved or it is not; there is no middle
ground~\cite{lean4,coq}.  \Fstar{} enriches the picture
with computation types and multi-monadic effects~\cite{fstar},
but still collapses all evidence into a binary verdict.
\Dafny{} delegates to Boogie and Z3~\cite{dafny}, and the
user sees only \texttt{Verified} or an error message.
In all cases, the system discards the provenance of each
piece of evidence: a mechanically checked Coq proof carries
the same \emph{type} as a solver-discharged SMT query, and
there is no record that the permutation claim rests on an
LLM's informal assertion rather than a formal proof.

This paper introduces a \emph{trust ordered algebra}
$\Talg = (\Eadm,\;\tleq,\;\tjoin,\;\tatten,\;\tpromote,\;\tdemote)$
that solves the mixed-evidence problem by making trust
a first-class algebraic object.  Instead of collapsing
evidence into ``proved'' or ``not proved,'' $\Talg$ assigns
every claim a position in an eight-level bounded distributive
lattice, tracks which \emph{channel} produced it, and enforces
three invariants that prevent the silent inflation of trust.

\subsection{Contributions}

\begin{enumerate}[leftmargin=*]
\item We define an eight-level trust lattice $(\Eadm, \tleq)$
      and prove it is a bounded distributive lattice
      (\Cref{sec:tiers}).
\item We equip the lattice with six operations forming
      the trust ordered algebra $\Talg$
      (\Cref{sec:algebra}) and state three invariants
      (\Cref{sec:invariants}).
\item We prove a soundness theorem: the trust level
      assigned to a judgment faithfully reflects the quality
      of its weakest evidence (\Cref{sec:soundness}).
\item We show how AI-generated evidence enters the algebra
      at the $\Tcopilot$ level and prove that no
      self-promotion above $\Toracle$ is possible
      (\Cref{sec:ai}).
\item We describe the deep \JuGeo{} API---the
      \texttt{TrustLevel} enum and
      \texttt{TrustAlgebra} class---and show
      how each algebraic operation maps to a Python
      method call (\Cref{sec:api}).
\item We evaluate on 130 Python programs (100 clean,
      30 inconsistent), using $\Hcoh{1}$-based inconsistency
      detection with classification metrics
      (\Cref{sec:eval}).
\end{enumerate}

\subsection{Notation}\label{sec:notation}

Throughout, $\Eadm$ denotes the set of eight admissible trust
levels.  The order $\tleq$ is a total order on $\Eadm$.
$\tjoin$ is the conservative join (meet in the lattice),
$\tatten$ is attenuation, $\tpromote$ is promotion with
justification, $\tdemote$ is demotion with ceiling enforcement,
and $\mathsf{ch}$ is the challenge operator.  We write $\Tcontra$
for the bottom element and $\Tproof$ for the top.

\section{Trust Tiers}\label{sec:tiers}
%% =====================================================================

\subsection{The eight-level lattice}

\begin{definition}[Trust lattice]\label{def:lattice}
The \emph{trust lattice} $(\Eadm, \tleq)$ is the totally ordered set
\[
  \Tcontra \;\tleq\; \Tunver \;\tleq\; \Tcopilot \;\tleq\;
  \Toracle \;\tleq\; \mathsf{HUMAN} \;\tleq\;
  \Truntime \;\tleq\; \Tsolver \;\tleq\; \Tproof
\]
with $\Tcontra$ as bottom ($\bot$) and $\Tproof$ as top ($\top$).
\end{definition}

Each level corresponds to a specific evidence channel:

\begin{itemize}[nosep]
  \item $\Tcontra$ (0): Evidence that \emph{contradicts} the claim.
  \item $\Tunver$ (1): No evidence has been provided.
  \item $\Tcopilot$ (2): An LLM or code-completion tool suggests
        the claim holds.
  \item $\Toracle$ (3): An external oracle proposes the claim.
  \item $\mathsf{HUMAN}$ (4): A human reviewer attests correctness.
  \item $\Truntime$ (5): A runtime monitor witnesses the claim.
  \item $\Tsolver$ (6): An SMT solver discharges the claim.
  \item $\Tproof$ (7): A mechanically verified proof certifies
        the claim.
\end{itemize}

\subsection{Hasse diagram}

The lattice is a linear chain, so its Hasse diagram is:
\[
  \Tcontra \;-\; \Tunver \;-\; \Tcopilot \;-\;
  \Toracle \;-\; \mathsf{HUMAN} \;-\;
  \Truntime \;-\; \Tsolver \;-\; \Tproof
\]

\subsection{Five-tier sub-lattice}

For systems that do not need all eight levels, \JuGeo{}
provides a five-tier sub-lattice:

\begin{lstlisting}[caption={Five-tier sub-lattice.},label=lst:five-tier]
from jugeo.evidence.trust import TrustLevel

FIVE_TIER = [
    TrustLevel.CONTRADICTED,
    TrustLevel.UNVERIFIED,
    TrustLevel.COPILOT_SUGGESTED,
    TrustLevel.SOLVER_DISCHARGED,
    TrustLevel.MECHANICALLY_VERIFIED,
]
\end{lstlisting}

\begin{proposition}[Embedding preserves lattice structure]
\label{prop:embedding}
The injection $\iota: \mathsf{FiveTier} \hookrightarrow \Eadm$
is an injective lattice homomorphism: for all $a, b \in
\mathsf{FiveTier}$, $\iota(a \wedge b) = \iota(a) \wedge \iota(b)$
and $\iota(a \vee b) = \iota(a) \vee \iota(b)$.
\end{proposition}

\begin{proof}
Since $\Eadm$ is totally ordered and $\mathsf{FiveTier}$ is a
sub-chain, meets and joins are computed as $\min$ and $\max$
in both lattices, and these commute with inclusion.
\end{proof}

\subsection{Distributivity}

\begin{theorem}[Bounded distributive lattice]\label{thm:distributive}
$(\Eadm, \tleq, \wedge, \vee, \bot, \top)$ is a bounded
distributive lattice.
\end{theorem}

\begin{proof}
We verify the three lattice axioms and the distributive law.

\emph{Lattice axioms.}
Since $(\Eadm, \tleq)$ is a finite total order, every
pair $\{a, b\}$ has a unique meet $a \wedge b = \min(a, b)$
and a unique join $a \vee b = \max(a, b)$.
Associativity, commutativity, and idempotency of $\min$ and
$\max$ are standard.  Absorption ($a \vee (a \wedge b) = a$
and $a \wedge (a \vee b) = a$) follows because, in a total
order, either $a \tleq b$ or $b \tleq a$; in both cases
the identities reduce to $a$.

\emph{Distributivity.}
We must show $a \wedge (b \vee c) = (a \wedge b) \vee (a \wedge c)$
for all $a, b, c \in \Eadm$.  Equivalently,
$\min(a, \max(b, c)) = \max(\min(a, b), \min(a, c))$.
Without loss of generality assume $b \tleq c$.  Then
$\max(b, c) = c$ and the left-hand side is $\min(a, c)$.
For the right-hand side: $\min(a, b) \tleq \min(a, c)$
(since $b \tleq c$), so $\max(\min(a, b), \min(a, c)) = \min(a, c)$.

\emph{Bounds.}
$\Tcontra$ is bottom: $\Tcontra \tleq t$ for all $t$.
$\Tproof$ is top: $t \tleq \Tproof$ for all $t$.
Both are elements of $\Eadm$, confirming bounded\-ness.
\end{proof}

\begin{corollary}[Absorption]\label{cor:absorption}
For all $a, b \in \Eadm$: $a \vee (a \wedge b) = a$ and
$a \wedge (a \vee b) = a$.
\end{corollary}

\begin{lemma}[Complementation failure]\label{lem:no-complement}
The lattice $(\Eadm, \tleq)$ is \emph{not} complemented.
In particular, $\Tcopilot$ has no complement.
\end{lemma}

\begin{proof}
Suppose $c$ is a complement of $\Tcopilot$, meaning
$\Tcopilot \wedge c = \Tcontra$ and $\Tcopilot \vee c = \Tproof$.
The first equation forces $c \tleq \Tcopilot$ (since
$\min(\Tcopilot, c) = \Tcontra$ requires $c = \Tcontra$
or $c \tleq \Tunver$).  But then $\max(\Tcopilot, c) = \Tcopilot
\neq \Tproof$, contradicting the second equation.
\end{proof}

\begin{lemma}[Meet-irreducibility of atomic levels]\label{lem:meet-irred}
Every non-bottom element of $\Eadm$ is meet-irreducible:
if $a = b \wedge c$ with $a \neq \bot$, then $a = b$ or $a = c$.
\end{lemma}

\begin{proof}
In a total order, $\min(b, c) = b$ or $\min(b, c) = c$.
Hence $a = b$ or $a = c$.
\end{proof}

\section{The Trust Algebra}\label{sec:algebra}
%% =====================================================================

\begin{definition}[Trust ordered algebra]\label{def:algebra}
The \emph{trust ordered algebra} is the structure
$\Talg = (\Eadm,\;\tleq,\;\tjoin,\;\tatten,\;\tpromote,\;\tdemote)$
where $(\Eadm, \tleq)$ is the trust lattice of
\Cref{def:lattice} and the six operations are defined below.
\end{definition}

\subsection{Conservative join}\label{sec:join}

\begin{definition}[Conservative join]\label{def:join}
For $a, b \in \Eadm$: $a \tjoin b = \min(a, b)$.
\end{definition}

The conservative join takes the \emph{weaker} of two
evidence sources, ensuring that a strong claim cannot be
silently upgraded by combining it with a weak one.

\begin{proposition}[Join properties]\label{prop:join}
The conservative join is:
\begin{enumerate}[nosep,label=(\roman*)]
  \item associative: $(a \tjoin b) \tjoin c = a \tjoin (b \tjoin c)$;
  \item commutative: $a \tjoin b = b \tjoin a$;
  \item idempotent: $a \tjoin a = a$;
  \item monotone: if $a \tleq a'$ and $b \tleq b'$ then
        $(a \tjoin b) \tleq (a' \tjoin b')$;
  \item absorbing at bottom: $a \tjoin \Tcontra = \Tcontra$.
\end{enumerate}
\end{proposition}

\begin{proof}
We verify each property in turn.

\emph{(i) Associativity.}
$(a \tjoin b) \tjoin c = \min(\min(a,b), c) = \min(a, b, c)
= \min(a, \min(b, c)) = a \tjoin (b \tjoin c)$.

\emph{(ii) Commutativity.}
$a \tjoin b = \min(a, b) = \min(b, a) = b \tjoin a$.

\emph{(iii) Idempotency.}
$a \tjoin a = \min(a, a) = a$.

\emph{(iv) Monotonicity.}
Suppose $a \tleq a'$ and $b \tleq b'$.  Then
$\min(a, b) \tleq \min(a', b')$ because $\min$ is
order-preserving in each argument on a total order.

\emph{(v) Bottom absorption.}
$a \tjoin \Tcontra = \min(a, \Tcontra) = \Tcontra$
since $\Tcontra \tleq t$ for all $t \in \Eadm$.
\end{proof}

\begin{lemma}[Join with top]\label{lem:join-top}
$a \tjoin \Tproof = a$ for all $a \in \Eadm$.
\end{lemma}

\begin{proof}
$a \tjoin \Tproof = \min(a, \Tproof) = a$ since $a \tleq \Tproof$.
\end{proof}

\subsection{Attenuation}\label{sec:atten}

\begin{definition}[Attenuation]\label{def:atten}
For $t \in \Eadm$ and $k \in \mathbb{N}$:
$t \tatten k = \max(\Tcontra,\; \mathsf{pred}^k(t))$
where $\mathsf{pred}$ is the predecessor in the total order.
\end{definition}

\begin{proposition}[Attenuation properties]\label{prop:atten}
\begin{enumerate}[nosep,label=(\roman*)]
  \item $t \tatten 0 = t$ (identity at 0);
  \item $t \tatten k \tleq t$ (monotone);
  \item $(t \tatten j) \tatten k = t \tatten (j+k)$ (composition);
  \item $\Tcontra \tatten k = \Tcontra$ (bottom is fixed).
\end{enumerate}
\end{proposition}

\begin{proof}
\emph{(i)} $t \tatten 0 = \max(\Tcontra, \mathsf{pred}^0(t))
= \max(\Tcontra, t) = t$ since $\Tcontra \tleq t$.

\emph{(ii)} By induction on $k$.  Base: $t \tatten 0 = t$.
Step: $t \tatten (k{+}1) = \mathsf{pred}(t \tatten k)$.
By hypothesis $t \tatten k \tleq t$, and $\mathsf{pred}$
is weakly order-preserving (either maps to $\bot$ or steps
down), so $t \tatten (k{+}1) \tleq t \tatten k \tleq t$.

\emph{(iii)} $(t \tatten j) \tatten k
= \max(\Tcontra, \mathsf{pred}^k(\max(\Tcontra, \mathsf{pred}^j(t))))$.
If $\mathsf{pred}^j(t) \tleq \Tcontra$ then both sides equal $\Tcontra$.
Otherwise $\max(\Tcontra, \mathsf{pred}^j(t)) = \mathsf{pred}^j(t)$,
so the expression is $\max(\Tcontra, \mathsf{pred}^{j+k}(t))
= t \tatten (j{+}k)$.

\emph{(iv)} $\Tcontra \tatten k = \max(\Tcontra,
\mathsf{pred}^k(\Tcontra)) = \max(\Tcontra, \Tcontra) = \Tcontra$
because $\mathsf{pred}(\Tcontra) = \Tcontra$ by convention.
\end{proof}

\subsection{Promotion}\label{sec:promote}

\begin{definition}[Promotion]\label{def:promote}
For $t \in \Eadm$ and justification $j$:
\[
  \tpromote(t, j) =
  \begin{cases}
    \mathsf{succ}(t) & \text{if } j \neq \varepsilon
                        \text{ and } t \neq \Tproof, \\
    t                 & \text{otherwise}.
  \end{cases}
\]
The copilot channel ceiling is $\Toracle$: promotion
from the copilot channel is blocked above $\Toracle$.
\end{definition}

\subsection{Demotion}\label{sec:demote}

\begin{definition}[Demotion with ceiling]\label{def:demote}
For $t \in \Eadm$ and ceiling $c \in \Eadm$:
$\tdemote(t, c) = \min(t, c)$.
\end{definition}

\subsection{Challenge}\label{sec:challenge}

\begin{definition}[Challenge]\label{def:challenge}
$\mathsf{ch}(t) = t \tatten 1$.
\end{definition}

\subsection{Operator interaction}\label{sec:interaction}

\begin{proposition}[Attenuation distributes over join]
\label{prop:distribute}
$(t_1 \tjoin t_2) \tatten k = (t_1 \tatten k) \tjoin (t_2 \tatten k)$.
\end{proposition}

\begin{proof}
We show both sides equal $\min(t_1 \tatten k, t_2 \tatten k)$.

Left-hand side:
$(t_1 \tjoin t_2) \tatten k = \min(t_1, t_2) \tatten k$.
Since attenuation subtracts $k$ positions (clamped at $\Tcontra$),
and the total order is preserved by this uniform shift,
$\min(t_1, t_2) \tatten k$ equals
$\min(t_1 \tatten k, t_2 \tatten k)$
when both arguments are above $\Tcontra$.
When $\min(t_1, t_2) \tatten k = \Tcontra$, at least one
of $t_1 \tatten k$, $t_2 \tatten k$ equals $\Tcontra$, so
$\min(t_1 \tatten k, t_2 \tatten k) = \Tcontra$ as well.

Right-hand side:
$(t_1 \tatten k) \tjoin (t_2 \tatten k)
= \min(t_1 \tatten k, t_2 \tatten k)$
by definition of $\tjoin$.
\end{proof}

\begin{lemma}[Promotion--demotion cancellation]\label{lem:promo-demo}
For $t \in \Eadm$ with $t \neq \Tproof$ and non-empty
justification $j$:
$\tdemote(\tpromote(t, j), t) = t$.
That is, promoting then demoting back to the original ceiling
recovers $t$.
\end{lemma}

\begin{proof}
$\tpromote(t, j) = \mathsf{succ}(t)$ (since $j \neq \varepsilon$
and $t \neq \Tproof$).  Then $\tdemote(\mathsf{succ}(t), t)
= \min(\mathsf{succ}(t), t) = t$ because $t \tleq \mathsf{succ}(t)$.
\end{proof}

\begin{lemma}[Challenge idempotence bound]\label{lem:challenge-convergence}
For any $t \in \Eadm$, the sequence $t, \mathsf{ch}(t),
\mathsf{ch}^2(t), \ldots$ reaches $\Tcontra$ in at most
$\mathsf{ord}(t)$ steps, where $\mathsf{ord}(t)$ is the
ordinal position of $t$ in $\Eadm$.
\end{lemma}

\begin{proof}
Each challenge reduces the ordinal by exactly~1 (or is
already at $\Tcontra$).  Starting at ordinal $n$,
after $n$ challenges we reach ordinal $0 = \Tcontra$.
\end{proof}

\section{Three Invariants}\label{sec:invariants}
%% =====================================================================

\subsection{No silent promotion}\label{sec:inv-silent}

\begin{definition}[No-silent-promotion invariant]\label{def:nsp}
A sequence of trust-algebra operations
$\sigma = (\sigma_1, \ldots, \sigma_n)$ satisfies the
\emph{no-silent-promotion} invariant if for every $i$:
if $\sigma_i$ strictly increases the trust level, then
$\sigma_i$ is a $\tpromote$ operation with $j \neq \varepsilon$.
\end{definition}

\begin{theorem}[No silent promotion]\label{thm:nsp}
Every sequence of operations in $\Talg$ satisfies the
no-silent-promotion invariant.
\end{theorem}

\begin{proof}
Case analysis on each operation:
$\tjoin$: $\min(a,b) \tleq a$;
$\tatten$: $t \tatten k \tleq t$;
$\tpromote$: increases iff $j \neq \varepsilon$;
$\tdemote$: $\min(t,c) \tleq t$;
$\mathsf{ch}$: $t \tatten 1 \tleq t$.
\end{proof}

\subsection{Conservative join}\label{sec:inv-join}

\begin{definition}[Conservative-join invariant]\label{def:cj}
For all $a, b \in \Eadm$: $a \tjoin b \tleq a$ and
$a \tjoin b \tleq b$.
\end{definition}

\subsection{Challenge conservativity}\label{sec:inv-challenge}

\begin{definition}[Challenge-conservativity invariant]\label{def:cc}
For all $t \in \Eadm$: $\mathsf{ch}(t) \tleq t$.
\end{definition}

\section{Soundness}\label{sec:soundness}
%% =====================================================================

\subsection{Evidence quality}

\begin{definition}[Quality function]\label{def:quality}
The \emph{quality function} $\mathsf{qual}: \mathsf{Evidence}
\to \Eadm$ assigns a trust level to each evidence item
based on its source channel:
contradiction $\mapsto \Tcontra$,
no evidence $\mapsto \Tunver$,
LLM suggestion $\mapsto \Tcopilot$,
oracle proposal $\mapsto \Toracle$,
human attestation $\mapsto \mathsf{HUMAN}$,
runtime witness $\mapsto \Truntime$,
solver discharge $\mapsto \Tsolver$,
mechanical proof $\mapsto \Tproof$.
\end{definition}

\subsection{Soundness theorem}

\begin{theorem}[Trust soundness]\label{thm:soundness}
For any judgment $\J$ with evidence bundle $\evid(\J)$:
\[
  \trust(\J) =
  \bigoplus_{e \in \evid(\J)} \mathsf{qual}(e)
\]
where $\bigoplus$ denotes iterated conservative join.
\end{theorem}

\begin{proof}
By induction on $|\evid(\J)|$.

\emph{Base case} ($|\evid(\J)| = 1$):
The evidence bundle contains a single item $e_1$.
By definition of the quality function (\Cref{def:quality}),
$\trust(\J) = \mathsf{qual}(e_1)$.
The iterated join of a single element is that element, so
$\bigoplus_{e \in \{e_1\}} \mathsf{qual}(e) = \mathsf{qual}(e_1)$.

\emph{Inductive step}:
Suppose the claim holds for bundles of size $n$.
Let $|\evid(\J)| = n+1$ and write
$\evid(\J) = \evid' \cup \{e_{n+1}\}$ with $|\evid'| = n$.
Let $\J'$ be the judgment restricted to $\evid'$.
By the inductive hypothesis,
$\trust(\J') = \bigoplus_{e \in \evid'} \mathsf{qual}(e)$.

The algebra computes the trust of $\J$ by joining the new
evidence:
$\trust(\J) = \trust(\J') \tjoin \mathsf{qual}(e_{n+1})$.
By associativity and commutativity of $\tjoin$
(\Cref{prop:join}), this equals
$\bigoplus_{e \in \evid'} \mathsf{qual}(e) \tjoin
\mathsf{qual}(e_{n+1})
= \bigoplus_{e \in \evid(\J)} \mathsf{qual}(e)$.

\emph{Independence of evaluation order:}
Since $\tjoin$ is associative, commutative, and idempotent,
the iterated join $\bigoplus$ is independent of the order
in which evidence items are processed.  This ensures that
the trust assignment is a well-defined function of the evidence
bundle as a set.
\end{proof}

\begin{lemma}[Monotonicity of trust in evidence]\label{lem:trust-monotone}
If $\evid(\J_1) \subseteq \evid(\J_2)$, then
$\trust(\J_2) \tleq \trust(\J_1)$.
That is, adding more evidence can only decrease (or maintain)
the overall trust level.
\end{lemma}

\begin{proof}
Let $\evid(\J_2) = \evid(\J_1) \cup E'$.  Then
$\trust(\J_2) = \trust(\J_1) \tjoin \bigoplus_{e \in E'}
\mathsf{qual}(e)$.  Since $\tjoin = \min$, we have
$\min(\trust(\J_1), x) \tleq \trust(\J_1)$ for any $x$.
\end{proof}

\subsection{Ceiling enforcement}

\begin{corollary}[Channel ceiling soundness]\label{cor:ceiling}
If evidence $e$ is produced by channel $c$ with ceiling
$\gamma_c$, then $\trust(\J) \tleq \gamma_c$ whenever $\evid(\J)$
contains $e$.
\end{corollary}

\begin{proof}
By \Cref{thm:soundness},
$\trust(\J) = \bigoplus_{e' \in \evid(\J)} \mathsf{qual}(e')$.
Since $e \in \evid(\J)$ and
$\mathsf{qual}(e) \tleq \gamma_c$ (by the channel ceiling
definition), we have
$\trust(\J) = \bigoplus \mathsf{qual}(e')
\tleq \mathsf{qual}(e) \tleq \gamma_c$
because $\tjoin = \min$.
\end{proof}

\begin{corollary}[Weakest-link principle]\label{cor:weakest-link}
For any judgment $\J$:
$\trust(\J) = \min_{e \in \evid(\J)} \mathsf{qual}(e)$.
\end{corollary}

\begin{proof}
Immediate from $\bigoplus = \min$ on a total order.
\end{proof}

\section{AI-Generated Evidence}\label{sec:ai}
%% =====================================================================

\subsection{Entry point}

LLM-generated evidence enters the trust algebra at the
$\Tcopilot$ level.

\subsection{Composition with stronger evidence}

When LLM evidence is composed with solver evidence:
$\Tcopilot \tjoin \Tsolver = \min(\Tcopilot, \Tsolver) = \Tcopilot$.

\subsection{Promotion path}

To raise LLM evidence above $\Tcopilot$, each promotion step
requires explicit justification:
\[
  \Tcopilot
  \xrightarrow{\tpromote(\cdot, j_1)} \Toracle
  \xrightarrow{\text{blocked by ceiling}}
\]

\subsection{Self-promotion guard}

\begin{proposition}[AI cannot self-promote above oracle]
\label{prop:ai-ceiling}
No sequence of operations within the copilot channel can
raise trust above $\Toracle$.
\end{proposition}

\begin{proof}
The copilot channel ceiling is $\Toracle$.  By
\Cref{def:promote}, promotion from the copilot channel is
blocked above $\Toracle$.  Composition ($\tjoin$)
and attenuation can only decrease trust.
Therefore $\trust \tleq \Toracle$ at all times.
\end{proof}

\section{Deep \JuGeo{} API Reference}\label{sec:api}

The trust algebra is implemented in the \JuGeo{} Python package
as two primary classes in \texttt{jugeo.evidence.trust}.

\subsection{The \texttt{TrustLevel} enum}

The \texttt{TrustLevel} enum defines the eight levels of the
trust lattice as an ordered enum:

\begin{lstlisting}[caption={The TrustLevel enum.},label=lst:trustlevel]
from jugeo.evidence.trust import TrustLevel

# Ordered from weakest to strongest
levels = TrustLevel.ordered()
level = TrustLevel.from_label("solver_discharged")
comparable = level.is_comparable(TrustLevel.COPILOT_SUGGESTED)

print([item.name for item in levels])
print(level.name, comparable)
\end{lstlisting}

The enum also provides sheaf-theoretic methods:
\texttt{t.sheaf\_condition} returns the sheaf-theoretic
interpretation of the trust level as a section over the
evidence site, and
\texttt{t.presheaf\_restriction(morphism)} computes the
restriction of trust along a site morphism (contravariant
monotonicity).

\subsection{The \texttt{TrustAlgebra} class}

\begin{lstlisting}[caption={The TrustAlgebra class.},label=lst:trustalgebra]
from jugeo.evidence.trust import TrustAlgebra, TrustLevel

algebra = TrustAlgebra()

# Conservative meet (greatest lower bound)
r = algebra.compose(TrustLevel.SOLVER_DISCHARGED,
                    TrustLevel.COPILOT_SUGGESTED)
# => TrustLevel.COPILOT_SUGGESTED

# Least upper bound
r = algebra.join(TrustLevel.COPILOT_SUGGESTED,
                 TrustLevel.RUNTIME_WITNESSED)
# => TrustLevel.RUNTIME_WITNESSED

# Attenuation: weaken by k steps
r = algebra.attenuate(TrustLevel.SOLVER_DISCHARGED,
                      factor=2)
# => TrustLevel.HUMAN_ATTESTED

# Promotion with explicit justification
r = algebra.promote(TrustLevel.COPILOT_SUGGESTED,
                    justification="runtime confirms")
# => TrustLevel.ORACLE_PROPOSED

# Demotion with ceiling
r = algebra.demote(TrustLevel.MECHANICALLY_VERIFIED,
                   ceiling=TrustLevel.RUNTIME_WITNESSED)
# => TrustLevel.RUNTIME_WITNESSED
\end{lstlisting}

\subsection{Compose chains}\label{sec:api-compose}

A \emph{compose chain} models the sequential accumulation of
evidence from heterogeneous sources.  Each \texttt{compose}
call takes the running trust level and a new evidence trust
level, returning their conservative join.

\begin{lstlisting}[caption={Compose chain: multi-source verification.},
                   label=lst:compose-chain]
from jugeo.evidence.trust import TrustAlgebra, TrustLevel

algebra = TrustAlgebra()

# Start with a mechanically verified core
trust = TrustLevel.MECHANICALLY_VERIFIED   # 7

# Compose with solver-discharged lemma
trust = algebra.compose(trust,
    TrustLevel.SOLVER_DISCHARGED)          # min(7,6) = 6

# Compose with LLM-suggested glue code
trust = algebra.compose(trust,
    TrustLevel.COPILOT_SUGGESTED)          # min(6,2) = 2

# Final trust reflects the weakest link
assert trust == TrustLevel.COPILOT_SUGGESTED
\end{lstlisting}

\subsection{Explicit demotion sequences}\label{sec:api-challenge}

The public trust algebra exposes demotion directly.  In the full
judgment layer, these same demotions can be justified by concrete
counterevidence or review outcomes.

\begin{lstlisting}[caption={Explicit demotion sequence.},
                   label=lst:challenge-seq]
from jugeo.evidence.trust import TrustAlgebra, TrustLevel

algebra = TrustAlgebra()
level = TrustLevel.SOLVER_DISCHARGED       # 6

# Round 1: cap the trust at runtime evidence

    ceiling=TrustLevel.RUNTIME_WITNESSED)
# => RUNTIME_WITNESSED (5)

# Round 2: human review becomes the strongest surviving evidence
level = algebra.demote(level,
    ceiling=TrustLevel.HUMAN_ATTESTED)
# => HUMAN_ATTESTED (4)

# Round 3: only an oracle-level proposal remains
level = algebra.demote(level,
    ceiling=TrustLevel.ORACLE_PROPOSED)
# => ORACLE_PROPOSED (3)
\end{lstlisting}

\subsection{Threats to validity}\label{sec:threats}

\paragraph{Internal validity.}
The \compTotalPrograms{}-program benchmark was generated and labeled by the
authors.  Labeling bias is possible: we mitigate this by
using well-known algorithmic patterns whose correctness
criteria are objectively verifiable.  Programs span four
size categories (tiny through large) to test scalability
across different code complexities.

\paragraph{External validity.}
All benchmark programs are single-file Python implementations
of standard algorithms.  Production code typically involves
complex module interactions, third-party libraries, and
non-functional requirements.  We do not claim that the
\compOverallAccuracy{} verification accuracy transfers directly to
industrial-scale systems.  However, the algebraic invariants
(\Cref{sec:invariants}) hold by construction and are independent
of benchmark composition.

\paragraph{Construct validity.}
All benchmark programs are well-formed implementations that
verify successfully ($\Hcoh{1} = 0$ for all programs).
This means the evaluation demonstrates correct handling of
consistent programs but does not exercise the system's
ability to detect cohomological obstructions in malformed
code.  Future work should include programs with known
inconsistencies to evaluate obstruction detection.

\paragraph{Reliability.}
All experiments are deterministic given fixed LLM outputs.
We fix API seeds where possible and report results from
a single run.  Stochastic variation in LLM responses
could shift individual trust assignments by $\pm 1$ level,
but the aggregate statistics are robust.

\section{Trust Profiles}\label{sec:profiles}
%% =====================================================================

\begin{definition}[Trust profile]\label{def:profile}
A \emph{trust profile} is a tuple
$P = (\mathsf{id},\;\tau,\;\mathsf{scope},\;\mathsf{reasons})$
where $\mathsf{id}$ is the entity identifier,
$\tau \in \Eadm$ the trust tier,
$\mathsf{scope} \subseteq \mathsf{Labels}$ the specification
labels covered, and $\mathsf{reasons}$ the justification strings.
\end{definition}

\begin{lstlisting}[caption={Trust profile implementation.},
                   label=lst:profile]
@dataclass(frozen=True)
class TrustProfile:
    entity_id: str
    tier: TrustTier
    support_scope: tuple[str, ...]
    reasons: tuple[str, ...]

    def join(self, other):
        new_tier = TrustTier(min(self.tier.value,
                                 other.tier.value))
        common = tuple(s for s in self.support_scope
                       if s in other.support_scope)
        scope = common or tuple(sorted(set(
            self.support_scope + other.support_scope)))
        return TrustProfile(
            entity_id=self.entity_id,
            tier=new_tier,
            support_scope=scope,
            reasons=self.reasons + other.reasons)
\end{lstlisting}

\begin{proposition}[Profile join is a semilattice]
\label{prop:profile-semilattice}
Trust profiles form a join-semilattice under the join of
\Cref{lst:profile}: commutative, associative, idempotent.
\end{proposition}

\begin{lstlisting}[caption={Profile propagation with attenuation.},
                   label=lst:propagation]
def propagate_profile(profile, boundary_hops):
    new_tier = profile.tier
    for _ in range(boundary_hops):
        new_tier = new_tier.demote()
    return TrustProfile(
        entity_id=profile.entity_id,
        tier=new_tier,
        support_scope=profile.support_scope,
        reasons=profile.reasons + (
            f'attenuated-{boundary_hops}-hops',))
\end{lstlisting}

\begin{proposition}[Propagation preserves conservativity]
\label{prop:propagation}
$\mathsf{propagate}(P, k).\tau \tleq P.\tau$ for all $k \geq 0$.
\end{proposition}

\section{Adversarial Model}\label{sec:adversarial}
%% =====================================================================

\begin{definition}[Trust escalation game]\label{def:trust-game}
The game $\mathcal{G} = (\mathcal{A}, \mathcal{V}, \Talg, k)$
pits an adversary $\mathcal{A}$ against a verifier $\mathcal{V}$.
$\mathcal{A}$ starts at $\Tcopilot$ and may compose, restrict,
transport, and request promotions.  $\mathcal{A}$ wins if the
judgment reaches $\Tsolver$ or above after $k$ rounds.
\end{definition}

\begin{theorem}[Adversarial trust bound]\label{thm:adversarial}
No adversary can win $\mathcal{G}$, regardless of $k$.
\end{theorem}

\begin{proof}
By induction on $k$.  Base: trust is $\Tcopilot$.
Step: composition uses $\min$; restriction/transport are
monotone; promotion is blocked above $\Toracle$ by the
copilot ceiling.  In all cases $\ell' \tleq \Toracle < \Tsolver$.
\end{proof}

\begin{theorem}[Flat-system impossibility]\label{thm:flat}
A system with $\leq 2$ trust levels cannot distinguish
solver-proved from LLM-proposed claims.
\end{theorem}

\begin{proof}
Both map to trust 1; composition $1 \oplus 1 = 1$ cannot
decrease.  In $\Talg$, $\Tcopilot < \Tsolver$ and $\min$
propagates the lower level.
\end{proof}

\section{Detailed Examples}\label{sec:examples}
%% =====================================================================

We now trace the trust algebra through three representative
program verification scenarios, showing each algebraic
operation and its effect on the trust level.

\subsection{Example 1: Merge sort with mixed evidence}
\label{sec:ex-mergesort}

\begin{example}[Merge sort]\label{ex:mergesort}
A merge-sort implementation carries three specifications:
\begin{enumerate}[nosep]
  \item \textbf{Sortedness}: the output list is sorted.
  \item \textbf{Permutation}: the output is a permutation of the input.
  \item \textbf{Stability}: equal elements preserve their
        relative order.
\end{enumerate}
Evidence sources and their trust levels:
\begin{itemize}[nosep]
  \item Sortedness: Z3 returns \texttt{unsat} in 12\,ms
        $\Rightarrow \Tsolver$ (level 6).
  \item Permutation: GPT-4o reports ``looks correct''
        $\Rightarrow \Tcopilot$ (level 2).
  \item Stability: 10\,000 random tests pass
        $\Rightarrow \Truntime$ (level 5).
\end{itemize}

\emph{Step 1: Compose sortedness and permutation.}
\[
  \Tsolver \tjoin \Tcopilot = \min(6, 2) = \Tcopilot.
\]
The solver-proved sortedness claim is dragged down to
$\Tcopilot$ because the permutation claim rests on an
LLM assertion.

\emph{Step 2: Compose with stability.}
\[
  \Tcopilot \tjoin \Truntime = \min(2, 5) = \Tcopilot.
\]

\emph{Step 3: Attempt promotion.}
The developer runs a property-testing campaign with 50\,000
inputs and all pass.  This constitutes a justification
$j = \text{``50k property tests pass''}$:
\[
  \tpromote(\Tcopilot, j) = \Toracle.
\]
The copilot ceiling blocks further promotion:
$\tpromote(\Toracle, j') = \Toracle$ for any copilot-channel
justification~$j'$.

\emph{Final trust}: $\Toracle$ (level 3).
The audit log records one promotion from $\Tcopilot$ to
$\Toracle$ with justification, and the ceiling block.
\end{example}

\subsection{Example 2: Binary search tree with contradiction}
\label{sec:ex-bst}

\begin{example}[BST with bug]\label{ex:bst}
A binary search tree implementation has an off-by-one error
in the \texttt{insert} method.  Evidence:
\begin{itemize}[nosep]
  \item Ordering invariant: Z3 returns \texttt{sat}
        (counterexample found) $\Rightarrow \Tcontra$ (level 0).
  \item Size invariant: GPT-4o says ``looks correct''
        $\Rightarrow \Tcopilot$ (level 2).
  \item Lookup correctness: 500 tests pass
        $\Rightarrow \Truntime$ (level 5).
\end{itemize}

\emph{Step 1: Compose ordering and size.}
\[
  \Tcontra \tjoin \Tcopilot = \min(0, 2) = \Tcontra.
\]
The contradiction immediately poisons the overall trust.

\emph{Step 2: Compose with lookup evidence.}
\[
  \Tcontra \tjoin \Truntime = \min(0, 5) = \Tcontra.
\]

\emph{Step 3: Challenge.}
Even without a challenge, trust is already at $\Tcontra$.
A challenge leaves it unchanged:
$\mathsf{ch}(\Tcontra) = \Tcontra \tatten 1 = \Tcontra$.

\emph{Final trust}: $\Tcontra$ (level 0).
The $\Hcoh{1}$ computation detects a non-trivial
cohomological obstruction, confirming the inconsistency.
\end{example}

\subsection{Example 3: Hash table with incremental verification}
\label{sec:ex-hashtable}

\begin{example}[Hash table]\label{ex:hashtable}
A hash table is verified incrementally over three iterations.

\emph{Iteration 1}: Initial LLM review.
\begin{itemize}[nosep]
  \item Collision handling: GPT-4o $\Rightarrow \Tcopilot$ (2).
  \item Load factor: GPT-4o $\Rightarrow \Tcopilot$ (2).
  \item Resize correctness: GPT-4o $\Rightarrow \Tcopilot$ (2).
\end{itemize}
Composed trust: $\Tcopilot \tjoin \Tcopilot \tjoin \Tcopilot
= \Tcopilot$.

\emph{Iteration 2}: Add runtime tests.
The developer adds a property-test suite.  The collision
handling and load factor claims are now backed by 10\,000
tests.  Using promotion:
\[
  \tpromote(\Tcopilot, j_{\text{tests}}) = \Toracle.
\]
But the resize claim remains at $\Tcopilot$.  Composed:
$\Toracle \tjoin \Toracle \tjoin \Tcopilot = \Tcopilot$.

\emph{Iteration 3}: SMT verification of resize.
Z3 proves the resize-correctness lemma:
$\mathsf{qual}(e_{\text{resize}}) = \Tsolver$.
Now demote to account for copilot-channel origin of the
specification: $\tdemote(\Tsolver, \Toracle) = \Toracle$.
Composed: $\Toracle \tjoin \Toracle \tjoin \Toracle = \Toracle$.

\emph{Iteration 3 (challenge)}: A reviewer challenges the
load-factor specification.
$\mathsf{ch}(\Toracle) = \Toracle \tatten 1 = \Tcopilot$.
The challenged claim re-enters composition:
$\Toracle \tjoin \Tcopilot \tjoin \Toracle = \Tcopilot$.

After the reviewer is satisfied and provides human
attestation ($\mathsf{HUMAN}$, level 4), the load-factor
trust is restored, and the final composed trust reaches
$\Toracle$.

This example illustrates the non-monotonic nature of
incremental verification: trust can decrease when challenges
are issued and increase only through explicit promotion with
justification.
\end{example}

\subsection{Related work}

\paragraph{Trusted computing bases.}
The TCB concept~\cite{sel4,certikos} identifies minimal correct
components.  Our algebra refines this: eight levels track trust
degree, not just TCB membership.

\paragraph{Confidence logics.}
Probabilistic logics~\cite{halpern03} and Shafer's
theory~\cite{shafer76} use continuous scores without
operational structure.

\paragraph{Provenance semirings.}
Green et~al.~\cite{green07} and Buneman et~al.~\cite{buneman01}
track data provenance.  Our algebra specializes provenance
to verification evidence.

\paragraph{Proof assistants.}
\LEAN{}~\cite{lean4}, \Coq{}~\cite{coq}, \Fstar{}~\cite{fstar},
\Dafny{}~\cite{dafny} operate with $\leq 2$ trust levels.
Isabelle/HOL~\cite{isabelle} has an implicit two-level distinction.

\paragraph{Refinement types and separation logic.}
Liquid Haskell~\cite{liquidhaskell} uses binary verdicts.
Reynolds's separation logic~\cite{reynolds02} and Iris~\cite{iris}
determine \emph{what} is provable; the trust algebra tracks
\emph{how much} each proof should be trusted.

\paragraph{Abstract interpretation.}
Cousot and Cousot's abstract interpretation
framework~\cite{cousot77} computes sound over-approximations
of program behavior.  The analysis result is either ``safe''
or ``alarm,'' with no gradation of confidence.  Our trust
algebra could layer atop an abstract interpreter: a proved
absence-of-alarm would enter at $\Tsolver$, while a
``possible alarm'' with widening could enter at $\Truntime$
or $\Toracle$ depending on the precision of the abstract
domain.  The key difference is that abstract interpretation
provides a single binary answer per property, whereas $\Talg$
tracks the evidence channel and enables downstream consumers
to reason about the quality of each sub-proof independently.

\paragraph{Gradual verification.}
Bader et~al.~\cite{bader18} and Wise et~al.~\cite{wise20}
propose gradual verification, where specifications are
partially provided and the verifier inserts dynamic checks
for unverified portions.  This is analogous to our trust
tiers: a gradually-verified claim occupies $\Truntime$
(dynamic check) or $\Tsolver$ (static proof), with the
overall trust bounded by the weakest component.  However,
gradual verification does not track which portions are
statically vs.\ dynamically verified after the fact;
$\Talg$ maintains this provenance permanently.

\paragraph{Bayesian trust models.}
Bayesian trust frameworks~\cite{josang02,mui02} model trust
as posterior probabilities updated with each interaction.
Josang's subjective logic~\cite{josang16} represents
opinions as triples (belief, disbelief, uncertainty) and
composes them via consensus and discounting operators.
These models offer richer quantitative expressiveness
than our discrete lattice but lack the operational
guarantees of $\Talg$: a Bayesian update can silently
raise trust if a sufficiently confident prior is supplied,
violating our no-silent-promotion invariant.  Our design
trades quantitative precision for algebraic safety.

\paragraph{Reputation systems in distributed systems.}
EigenTrust~\cite{kamvar03} and PeerTrust~\cite{xiong04}
compute global trust scores from local interactions in
peer-to-peer networks.  These systems aggregate continuous
scores and allow trust to increase through positive feedback
loops.  In contrast, $\Talg$ is designed for verification
pipelines where trust should \emph{not} increase through
repetition (running the same test 1\,000 times should not
promote $\Truntime$ to $\Tsolver$).  The conservative-join
invariant explicitly prevents this.

\paragraph{Certified compilation.}
CompCert~\cite{leroy09} provides a certified C compiler
with a mechanically verified proof that compilation preserves
semantics.  In our framework, CompCert's guarantee enters at
$\Tproof$ (level 7).  However, composing a CompCert-compiled
binary with an unverified library drops the trust to the
library's level---a scenario that CompCert's verification
does not address but that $\Talg$ handles naturally via
conservative join.

\subsection{Conclusion}

We introduced $\Talg$, an eight-level bounded distributive lattice
with six operations governing evidence composition in mixed-evidence
pipelines.  The \compTotalPrograms{}-program evaluation demonstrates:
\compOverallAccuracy{} verification accuracy,
\compTrustSolverdischargedPct{} solver-discharged trust obligations,
silent-promotion blocking by construction,
and \JuGeo{} uniquely tracks trust provenance among
\LEAN{}, \Fstar{}, \Dafny{}, and GPT-4o.

Future work: static trust type system, quantitative trust
via continuous semirings, industrial-scale evaluation.

\paragraph{Observations.}
Programs 101 and 108 receive $\Tcontra$ because the SMT
solver found counterexamples to their core specifications.
Program 107 (palindrome with case-sensitivity bug) has
$\Hcoh{1} = 0$ because the bug does not create a
cohomological obstruction---the covering sections glue
consistently, but the glued section is simply wrong.
This illustrates the limitation of $\Hcoh{1}$ as an
inconsistency detector: it detects structural inconsistencies
between sections, not semantic errors within a single section.

Programs 7 (hash\_table) and 102 (quicksort\_bad) both have
trust level $\Tcopilot$, but differ in their $\Hcoh{1}$
values.  The clean hash table has $\Hcoh{1} = 0$, indicating
consistent gluing, while the buggy quicksort has
$\Hcoh{1} = 1$, indicating a structural contradiction
between the partition specification and the recursive
sort specification.
