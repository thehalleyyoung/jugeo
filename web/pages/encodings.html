Encodings Module

The encodings layer translates JuGeo judgments into SMT formulas that Z3 and CVC5 can discharge. It comprises 18 sub-packages covering every Python type domain that JuGeo can reason about.

Overview

When JuGeo constructs a judgment such as \(\vdash_{\mathcal{S}} f : \sigma\), the judgment must ultimately be reduced to a set of SMT formulas that a solver can decide. The encodings layer performs this translation.

The translation is compositional: the encoding of a complex judgment is built from the encodings of its sub-judgments. Each sub-package handles a specific domain (scalars, collections, heap memory, etc.) and contributes a set of constraints and axioms to the solver context. The encoding also records which SMT-LIB fragment the resulting formula belongs to, enabling the solver router to select the most appropriate solving strategy.

Sub-packages

The 18 sub-packages of jugeo.encodings:

scalar_encodings
Refinement types for int, float, str, bool. Linear arithmetic and bitvector encodings.
deduction_rules
Inference rule schemas and their SMT encodings. Automated rule instantiation.
collection_heap_encodings
Lists, dicts, sets, tuples. Array theory and McCarthy's Select/Store axioms.
theorem_schemas
Named theorem patterns (commutativity, associativity, distributivity, etc.).
doctrine_completion
Logical doctrine (geometric, coherent, topos-theoretic) and completion procedures.
incremental_memory
Push/pop incremental solving state and learned clause caching.
tensor_quantifier_encodings
NumPy/PyTorch tensor shapes and dtypes as SMT quantifier formulas.
sequence_encodings
Finite sequences, strings, and byte arrays with length and content constraints.
text_encodings
String and regex refinement types using Z3's string theory extension.
state_space_encodings
Stateful computation encoding — mutable state as functional update sequences.
partiality_models
Partial functions, optional values, and non-termination encodings.
countermodel_extraction
Extract and format SAT models as concrete Python counterexamples.
semantic_caching
Cache solved judgment encodings keyed by semantic fingerprint.
certificate_chains
Chain multiple solver results into a single auditable certificate.
repair_semantics
Encoding of repair constraints for the sheaf repair pipeline.
replay_gluing
Replay solver evidence for gluing checks without re-invoking the solver.
generated_contracts
Auto-generated pre/post contracts from type annotations and docstrings.
semantic_control
Control flow encoding: loops, branches, exceptions as transition relations.

Scalar Encodings

Scalar encodings translate Python's numeric types into SMT sorts with refinement constraints. The encoding of an int with a refinement predicate \(P\) is an SMT integer \(x\) plus a constraint \(P(x)\):

\[\text{encode}(\{x : \mathbb{Z} \mid P(x)\}) = (\texttt{Int } x,\; P(x))\]

For floating-point values JuGeo defaults to SMT reals (a sound over-approximation). Bitvector encodings are available for functions that explicitly require bit-exact semantics (e.g., cryptographic code).

python 
from jugeo.encodings import scalar_encodings as sc

helpers = sorted(name for name in dir(sc) if name.startswith("encode_"))
print(helpers[:5])
print(sc.EncodingResult.__name__)

Deduction Rules

The deduction rules sub-package encodes inference rules as SMT formulas and provides automated rule instantiation. Each rule is a schema with premises and a conclusion, expressed as an SMT implication:

\[\frac{\Gamma \vdash A \quad \Gamma \vdash B}{\Gamma \vdash A \wedge B} \quad (\wedge\text{-intro})\]

The encodings layer uses automated rule instantiation to generate the SMT constraints corresponding to each applicable inference rule, without requiring the developer to reason about the rules manually.

python 
from jugeo.encodings import deduction_rules as dr

rule_types = sorted(name for name in dir(dr) if name.endswith("Rule"))
print(rule_types[:6])
print(type(dr.get_manifest()).__name__)

Heap & Collections

Python's mutable data structures (lists, dicts, sets) require a heap model. JuGeo uses an abstract heap encoding based on McCarthy's array theory, augmented with aliasing constraints derived from the python_runtime layer's alias analysis. The heap encoding soundly approximates both read and write operations, generating the Select/Store axioms automatically.

python 
from jugeo.encodings import collection_heap_encodings as che

exports = sorted(name for name in dir(che) if "encoder" in name or "obligation" in name)
print(exports[:6])

Tensor Quantifier Encodings

NumPy arrays and PyTorch tensors are encoded as SMT multi-dimensional arrays with shape constraints. The tensor encoding uses quantifiers to express element-wise properties without enumerating all indices:

\[\forall i_1, \ldots, i_n.\; 0 \le i_k < d_k \;\Rightarrow\; P(T[i_1, \ldots, i_n])\]

This keeps the VC size constant regardless of tensor dimensions. Shape constraints are encoded as linear arithmetic equalities, enabling the solver to rule out shape mismatches at compile time (before any runtime data flows).

python 
from jugeo.encodings import tensor_quantifier_encodings as tqe

print(sorted(name for name in dir(tqe) if "matrix" in name or "tensor" in name)[:10])
print(tqe.transpose_matrix([[1, 2], [3, 4]]))

Doctrine Completion

JuGeo supports multiple logical doctrines — the logical fragment in which judgments are expressed. The doctrine completion sub-package implements automatic completion of a partial judgment set to a full doctrine:

  • Geometric doctrine — existential and finite-disjunction-free fragment. Decidable, fast.
  • Coherent doctrine — extends geometric with bounded universal quantification.
  • Topos-theoretic doctrine — full higher-order logic over a Grothendieck topos.
python 
from jugeo.encodings import doctrine_completion as dc

statements, evidence_map = dc.create_sample_doctrine(n_statements=3)
summary = dc.get_coverage_summary(statements, evidence_map)
report = dc.check_doctrine_completeness(statements, evidence_map)
print(summary["overall_score"])
print(report.status)
print(report.summary)

Encoding Pipeline

The encoding pipeline takes a fully constructed judgment and produces a Z3 solver context ready for discharge. The pipeline is orchestrated by the public jugeo.encodings package, which selects the appropriate sub-package for each component of the judgment and assembles the results into a single SolverContext.

python 
from jugeo.encodings import encode_judgment, encoding_registry
from jugeo.geometry.site import Coordinate, CoordinateKind

class DemoJudgment:
    judgment_id = "demo"
    coordinate = Coordinate(("pricing", "total"), CoordinateKind.FUNCTION)

registry = encoding_registry()
print(sorted(registry))
encoded = encode_judgment(DemoJudgment())
print(encoded["family"])
print(encoded["coordinate_kind"])
print(encoded.get("note"))
💡
Custom encodings. You can register a custom encoding for your own types. Implement jugeo.encodings.EncodingProtocol and call dispatch.register(MyType, MyEncoding) before running verification. The encoding will be automatically selected when the dispatch encounters a value of your type.
