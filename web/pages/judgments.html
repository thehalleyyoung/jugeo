Judgments

A judgment is the fundamental unit of meaning in JuGeo — an 8-tuple that formally records what is being claimed, about what coordinate, supported by what evidence, under what obligations and trust constraints.

The 8-tuple Structure

Every claim that JuGeo reasons about is reified as a judgment. Rather than a simple proposition, a judgment carries rich metadata about where the claim lives, who vouches for it, what it would take to discharge it, and how much it costs to maintain. This makes judgments first-class objects that can be stored, compared, composed, and transported across the semantic site.

Definition 1.1 — Judgment
$$J \;=\; (c,\; \varphi,\; A,\; E,\; O,\; B,\; T,\; \Pi)$$

Each position in the tuple has a distinct role. The table below gives a concise reference; each component is explained in depth in the sections that follow.

Symbol Field Description
ccoordinateThe semantic coordinate (module, function, class, …) this judgment is about
φformulaThe logical formula being asserted, written in the judgment logic
AantecedentsThe set of prior judgments on which this one depends
EevidenceThe evidence bundle — one or more evidence items from distinct channels
OobligationsProof obligations remaining to be discharged before the judgment is complete
BbudgetResource budget: solver time, token budget, oracle calls, cost ceiling
TtrustTrust level drawn from the 6-level lattice (NONE < RUNTIME < … < FORMAL)
ΠprovenanceAudit trail: timestamp, agent id, channel sequence, version hash
💡

Why 8 fields? Earlier versions of JuGeo used a 5-tuple (coordinate, formula, evidence, trust, provenance). The three additional fields — antecedents, obligations, and budget — emerged from the need to support compositional reasoning (A), incremental proof (O), and resource- aware solver routing (B). See Paper 02 for the algebraic motivation.

Components Explained

Coordinate — c

A coordinate identifies a location in the semantic site. Coordinates are objects of the underlying category \(\mathcal{C}\) and carry a kind tag drawn from the enumeration {MODULE, PACKAGE, FUNCTION, CLASS, METHOD, VARIABLE, TYPE, IMPORT}. A coordinate also carries its qualified name, source span, and an optional type signature extracted from annotations.

The coordinate \(c\) determines which stalk of the sheaf the judgment lives in. Formally, if \(\mathcal{F}\) is the judgment sheaf on the site \((\mathcal{C}, J)\), then \(J \in \mathcal{F}(U)\) for some open \(U\) containing \(c\). Restriction maps move judgments between stalks as the coordinate changes.

Formula — φ

The formula is the logical content of the judgment. JuGeo supports a stratified formula language:

  • Ground atoms — type assertions, value equalities, membership tests
  • Linear arithmetic — inequalities over integer and real-valued expressions (dispatched to QF_LIA / QF_LRA SMT fragments)
  • Effect predicates — Terminates(f), Deterministic(f), IsPure(f), HasEffect(f, e)
  • Relational formulas — \(\varphi_1 \Rightarrow \varphi_2\), pre/post pairs, invariants
  • Higher-order — quantification over type variables (requires FORMAL trust channel)

Antecedents — A

The antecedent set \(A = \{J_1, \ldots, J_k\}\) records the judgments that were used as hypotheses when deriving \(J\). This creates a proof DAG rather than a flat collection. Trust propagates through antecedents via the meet operation of the trust lattice: the trust of a composed judgment cannot exceed the minimum trust of its antecedents.

Trust monotonicity through antecedents
$$T(J) \;\leq\; \bigwedge_{J_i \in A} T(J_i)$$

Evidence — E

Evidence is an EvidenceBundle — a list of EvidenceItem objects, each tagged with its originating channel (SOLVER, RUNTIME, ORACLE, FORMAL_PROOF, COMPOSED, COPILOT). Multiple items in the bundle combine via the evidence join operation. See the Evidence Channels page for full details.

Obligations — O

Obligations are open proof goals that must be discharged before the judgment can be considered complete. A judgment with non-empty obligations is partial: it may be used as a hypothesis, but emits a warning when queried for its trust level. Obligations are discharged by running additional evidence-gathering passes or by providing a FORMAL_PROOF item.

Budget — B

The budget record limits resource consumption during evidence gathering:

  • solver_ms — wall-clock milliseconds allocated to SMT calls
  • token_budget — LLM token budget for ORACLE / COPILOT channels
  • oracle_calls — maximum number of external oracle invocations
  • cost_usd — monetary ceiling (summed across all channels)

Trust — T

Trust is a value in the 6-level lattice \(\mathbf{T}\): $$\text{NONE} \;\lt\; \text{RUNTIME} \;\lt\; \text{ORACLE} \;\lt\; \text{SOLVER} \;\lt\; \text{COMPOSED} \;\lt\; \text{FORMAL}$$ The lattice is equipped with meet (\(\wedge\)) and join (\(\vee\)) so that trust levels can be composed. The join models "best available evidence" while the meet models "weakest link in a chain."

Provenance — Π

Provenance is an immutable audit record containing: the UTC timestamp of judgment creation, the agent identifier, the ordered sequence of evidence channels consulted, the version hash of the JuGeo kernel, and a content hash of the formula. Provenance records are append-only and form a tamper-evident chain when judgments are composed.

Python API

The most stable public entry point for judgment-level work is jugeo.easy, which runs the real CLI and returns structured results. For lower-level introspection, the public geometry and trust modules expose the coordinate, morphism, and trust primitives that these judgments sit on top of.

python 
from jugeo.easy import prove

result = prove(
    """
def sum_positive(xs: list[int]) -> int:
    return sum(x for x in xs if x > 0)
"""
)

print(result.verdict)      # verified / obstructed
print(result.trust)        # e.g. SOLVER_DISCHARGED
print(result.H1)           # 0 means descent succeeded
print(result.propositions) # (discharged, total)

The public API follows the same rule as the internal judgment algebra: trust is conservative. When two sources of evidence are combined, the result takes the meet of their trust levels.

python 
from jugeo.evidence.trust import TrustAlgebra, TrustLevel

algebra = TrustAlgebra()

solver_checked = TrustLevel.SOLVER_DISCHARGED
copilot_hint = TrustLevel.COPILOT_SUGGESTED

combined = algebra.meet(solver_checked, copilot_hint)
print(combined)  # TrustLevel.COPILOT_SUGGESTED

promoted = algebra.promote(TrustLevel.UNVERIFIED, "confirmed by an explicit review step")
print(promoted)
🔎

Immutability. The public geometry and trust types are immutable dataclasses and enums. Operations like coordinate restriction, morphism reversal, and trust composition return new values rather than mutating existing ones.

Composition

Two judgments \(J_1\) and \(J_2\) about the same coordinate can be composed when \(\varphi_1\) and \(\varphi_2\) are logically compatible. The composed judgment \(J_1 \otimes J_2\) has:

Judgment composition
$$J_1 \otimes J_2 \;=\; (c,\; \varphi_1 \wedge \varphi_2,\; A_1 \cup A_2,\; E_1 \sqcup E_2,\; O_1 \cup O_2,\; B_1 \oplus B_2,\; T_1 \wedge T_2,\; \Pi_1 \cdot \Pi_2)$$

Where \(\sqcup\) is the evidence join (union of items, deduplicating by channel), \(\oplus\) is budget addition (sums each numeric field), and \(\cdot\) is provenance concatenation (appending audit records).

python 
from jugeo.easy import prove
from jugeo.evidence.trust import TrustAlgebra, TrustLevel

proof = prove(
    """
def add(x: int, y: int) -> int:
    return x + y
"""
)

algebra = TrustAlgebra()
judgment_trust = TrustLevel.from_label(proof.trust)
combined_trust = algebra.meet(judgment_trust, TrustLevel.HUMAN_ATTESTED)

print(judgment_trust)
print(combined_trust)

Restriction and Transport

The sheaf structure on judgments means they can be restricted to sub-coordinates and transported along morphisms in the site.

restrict(J, c') where c' ≤ c

Restriction

Restricts a judgment at coordinate c to a sub-coordinate c'. The formula is weakened to apply only to the smaller scope. Trust is preserved; provenance records the restriction morphism.

transport(J, f) where f : c → c'

Transport

Transports a judgment along a morphism f (e.g. rename, inline, specialize). The formula is rewritten using the pullback of f. Trust may decrease if the morphism is not an isomorphism.

glue(J_1, ..., J_n, cover)

Gluing

Given local judgments on a covering family, constructs a global judgment on the covered object. Requires the descent condition to hold. See the Descent page for details.

python 
from jugeo.geometry.site import Coordinate, CoordinateKind, Morphism, MorphismKind

module = Coordinate(("mymod",), CoordinateKind.MODULE)
fn = Coordinate(("mymod", "sum_positive"), CoordinateKind.FUNCTION)
renamed = Coordinate(("mymod", "add_positives"), CoordinateKind.FUNCTION)

print(module.is_prefix_of(fn))  # True: function is a restriction of the module

rename = Morphism(
    source=fn,
    target=renamed,
    kind=MorphismKind.TRANSPORT,
    label="rename",
)

print(rename.is_invertible())        # True
print(rename.reversed().source.name) # mymod.add_positives

The Trust Lattice

The trust component \(T\) is a value in the bounded lattice \((\mathbf{T}, \leq, \wedge, \vee, \bot, \top)\) where \(\bot = \text{NONE}\) and \(\top = \text{FORMAL}\). The ordering reflects the soundness guarantee provided by each evidence channel:

  • NONE — no evidence gathered yet; the formula is unsubstantiated
  • RUNTIME — property was observed to hold on sampled inputs (unsound in general)
  • ORACLE — LLM or external oracle assessed the property (probabilistic)
  • SOLVER — SMT solver returned SAT/UNSAT with a certificate (sound within the fragment)
  • COMPOSED — multiple channels agreed; trust is their meet
  • FORMAL — Lean 4 / Coq proof term verified by a kernel (unconditionally sound)
⚠

Trust is not probability. A RUNTIME judgment with 10,000 passing tests does not get promoted to SOLVER trust. The lattice reflects the kind of evidence, not the quantity. Use compose() with judgments from different channels to accumulate evidence while respecting the lattice semantics.
