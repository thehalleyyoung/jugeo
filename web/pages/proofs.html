Introduction

JuGeo has 93 Lean 4 proof files formalizing the theoretical foundations of the Judgment Geometry series. These provide mechanized verification of the core theorems: site axioms, descent and gluing, trust-algebra laws, obstruction classification, effect encodings, and dozens of application-domain results spanning program analysis, LLM orchestration, and multi-agent copilot architecture.

Each file corresponds directly to a topic in the mathematical framework. The proofs are self-contained or depend only on Common.lean and the Lean 4 / Mathlib4 standard library. All proofs are fully closed — the Lean elaborator accepts them without any sorry, native_decide shortcuts that hide proof obligations, or admitted axioms beyond those in Mathlib.

The proof library serves two purposes: it provides a machine-checkable certificate of the theoretical claims made across the mathematical framework, and it serves as executable specification that the Python runtime implementation can be tested against.

Lean Infrastructure

Two infrastructure files underpin the entire proof library. All proof files live under proofs/lean/ alongside these root modules.

⚙

Common.lean

Defines shared structures used across the library: TrustLevel, coordinate types, morphism kinds, covering families, and the abstract CategoryStr structure. Imported by most paper proof files to avoid duplication of core vocabulary.

📚

JudgmentGeometry.lean

The root import module. Re-exports all paper namespaces under the JudgmentGeometry umbrella so that downstream users can obtain the full library with a single import JudgmentGeometry statement. Also the entry point for lake build.

📄

lakefile.lean

Lake build configuration. Declares the JudgmentGeometry library target, sets the Lean 4 toolchain version, and lists Mathlib4 as a dependency. Run lake build from proofs/lean/ to type-check all 93 files end-to-end.

Key Theorems

Five results stand out as the load-bearing theorems of the Judgment Geometry framework. Each is fully proved in the Lean library with no axioms beyond Mathlib.

Site Axioms

site_axioms_satisfied — Paper01_SemanticSites.lean

The program-coordinate covering families satisfy all three Grothendieck topology axioms: the identity sieve covers every object, covering sieves are stable under pullback, and if a sieve \(S\) covers \(U\) and for each \(f \in S\) a sieve \(T_f\) covers the source of \(f\), then \(T = \bigcup_f f^*T_f\) covers \(U\). Formally: \[ \text{satisfies\_grothendieck\_axioms}(\mathcal{T}) \]

Descent Theorem

descent_theorem — Paper03_DescentObstructions.lean

A compatible family of local sections \(\sigma\) over a covering family \(U\) glues to a unique global section. That is, for every compatible family there exists a unique \(s\) such that the restriction of \(s\) to each member of the cover equals the corresponding local section: \[ \forall\, U,\, \sigma \in \text{CompatibleFamily}(U),\;\; \exists!\, s \in \Gamma(U),\;\; \forall\, i,\;\; s|_{U_i} = \sigma_i \]

Obstruction Theorem

obstruction_classification — Paper03_DescentObstructions.lean

When the sections in a family fail the compatibility condition on an overlap, the obstruction to gluing is detected as a non-trivial class in the first Cech cohomology group of the covering. Symbolically: \[ \neg\text{compatible}(\sigma) \;\Longrightarrow\; \Delta(\sigma) \in H^1(U, \mathcal{F}),\;\; \Delta \neq 0 \]

Trust Algebra Laws

trust_no_silent_promotion / trust_conservative_join — Paper04_TrustAlgebra.lean

The trust level of a judgment can only increase through an explicit, auditable promotion action — no evidence channel or transport step can silently raise trust. The join operation on trust levels is conservative: the trust of a combined judgment is at most the minimum of the contributing levels: \[ t_1 \sqcup t_2 = \min(t_1, t_2) \]

Cut Admissibility

cut_admissibility — Paper34_DeductionRules.lean

Every proof in the JuGeo deduction rule engine that uses the cut rule can be transformed into an equivalent cut-free proof. This guarantees subformula property and makes the deduction system analytically tractable: \[ \Gamma \vdash A \;\;\text{with cut} \;\;\Longrightarrow\;\; \Gamma \vdash A \;\;\text{cut-free} \]

  sheaf_condition U σ

-- Incompatible sections yield a non-trivial obstruction class in H¹.
theorem obstruction_is_nontrivial
    (U : CoveringFamily)
    (σ : LocalSections U)
    (h : ¬compatible σ) :
    obstruction σ ≠ CechCohomology.zero :=
  obstruction_nonzero_of_incompatible U σ h

Building the Proofs

The entire Lean proof library is managed by Lake, Lean 4's official build system. Lake handles dependency resolution (Mathlib4), incremental compilation, and parallel build scheduling.

Checking all 93 proof files

Clone the repository and navigate to the Lean proof directory, then invoke Lake:

bash 
cd proofs/lean
lake build

Lake will download Mathlib4 on the first run (this may take a few minutes), then type-check all 93 files in dependency order. A successful build produces no errors and no warnings about sorry.

Checking a single file

To check one paper in isolation:

bash 
cd proofs/lean
lake check JudgmentGeometry.Paper01_SemanticSites

Searching for theorems

Use Lean's #check command inside any file, or search with exact?:

lean4 
#check JudgmentGeometry.Paper04.trust_no_silent_promotion
#check JudgmentGeometry.Paper01.site_axioms_satisfied
#check JudgmentGeometry.Paper03.descent_theorem
