Code Generation Pipeline

JuGeo's generation pipeline synthesizes verified Python from specifications. The output is proof-carrying Python — a standard Python module containing the implementation, scaffold functions, and a machine-readable certificate.

Pipeline Overview

Given a specification \(\sigma\), the generation pipeline synthesizes a verified implementation \(f\) such that \(\vdash_{\mathcal{S}} f : \sigma\). The pipeline has six stages:

  1. 1

    Cover Design

    Partition the input space into a cover \(\mathcal{U} = \{U_i\}\) of overlapping opens that respect the structure of the specification. Each open becomes a sub-problem for the fleet.

  2. 2

    Inhabitant Fleets

    For each open \(U_i\), launch a fleet of candidate implementations ("inhabitants"). Fleet members compete: they are evaluated against the local specification and ranked by a trust-weighted score.

  3. 3

    Construction Loop

    Each fleet member cycles through propose → normalize → compare → select. The loop runs until the fleet converges or a budget limit is hit.

    Construction Loop
    Propose
    generate candidates
    Normalize
    canonical form
    Compare
    rank by score
    Select
    keep best k
  4. 4

    Descent & Glue

    Once each open \(U_i\) has a winning inhabitant \(f_i\), the descent check verifies the gluing condition: on overlaps \(U_i \cap U_j\), the sections must agree, \(f_i\big|_{U_i \cap U_j} = f_j\big|_{U_i \cap U_j}\). If they agree, gluing produces the global implementation \(f\).

  5. 5

    Certificate Emit

    The solver evidence for each VC, the cover structure, and the winning fleet rankings are packaged into a signed certificate object that travels with the output module.

  6. 6

    Proof-Carrying Python

    The final output is a standard .py file that imports and re-exports the implementation, embeds the certificate in a module-level variable, and adds scaffold functions used by downstream verification tools.

Cover Design

Cover design determines how the input space is partitioned. A good cover is small enough to be tractable, but expressive enough that each open admits a simple local implementation.

JuGeo uses three cover strategies, selectable via --cover-strategy:

  • Uniform — equal-weight partition by linear arithmetic constraints. Fast; good for numeric domains.
  • Semantic — opens are shaped by the pre/post structure of the spec. More opens, but easier local problems.
  • Adaptive — starts uniform, then refines opens where fleet convergence is slow. Best quality; highest cost.
import jugeo

cover = jugeo.design_cover(
    spec=spec,
    strategy="semantic",   # "uniform" | "semantic" | "adaptive"
    max_opens=16,
    overlap_fraction=0.1,  # allow 10% overlap between opens
)

print(f"Cover: {len(cover)} opens")
for i, u in enumerate(cover):
    print(f"  U[{i}]: {u.constraint_summary()}")

Inhabitant Fleets

For each open \(U_i\), JuGeo launches an inhabitant fleet — a pool of candidate implementations parameterized by the local specification restricted to \(U_i\). Fleet members are drawn from three sources:

  • Template instantiation — known patterns (linear, polynomial, recursive) are instantiated and checked.
  • Semantic search — the ideation engine proposes candidates based on the spec's semantic fingerprint.
  • Copilot channel — optionally, an LLM is queried as an evidence source (trust ceiling: COPILOT_SUGGESTED).
import jugeo

fleet_config = jugeo.FleetConfig(
    size=12,                  # fleet members per open
    sources=["template", "semantic", "copilot"],
    copilot_weight=0.3,       # fraction of budget for copilot
    convergence_patience=3,   # stop if no improvement for 3 rounds
)

fleets = jugeo.run_fleets(cover, spec, config=fleet_config)
for i, fleet in enumerate(fleets):
    print(f"U[{i}]: best score = {fleet.best_score:.3f}, "
          f"winner = {fleet.winner.name}")

Construction Loop

The construction loop is the inner engine of each fleet. It iterates four phases:

Propose
Each surviving fleet member generates a new candidate by applying a semantic move (see Orchestration) to its current implementation.
Normalize
Candidates are normalized to a canonical form that eliminates syntactic variation. Normalization uses the judgments layer to compute semantic equivalence classes.
Compare
Normalized candidates are compared against the local specification via SMT. Each candidate receives a score in \([0,1]\) based on the fraction of VCs discharged, weighted by VC complexity.
Select
The top-\(k\) candidates survive to the next round. \(k\) decreases geometrically as the loop converges.
import jugeo

# Configure the construction loop
loop_config = jugeo.ConstructionLoopConfig(
    max_rounds=20,
    initial_k=8,
    k_decay=0.75,
    move_budget_per_round=5,
    normalize=True,
)

# Run loop for a single open
result = jugeo.construction_loop(
    open_set=cover[0],
    spec_local=spec.restrict(cover[0]),
    fleet=fleets[0],
    config=loop_config,
)

print(f"Converged after {result.rounds} rounds")
print(f"Winner: {result.winner}")
print(f"Score: {result.winner_score:.4f}")

Descent & Glue

Once every open has a winner, descent checking verifies the cocycle condition. For opens \(U_i, U_j\) with non-empty intersection \(U_{ij} = U_i \cap U_j\), we need:

\[f_i\big|_{U_{ij}} \;\sim\; f_j\big|_{U_{ij}}\]

This is checked as an equivalence judgment on the overlap domain. If the check fails, JuGeo either relaxes the overlap constraints or re-runs the fleet for the failing open with additional gluing constraints. 

import jugeo

# Run descent check on the winner set
descent_result = jugeo.check_descent(
    cover=cover,
    winners={i: fleet.winner for i, fleet in enumerate(fleets)},
    spec=spec,
    on_failure="re_run_fleet",  # "fail" | "relax" | "re_run_fleet"
)

if descent_result.ok:
    # Glue the local implementations into a global one
    global_impl = jugeo.glue(descent_result.sections, cover)
    print(f"Glued: {global_impl}")
else:
    for fail in descent_result.failures:
        print(f"Overlap U[{fail.i}]∩U[{fail.j}] failed descent check")

Certificate Emit

The certificate captures all evidence produced during generation. It is a signed, machine-readable data structure embedded in the output module as a module-level constant. 

import jugeo

cert = jugeo.Certificate(
    mode="spec",
    target="compute_price",
    spec_digest="sha256:a3f8b2c1...",
    cover=cover.to_record(),
    vc_discharges=[...],        # solver evidence per VC
    fleet_rankings=[...],       # per-open winner history
    glue_evidence=...,          # descent check results
    trust_level="MACHINE_VERIFIED",
    issued_at="2026-03-23T10:00:00Z",
    jugeo_version="0.9.0",
)

print(cert.is_valid())      # True
print(cert.trust_level)     # "MACHINE_VERIFIED"
print(cert.to_json())       # serializable form

Proof-Carrying Python

The final output of the pipeline is a standard Python file. It can be imported like any other module. The implementation is fully functional — the scaffold functions and certificate are non-executing metadata unless explicitly invoked by a checker.

Structure of a proof-carrying Python module

# ============================================================
# compute_price_verified.py
# Generated by JuGeo 0.9.0  —  DO NOT EDIT
# ============================================================
from __future__ import annotations
import jugeo.pcp as _pcp

# ── Certificate ──────────────────────────────────────────────
_JUGEO_CERT = _pcp.Certificate.from_json("""
{
  "mode": "spec",
  "target": "compute_price",
  "spec_digest": "sha256:a3f8b2c1d4e5f6a7b8c9d0e1f2a3b4c5",
  "trust_level": "MACHINE_VERIFIED",
  "issued_at": "2026-03-23T10:00:00Z",
  "jugeo_version": "0.9.0",
  "cover": {"size": 8, "strategy": "semantic", "opens": [...]},
  "vc_count": 3,
  "vc_all_discharged": true
}
""")

# ── Implementation ────────────────────────────────────────────
def compute_price(x: float) -> float:
    """Return the discounted price for x."""
    if x <= 0:
        return 0.0
    return x * 0.9

# ── Scaffold: coordinate ─────────────────────────────────────
def _coordinate(x: float) -> int:
    """Return the index of the cover open containing x."""
    if x <= 0:         return 0
    if x <= 100:       return 1
    if x <= 1000:      return 2
    return 3

# ── Scaffold: support ────────────────────────────────────────
def _support(x: float) -> list[int]:
    """Return all opens whose closure contains x (for overlaps)."""
    opens = [_coordinate(x)]
    if 95 <= x <= 105:   opens.append(_coordinate(x) + 1)
    if 995 <= x <= 1005: opens.append(_coordinate(x) + 1)
    return opens

# ── Scaffold: descent profile ────────────────────────────────
def _descent_profile(x: float) -> dict:
    """Return gluing data for downstream refinement checking."""
    return {
        "open": _coordinate(x),
        "support": _support(x),
        "local_value": compute_price(x),
        "cert_digest": _JUGEO_CERT.digest(),
    }

Scaffold function roles

_coordinate

Maps an input to the index of its primary cover open. Used by downstream tools to localize verification queries and by the runtime sheaf to dispatch local invariant checks.

_support

Returns all opens whose closures contain the input, including overlapping opens. The support list is used by refinement checkers to identify which gluing conditions apply at this input point.

_descent_profile

Returns a dictionary of gluing data sufficient for a downstream tool to verify that the output is consistent with all covering sections at this point. Contains the local value, open index, support list, and a certificate digest for integrity.

💡
Runtime overhead is zero by default. The scaffold functions and certificate are never called by the implementation itself. To enable runtime invariant checking, wrap the module with jugeo.runtime.wrap(module), which installs a transparent proxy that invokes _descent_profile on each call and validates the result against the certificate.

Generating proof-carrying Python

# From CLI
jugeo spec --target mymodule.py::compute_price \
           --spec specs/pricing.yaml \
           --emit-pcp \
           --output compute_price_verified.py

# From Python API
import jugeo

result = jugeo.generate(
    spec=jugeo.Spec.from_yaml("specs/pricing.yaml"),
    cover_strategy="semantic",
    fleet_size=12,
    emit_pcp=True,
    output_path="compute_price_verified.py",
)
print(result.status)   # "SUCCESS"
print(result.output)   # Path to generated file
