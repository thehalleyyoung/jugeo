LLM / Copilot Integration

JuGeo integrates large language models as structured evidence channels with bounded, auditable trust. Copilots can construct proofs, suggest annotations, lower IR, run research tasks, and participate in oracle federation — always subject to the COPILOT_SUGGESTED trust ceiling.

The Copilot Trust Model

JuGeo treats LLMs not as oracles but as evidence channels in the trust algebra. Like all channels, a copilot produces evidence that is assigned a trust level, and that trust level determines how the evidence is used in descent and gluing. The key constraint is the COPILOT_SUGGESTED ceiling: evidence produced by an LLM copilot can never directly yield a trust level higher than COPILOT_SUGGESTED.

This ceiling is not a limitation — it is a safety feature. LLMs can hallucinate plausible-looking but incorrect proofs or annotations. By capping their trust, JuGeo ensures that copilot output must always be confirmed by a higher-trust channel (solver or formal proof) before it contributes to a VERIFIED judgment. Copilot evidence is best understood as a high-quality hint that dramatically reduces the search space for the solver.

⚠️

COPILOT_SUGGESTED is never sufficient for closure. A judgment cannot be closed with only copilot evidence. At least one higher-trust channel (SOLVER, ANNOTATION, or FORMAL_PROOF) must confirm the copilot's output. Use require_confirmation=True (the default) in the CopilotAgent to enforce this automatically.

The trust hierarchy relevant to copilot integration is: \[ \mathrm{NONE} \;\prec\; \mathrm{COPILOT\_SUGGESTED} \;\prec\; \mathrm{ANNOTATION} \;\prec\; \mathrm{SOLVER} \;\prec\; \mathrm{FORMAL\_PROOF} \]

Copilot Roles (Papers 86–98)

The copilot integration covers nine distinct roles, each explored in a dedicated paper. The roles are implemented as specialised CopilotAgent subclasses in jugeo.copilot.

Paper 86
Construction

Generate proof terms, lemma statements, and annotation templates from natural-language descriptions of the intended invariant.

Paper 87
Deduction

Apply inference rules step-by-step to advance a proof state. Uses chain-of-thought prompting to produce structured deduction traces.

Paper 88
Evidence Channels

Copilot as a first-class evidence channel with structured output schema, provenance tagging, and automatic CHALLENGE generation on conflict.

Paper 89
Oracle Federation

Multiple copilot instances federated as an oracle ensemble. Majority vote or trust-weighted combination resolves disagreements.

Paper 90
Advisors

Domain-specialist advisor agents (security, performance, API design) that annotate judgments with domain-specific concerns.

Paper 91
Research

Long-horizon research tasks: literature search, analogical reasoning, hypothesis generation, and novelty assessment for new theorems.

Paper 92
IR Lowering

Translate high-level semantic judgments into SMT-LIB or Lean IR, closing the gap between natural-language specs and machine-verifiable formulas.

Paper 93
Lifecycle

Manage the full verification lifecycle: triage open judgments, schedule work, generate status reports, and coordinate handoffs to human reviewers.

Paper 94–98
Specialised Copilots

Trust algebra advisor, doctrine reviewer, cover designer, theorem assistant, and diagnostic summariser — each targeting a specific sub-system of JuGeo.

Evidence Channel Protocol

All copilot agents implement the EvidenceChannel protocol. Submitting a judgment to a copilot agent produces a structured CopilotEvidence object that integrates cleanly with the mixed-evidence router and the trust algebra.

python 
from jugeo.copilot import CopilotAgent, CopilotRole
from jugeo.trust import TrustLevel
import jugeo

# Create a construction copilot
agent = CopilotAgent(
    role=CopilotRole.CONSTRUCTION,
    model="claude-3-5-sonnet",
    temperature=0.2,
    require_confirmation=True,   # evidence must be confirmed by solver
    max_tokens=4096,
)

# Submit an open judgment to the copilot
state = orchestrator.frontier[0]
result = agent.request_evidence(state)

print(result.trust)              # TrustLevel.COPILOT_SUGGESTED (always)
print(result.suggested_formula)  # formula suggested by the copilot
print(result.rationale)          # chain-of-thought explanation
print(result.annotation_text)    # ready-to-paste Python annotation
print(result.provenance)         # model name, timestamp, prompt hash

# Route the result to the solver for confirmation
confirmation = solver_agent.verify_with_hint(
    judgment=state,
    hint=result.suggested_formula,
)
if confirmation.status == "UNSAT":
    print(f"Confirmed! Trust: {confirmation.trust}")
    # trust is now TrustLevel.SOLVER (copilot hint + solver confirmation)

Oracle Federation

Oracle federation (Paper 89) allows multiple copilot instances to be combined into a single high-reliability oracle. Each copilot in the federation independently answers the same query, and the federation protocol aggregates their responses into a single evidence artifact with a combined trust score.

The federation uses one of three aggregation modes:

  • MAJORITY — the answer held by a majority of copilots wins. Trust is COPILOT_SUGGESTED only if all agree; otherwise NONE.
  • TRUST_WEIGHTED — each copilot has a prior reliability weight; answers are weighted by reliability score.
  • CONSERVATIVE — only accept an answer if all copilots agree. Highest precision; lowest recall.
python 
from jugeo.copilot import OracleFederation, AggregationMode

federation = OracleFederation(
    members=[
        CopilotAgent(role=CopilotRole.DEDUCTION, model="claude-3-5-sonnet"),
        CopilotAgent(role=CopilotRole.DEDUCTION, model="claude-3-5-haiku"),
        CopilotAgent(role=CopilotRole.CONSTRUCTION, model="claude-3-5-sonnet"),
    ],
    mode=AggregationMode.TRUST_WEIGHTED,
    reliability_priors={"claude-3-5-sonnet": 0.85, "claude-3-5-haiku": 0.70},
)

result = federation.query(state)
print(result.agreement_rate)     # fraction of members that agreed
print(result.combined_trust)     # combined trust level
print(result.winning_answer)     # the aggregated answer
print(result.dissenting_members) # members that disagreed

Lifecycle Management & Advisors

The Lifecycle copilot (Paper 93) manages the end-to-end verification workflow for a codebase. It triages open judgments, schedules verification work according to priority (backpressure score, deadline, developer assignment), generates status reports, and coordinates handoffs between automated and human-in-the-loop steps.

Advisor copilots (Paper 90) are specialist agents that annotate judgments with domain expertise. Current built-in advisors:

  • SecurityAdvisor — flags potential injection, overflow, and privilege escalation issues.
  • PerformanceAdvisor — identifies quadratic patterns, excessive allocation, and lock contention.
  • APIDesignAdvisor — suggests interface improvements that would reduce H¹ obstructions at API boundaries.
  • DocAdvisor — generates docstring annotations that can be verified by the solver.
python 
from jugeo.copilot import LifecycleCopilot, AdvisorPool
from jugeo.copilot.advisors import SecurityAdvisor, APIDesignAdvisor
import jugeo

# Set up the lifecycle manager
site = jugeo.build_site("mymod")
lifecycle = LifecycleCopilot(site=site, model="claude-3-5-sonnet")

# Triage and schedule
triage = lifecycle.triage(property="pure")
print(triage.high_priority)    # list of coords with high backpressure
print(triage.schedule)         # recommended verification order

# Run advisor pool across the module
advisors = AdvisorPool([SecurityAdvisor(), APIDesignAdvisor()])
advice = advisors.advise_module("mymod", site=site)

for item in advice.items:
    print(f"  [{item.severity}] {item.coordinate}: {item.message}")
    if item.suggested_annotation:
        print(f"    Suggested: {item.suggested_annotation}")

# Generate a status report
report = lifecycle.status_report(site=site, property="pure")
print(report.summary_text)
print(f"Overall trust coverage: {report.trust_coverage:.1%}")

Python Examples

Using the IR lowering copilot (Paper 92) to translate a natural-language spec:

python 
from jugeo.copilot import IRLoweringCopilot

lowerer = IRLoweringCopilot(model="claude-3-5-sonnet")

# Translate a natural-language invariant to SMT-LIB
nl_spec = "The output price is always non-negative and at most 10x the input cost."

ir = lowerer.lower(
    natural_language=nl_spec,
    context_function="mymod.pricing.compute_price",
    target_format="smt2",   # "smt2" | "lean4" | "jugeo_formula"
)

print(ir.smt2_text)
# (assert (and (>= price 0.0) (<= price (* 10.0 cost))))

print(ir.jugeo_formula)   # jugeo Formula object ready for dispatch
print(ir.confidence)      # 0.0-1.0, copilot's self-reported confidence
print(ir.caveats)         # any assumptions the copilot made

# Submit the lowered formula for solver confirmation
ctx = dispatch.encode_formula(ir.jugeo_formula)
result = ctx.check()
print(result.status)      # "UNSAT" if the property holds

Research copilot (Paper 91) for theorem analogy search:

python 
from jugeo.copilot import ResearchCopilot

researcher = ResearchCopilot(model="claude-3-5-sonnet")

# Find analogous theorems from the theorem ecology
open_judgment = orchestrator.frontier[0]
analogies = researcher.find_analogies(open_judgment, top_k=5)

for analogy in analogies:
    print(f"  Analogy: {analogy.theorem_name}")
    print(f"    similarity: {analogy.similarity_score:.2f}")
    print(f"    transport_plan: {analogy.transport_plan}")
    print(f"    estimated_effort: {analogy.effort_estimate}")

# Request a proof sketch for the most similar analogy
best = analogies[0]
sketch = researcher.proof_sketch(open_judgment, analogy=best)
