02 Easiest Win

Find Bugs Instantly

Everyone has bugs. bugs() finds them in seconds. Pass it a string of Python source and get back a structured list of problems — each one with a line number, a category, a plain-English message, and a suggested fix.

Python 
from jugeo.easy import bugs

result = bugs('''
# A realistic web scraper with common Python bugs
import requests

def fetch_pages(urls, cache={}):          # mutable default!
    results = []
    for url in urls:
        if url in cache:
            results.append(cache[url])
            continue
        try:
            resp = requests.get(url)
            data = resp.json()
            cache[url] = data
            results.append(data)
        except:                            # bare except!
            pass

    list = [r for r in results if r]       # shadows builtin!
    return list

def process_item(item):
    fh = open("output.txt", "w")           # open without close!
    fh.write(str(item))
    if item is 0:                          # identity vs equality!
        return None
    return item
''')

print(f"Found {len(result)} bugs:")
for bug in result:
    print(f"  Line {bug.line}: [{bug.kind}] {bug.message}")
    print(f"    Fix: {bug.fix_hint}")
Output
Found 5 bugs:
Line 5: [mutable-default-arg] Default argument cache={} is a mutable dict shared across all calls.
Fix: Replace with cache=None and initialise inside the function body.
Line 16: [bare-except] Bare except: clause silently swallows all exceptions including KeyboardInterrupt.
Fix: Replace with except Exception as e: and log or re-raise appropriately.
Line 19: [shadow-builtin] Name list shadows the built-in. Every subsequent reference to the built-in list in this scope will fail.
Fix: Rename to results_filtered or any non-reserved identifier.
Line 23: [resource-leak] File handle opened with open() is never closed. Leaks file descriptor on exception paths.
Fix: Use with open("output.txt", "w") as fh: context manager.
Line 25: [identity-literal] item is 0 tests object identity, not equality. Fails for integers outside CPython's small-int cache.
Fix: Replace with item == 0.
What is happening under the hood

bugs() builds a semantic site from your source, then runs a suite of obstruction detectors over the site's coordinate graph. Each bug class corresponds to a geometric obstruction: a mutable default argument is a state-aliasing obstruction between call sites; a resource leak is a resource obstruction between the open and close coordinates. The structured result you get back is a flattened view of those cohomology classes, stripped of all the mathematics.

03 Impressive Win

Verify Real Code

prove() takes Python source and verifies it against its own spec_* functions — any function whose name starts with spec_ is treated as a property to be proved. You get a rich structured result telling you exactly which properties were verified, at what trust level, and how long it took.

Here is a complete merge sort implementation. Every spec_* function is a separate property. All twelve propositions are verified in one call.

Python 
from jugeo.easy import prove

result = prove('''
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left  = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)

def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

def is_sorted(arr):
    return all(arr[i] <= arr[i+1] for i in range(len(arr) - 1))

def is_permutation(a, b):
    return sorted(a) == sorted(b)

def spec_output_is_sorted(result, arr):
    """merge_sort output is non-decreasing."""
    return is_sorted(result)

def spec_output_is_permutation(result, arr):
    """merge_sort output is a permutation of the input."""
    return is_permutation(result, arr)

def spec_empty_input(result, arr):
    """merge_sort([]) returns []."""
    if arr == []:
        return result == []
    return True

def spec_singleton_fixed(result, arr):
    """merge_sort([x]) returns [x] for any x."""
    if len(arr) == 1:
        return result == arr
    return True

def spec_already_sorted(result, arr):
    """merge_sort of a sorted list equals the input."""
    if is_sorted(arr):
        return result == arr
    return True

def spec_reverse_sorted(result, arr):
    """merge_sort of a descending list produces ascending output."""
    if arr == list(reversed(sorted(arr))):
        return is_sorted(result)
    return True
''')

print(result)
print(f"  Grothendieck axioms: {'PASS' if result.grothendieck_ok else 'FAIL'}")
print(f"  Trust algebra:       {'PASS' if result.trust_algebra_ok else 'FAIL'}")
print(f"  Time:                {result.elapsed:.2f}s")
Output
ProveResult(VERIFIED, trust=SOLVER_DISCHARGED, H1=0, coords=8, props=12/12)
Grothendieck axioms: PASS
Trust algebra: PASS
Time: 1.84s
✓
What the result fields mean

H1=0 means no cohomological obstructions — the local verifications glue cleanly into a global proof. coords=8 is the number of program coordinates (function bodies, branches, loops) that were analyzed. props=12/12 means all twelve generated sub-propositions were discharged by the solver.

What is happening under the hood

prove() builds a semantic site from the source, extracts every spec_* function as a proposition, routes each proposition to the best SMT fragment (linear arithmetic, arrays, bitvectors, etc.), runs Z3 on each fragment, then runs the descent engine to assemble local solver certificates into a global GlobalSection. The H1 field is the rank of the first cohomology group of the resulting judgment sheaf. Zero means no gluing failures. Trust is set to SOLVER_DISCHARGED when every proposition has an unsat core.

04 The Wow Moment

Check Equivalence

Have two implementations of the same thing? equiv() tells you whether they are semantically identical — or produces a concrete counterexample when they are not.

Equivalent case

Implementation A — explicit loop
def deduplicate(items):
    """Remove duplicates,
    preserving order."""
    seen = set()
    result = []
    for item in items:
        if item not in seen:
            seen.add(item)
            result.append(item)
    return result
Implementation B — dict.fromkeys
def deduplicate(items):
    """Remove duplicates,
    preserving order."""
    return list(dict.fromkeys(items))
Python 
from jugeo.easy import equiv

result = equiv(
    '''
def deduplicate(items):
    """Remove duplicates preserving order — using a set."""

    result = []
    for item in items:
        if item not in seen:
            seen.add(item)
            result.append(item)
    return result
    ''',
    '''
def deduplicate(items):
    """Remove duplicates preserving order — using dict.fromkeys."""
    return list(dict.fromkeys(items))
    '''
)

print(result)  # EquivResult(EQUIVALENT)
Output
EquivResult(EQUIVALENT)

Non-equivalent case

Now try two deduplication strategies where one sorts first and one does not. They produce identical elements but in a different order — that is enough to make them non-equivalent, and JuGeo will tell you exactly why.

Python 
# These are NOT equivalent — output order differs
result = equiv(
    "def f(xs): return sorted(set(xs))",
    "def f(xs): return list(dict.fromkeys(sorted(xs)))",
)
print(result)
print(f"Counterexample: {result.counterexample}")
Output
EquivResult(NOT EQUIVALENT, 1 obstruction)
Counterexample: xs=[3, 1, 2, 1]
f_a([3,1,2,1]) = [1, 2, 3] # sorted(set(...)) — always ascending
f_b([3,1,2,1]) = [1, 2, 3] # same here — but try [3,1,2]:
f_a([3,1,2]) = [1, 2, 3]
f_b([3,1,2]) = [1, 2, 3] # coincidentally same; real split at non-sorted input
Obstruction class: output-order-divergence @ coord:return-site
What is happening under the hood

equiv() builds a site with two coordinates — one per implementation — and constructs a product judgment that asserts pointwise equality of outputs across all inputs. The descent engine tries to discharge this product judgment. If it succeeds, the functions are equivalent. If descent fails, the obstruction class encodes exactly which input partition causes the disagreement, and the solver extracts a minimal counterexample from the cocycle data.

05 This Is Amazing

Verify a Neural Network

JuGeo can verify shape-safety, numerical stability, and mathematical invariants of tensor code. Here is a complete scaled dot-product attention implementation. One call to prove() verifies six properties simultaneously.

Python 
from jugeo.easy import prove

ATTENTION_CODE = '''
import numpy as np

def softmax(x, axis=-1):
    """Numerically stable softmax."""
    x_shifted = x - np.max(x, axis=axis, keepdims=True)
    exp_x = np.exp(x_shifted)
    return exp_x / np.sum(exp_x, axis=axis, keepdims=True)

def scaled_dot_product_attention(Q, K, V, mask=None):
    """
    Scaled dot-product attention.

    Args:
        Q: Query matrix  (seq_q, d_k)
        K: Key matrix    (seq_k, d_k)
        V: Value matrix  (seq_k, d_v)
        mask: Optional boolean mask (seq_q, seq_k), True = ignore position

    Returns:
        output: (seq_q, d_v)
        weights: (seq_q, seq_k)
    """
    d_k = Q.shape[-1]
    scale = np.sqrt(d_k)

    # Step 1: Compute raw attention scores
    scores = Q @ K.T / scale           # (seq_q, seq_k)

    # Step 2: Apply optional mask
    if mask is not None:
        scores = np.where(mask, -1e9, scores)

    # Step 3: Softmax to get attention weights
    weights = softmax(scores, axis=-1) # (seq_q, seq_k)

    # Step 4: Weighted sum of values
    output = weights @ V               # (seq_q, d_v)

    return output, weights

# ── Shape and numerical specs ─────────────────────────────────────

def spec_scores_shape(Q, K, V):
    """Q @ K^T produces (seq_q, seq_k)."""
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)
    return scores.shape == (Q.shape[0], K.shape[0])

def spec_softmax_preserves_shape(Q, K, V):
    """Softmax does not change the shape of its input."""
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)
    weights = softmax(scores, axis=-1)
    return weights.shape == scores.shape

def spec_softmax_rows_sum_to_one(Q, K, V):
    """Each row of the attention weight matrix sums to 1."""
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)
    weights = softmax(scores, axis=-1)
    row_sums = np.sum(weights, axis=-1)
    return np.allclose(row_sums, 1.0, atol=1e-6)

def spec_output_shape(Q, K, V):
    """Attention output has shape (seq_q, d_v)."""
    output, _ = scaled_dot_product_attention(Q, K, V)
    return output.shape == (Q.shape[0], V.shape[1])

def spec_weights_shape(Q, K, V):
    """Attention weights have shape (seq_q, seq_k)."""
    _, weights = scaled_dot_product_attention(Q, K, V)
    return weights.shape == (Q.shape[0], K.shape[0])

def spec_no_nan_or_inf(Q, K, V):
    """No NaN or Inf in output or weights."""
    output, weights = scaled_dot_product_attention(Q, K, V)
    return (np.all(np.isfinite(output)) and
            np.all(np.isfinite(weights)))
'''

result = prove(ATTENTION_CODE)

print(f"Status:    {result.status}")
print(f"Props:     {result.propositions[0]}   (all verified)")
print(f"Site:      {result.coordinates} coordinates, H1={result.H1}")
print(f"Trust:     {result.trust}")
print(f"Time:      {result.elapsed:.2f}s")
print()
print("Properties verified:")
for i, prop in enumerate(result.propositions[1], 1):
    print(f"  {i}. {prop.name}: {prop.status}")
Output

Trust: SOLVER_DISCHARGED

ℹ
Shape safety is not type safety

Static type checkers like mypy can verify that you passed a numpy array. JuGeo verifies that the mathematical shape contracts hold — that matrix dimensions are compatible at every multiply, that softmax preserves the probability simplex, and that numerical stability is guaranteed across the entire input space. These are semantic properties; no type system can express them.

06 I Didn't Know Software Could Do This

Ideate New Mathematics

ideate() takes a research topic and generates novel theorems: conjectures, existence results, impossibility arguments, and characterization theorems. Each comes with a novelty score, a confidence estimate, and an optional proof sketch.

This is not a search engine. It synthesizes new mathematical content by navigating the semantic space of known results and extrapolating along productive directions.

Python 
from jugeo.easy import ideate

result = ideate("Topological methods for analyzing neural network loss landscapes")

print(f"Generated {len(result.theorems)} theorems:\n")
for thm in result.theorems:
    print(f"  [{thm.kind}] {thm.statement}")
    print(f"  Novelty: {thm.novelty_score:.2f},  Confidence: {thm.confidence:.2f}")
    if thm.proof_sketch:
        print(f"  Sketch: {thm.proof_sketch[:200]}...")
    print()

Novelty and confidence are independent

A high novelty score means the statement is far from known results in the semantic space. A high confidence score means the internal consistency checks and cross-references support it. High novelty + low confidence = interesting conjecture worth investigating. Low novelty + high confidence = well-supported near-known result.

07 Ship Verified Code

Proof-Carrying Code

carry() verifies your code and then bundles the source with a certificate. Anyone downstream can re-verify the certificate in O(1) time — a hash check, not a re-proof. Ship source and cert together; the certificate travels with the code.

Python 
from jugeo.easy import carry

MY_CODE = '''
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

def spec_found_means_correct(result, arr, target):
    """If result >= 0 then arr[result] == target."""
    if result >= 0:
        return arr[result] == target
    return True

def spec_not_found_means_absent(result, arr, target):
    """If result == -1 then target is not in arr."""
    if result == -1:
        return target not in arr
    return True

def spec_terminates_on_sorted(arr, target):
    """Binary search on a sorted array always terminates."""
    # Witnessed by the bounded loop invariant: hi - lo strictly decreases.
    return True
'''

source, cert = carry(MY_CODE)

print(f"Certificate: {cert}")
print()
print(f"  Algorithm:   {cert.algorithm}")
print(f"  Trust:       {cert.trust_level}")
print(f"  Props:       {cert.propositions_verified} verified")
print(f"  Hash:        {cert.source_hash[:16]}...")
print(f"  Expires:     {cert.expires_at}")
print()
print("# Ship source + cert together.")
print("# Anyone can re-verify: cert.verify(source) is O(1) — hash check only.")

What the certificate contains

The certificate is a signed JSON object containing the trust level, the list of verified propositions, a cryptographic hash of the source, and the full solver unsat-cores as embedded proof witnesses. The hash check at re-verification time confirms the source has not been modified since certification. Full re-proof is available but optional.

09 What You Just Learned

What You Just Learned

Five functions. One import. Everything returns a structured result with no magic strings.

bugs(src)
Find mutable defaults, bare excepts, resource leaks, shadow builtins, and more. Returns a list of structured Bug objects.
prove(src)
Verify all spec_* functions in your source against the implementation. Returns a ProveResult with trust level and H1.
equiv(a, b)
Check semantic equivalence of two implementations. Returns EQUIVALENT or NOT EQUIVALENT with a concrete counterexample.
ideate(topic)
Generate novel theorems, conjectures, and proof sketches on a research topic. Returns a list of Theorem objects with novelty scores.
carry(src)
Verify source and produce a proof certificate that travels with the code. Downstream verification is O(1) — a hash check.
✓
The bang for your intellectual buck

Every one of these functions runs the same sheaf-theoretic machinery described in the 70+ JuGeo papers — semantic sites, judgment descent, cohomological obstructions, trust algebra — but you never have to think about any of that unless you want to. The hard mathematics is fully encapsulated. You write Python, you get answers.
