Orchestration Pipeline

JuGeo's orchestration layer coordinates fleet management, semantic control, move selection, mixed-evidence routing, and frontier objectives into a single coherent pipeline that advances the global verification state with each tick.

Architecture Overview

The orchestration pipeline is the top-level loop that runs JuGeo's proof search. It manages a fleet of worker agents (solvers, LLM copilots, static analysis tools), dispatches verification work to them, and collects their evidence contributions into the judgment sheaf.

The pipeline operates on a frontier — the set of open judgments that have not yet been verified or falsified. Each iteration of the loop selects a subset of frontier judgments, chooses moves to apply to each, dispatches them to the appropriate fleet members, collects results, and updates the frontier. The loop terminates when the frontier is empty or a resource budget is exhausted.

Orchestration Fixed-Point
\[ \text{Orch}(\mathcal{F}_0) \;=\; \mu X.\; \text{step}(X) \quad\text{where}\quad \text{step}(F) = F \setminus \text{Closed}(F) \cup \text{NewGoals}(F) \]
1
Site construction

Build the semantic site from the target module. Identify all coordinates (functions, classes, modules) and their morphisms (call edges, import edges, containment).

2
Frontier initialisation

Seed the frontier with all open judgments for the target property. Each coordinate gets an initial judgment state with NONE trust.

3
Move selection

For each frontier judgment, the semantic control layer selects the best applicable move using the configured control law (GREEDY, LOOKAHEAD, BALANCED, or ADAPTIVE).

4
Fleet dispatch

Moves are dispatched to fleet members in parallel. SMT moves go to the solver fleet; copilot moves go to LLM agents; static analysis moves go to the AST analysis tools.

5
Evidence collection & routing

Results from fleet members are collected and routed through the mixed-evidence router. Conflicting evidence is resolved using the trust algebra meet operation.

6
Frontier update

Closed judgments are removed from the frontier. New sub-goals generated by moves (e.g., GLUE generates local section goals) are added. Loop back to step 3.

Fleet Management

A fleet is a pool of heterogeneous verification agents. Fleet members are registered with the orchestrator and assigned jurisdictions: the set of move kinds and formula fragments each member is authorised to handle. The fleet manager load-balances work across members and respects resource budgets.

SolverAgent
SMT Solver Agent

Wraps a Z3Session or CVC5 session. Handles VERIFY, NORMALIZE, and WEAKEN moves for SMT-decidable formulas.

CopilotAgent
LLM Copilot Agent

Routes moves to an LLM copilot. Handles CONSTRUCT, REPAIR, and NEGOTIATE_TREATY moves. Evidence carries COPILOT_SUGGESTED trust ceiling.

StaticAgent
Static Analysis Agent

Runs mypy, pyright, or custom AST analyzers. Handles VERIFY and RESTRICT moves for type-level properties.

FormalAgent
Formal Proof Agent

Submits goals to Lean/Coq. Handles CONSTRUCT and PROMOTE_TRUST moves. Evidence carries FORMAL_PROOF trust, the highest level.

OracleAgent
Oracle Agent

Queries a domain-specific oracle (e.g., a property database or a specialist solver). Used for CHALLENGE and ESCALATE moves.

💡

Fleet composition. The default fleet for interactive use is one SolverAgent (Z3) plus one CopilotAgent. For CI pipelines, add a StaticAgent. For critical security-sensitive code, add a FormalAgent to require Lean proofs for selected properties. Fleet members can be added at any time; their evidence is incorporated into the next orchestration tick.

Semantic Control

The semantic control layer is responsible for move selection and sequencing. It acts as the “brain” of the orchestrator, translating the high-level frontier objectives into concrete move sequences for each fleet member.

Semantic control implements the interface defined in jugeo.orchestration.SemanticController. The default implementation uses the BALANCED control law with a two-level priority queue: high-backpressure judgments are processed first, then the rest in cost-ascending order.

python 
from jugeo.orchestration import SemanticController, ControlLaw

controller = SemanticController(
    control_law=ControlLaw.ADAPTIVE,
    priority="backpressure",   # or "cost", "trust_gap", "random"
    lookahead_depth=3,
)

# Ask the controller which move to apply next to a given judgment state
state = orchestrator.frontier[0]
move = controller.select_move(state)
print(move.kind.name)          # e.g., "VERIFY" or "GLUE"
print(move.cost)               # estimated resource cost
print(move.expected_trust_delta)

# Override: force a specific move kind on the next tick
controller.force_next_move(state, MoveKind.CUT, params={"lemma": my_lemma})

Mixed-Evidence Routing

Different evidence channels produce evidence with different trust levels. The mixed-evidence router collects contributions from all fleet members for a single judgment and resolves them into a single combined judgment using the trust algebra. When channels agree, their trust levels are joined (the maximum is taken). When channels conflict, the meet (minimum) is taken and a CHALLENGE move is generated.

Evidence combination
\[ \tau_{\text{combined}} \;=\; \begin{cases} \tau_1 \vee \tau_2 & \text{if evidence agrees} \\ \tau_1 \wedge \tau_2 & \text{if evidence conflicts (triggers CHALLENGE)} \end{cases} \]
python 
from jugeo.orchestration import MixedEvidenceRouter

router = MixedEvidenceRouter(
    conflict_policy="challenge",   # "challenge" | "prefer_formal" | "prefer_solver"
    min_trust_for_closure=TrustLevel.SOLVER,
)

# Route evidence from multiple sources to a single judgment
from jugeo.evidence import EvidenceBundle
bundle = EvidenceBundle()
bundle.add(solver_result)     # from SolverAgent
bundle.add(copilot_result)    # from CopilotAgent

combined = router.combine(bundle, target_judgment=j)
print(combined.trust)         # resolved trust level
print(combined.conflicts)     # any conflict records
print(combined.challenge_moves)  # moves generated for conflicts

Frontier Objectives

A frontier objective is a goal that the orchestrator is trying to achieve by advancing the frontier. JuGeo supports five built-in objectives:

CLOSE_ALL
Close All

Advance every frontier judgment to a closed state (verified or falsified). The default objective for module-wide analysis.

MAX_TRUST
Maximise Trust

Maximise the minimum trust level across all judgments in the module. Stops when the entire module is at least SOLVER-trusted.

MIN_COST
Minimise Cost

Close the frontier using the least total resource cost. Useful for large codebases where full verification is too expensive.

TARGETED
Targeted

Close a specific named set of coordinates (e.g., all public API functions). Ignores internal helpers unless needed for descent.

REPAIR_FIRST
Repair-First

Prioritise REPAIR moves; defer verification until all automatic repairs have been applied. Good for initial bootstrapping of a codebase that has many H⁰ obstructions.

Python Examples

Running the full orchestration pipeline:

python 
from jugeo.orchestration import Orchestrator, FleetConfig, FrontierObjective
import jugeo

site = jugeo.build_site("mymod")

# Configure the fleet
fleet = FleetConfig()
fleet.add_solver_agent(solver="z3", timeout_ms=10_000)
fleet.add_copilot_agent(model="claude-3-5-haiku", max_tokens=2000)
fleet.add_static_agent(tool="mypy")

# Create the orchestrator
orch = Orchestrator(
    site=site,
    fleet=fleet,
    objective=FrontierObjective.CLOSE_ALL,
    property="pure",
    max_ticks=100,
    time_budget_s=120.0,
)

# Run the pipeline
report = orch.run()

print(f"Ticks completed : {report.ticks}")
print(f"Judgments closed: {report.closed_count}")
print(f"Remaining open  : {report.open_count}")
print(f"Obstructions    : {report.obstruction_count}")
print(f"Total cost      : {report.total_cost:.2f}")

Monitoring the orchestrator in real time:

python 
from jugeo.orchestration import Orchestrator, OrchestratorCallback

class PrintCallback(OrchestratorCallback):
    def on_tick_start(self, tick: int, frontier_size: int):
        print(f"Tick {tick}: frontier={frontier_size}")

    def on_judgment_closed(self, coord, trust):
        print(f"  Closed: {coord} @ {trust.name}")

    def on_obstruction_found(self, obs):
        print(f"  Obstruction: {obs.degree.name} @ {obs.coordinate} "
              f"bp={obs.backpressure_score:.2f}")

orch = Orchestrator(site=site, fleet=fleet,
                    objective=FrontierObjective.MAX_TRUST,
                    property="no_io")
orch.add_callback(PrintCallback())
report = orch.run()
